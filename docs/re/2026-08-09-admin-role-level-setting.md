# 后台角色等级设置

## 契约

账号管理的每个角色行新增“设定等级”入口，允许输入 `1` 至 `70`。
`account_roles.level` 不是独立权威字段：客户端等级由累计 `exp` 的等级曲线推导。因此
提交 `set-role-level` 时，服务端将 `level` 和 `exp` 同时设为当前运行时等级曲线中目标等级的
经验起点，再重算装备参与后的 HP/MP 上限。

这不是复活或治疗操作：当前 HP/MP 保持原值，只在超过新上限时截断。

## 持久化与并发边界

该操作复用账号管理的离线角色快照和 `vm_net_mock_role_db_save_relational` 全量事务写入。
若账号仍有活动角色会话，服务端拒绝请求；否则运行中会话的稍后保存可能覆盖数据库中的
等级、经验和生命/法力上限。

失败时恢复内存快照，不提交部分状态。日志为：

```text
[info][mock-admin] role_level_set ... action=commit
```

## 回归验证

`scripts/admin-role-level-regression.c` 直接调用同一角色变更函数，验证：

- 49 和 70 级分别使用当前权威经验曲线表的对应起点；
- 最大生命/法力会按新等级更新，当前值永远不会超出新上限；
- 0 和大于 70 的等级被拒绝。
