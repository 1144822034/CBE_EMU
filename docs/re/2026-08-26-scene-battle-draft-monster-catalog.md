# 场景战斗怪草稿与怪物目录

## 现象

在“场景战斗怪”保存草稿后，怪物 ID 可能尚未出现在“怪物管理”目录，因而无法在部署前配置属性或掉落；场景草稿卡片也没有直接显示对应的怪物 ID。早期界面还将草稿 ID 固定为自动分配的独立 ID，无法为同一怪物配置多个坐标点，也无法在已保存草稿中调整怪物 ID。

## 根因

怪物目录只从基础怪物表和已部署/已存在的 SCE2 kind-3 节点建立。server_scene_battle_monsters 是草稿数据源，保存和删除草稿均没有使目录缓存失效，也没有在目录重建时投影草稿 ID。新建表单的 monster_id 曾同时被误作参考模板和草稿最终身份，缺少独立 ID 分配与属性复制边界；随后为了避免改写模板，又把已保存草稿的 ID 设成只读，造成复用和编辑能力缺失。

## 修复契约

- 新建草稿可选“复用怪物 ID”。所选 ID 已在怪物目录中时，会直接用于新的坐标节点；服务端不会复制或改写它的属性、掉落或其他既有草稿。
- 新建时未选择复用 ID，才使用“参考怪物”字段。服务端从 2000 起分配未被草稿、怪物覆盖或现有目录占用的新 ID；参考怪物仅提供初始属性、奖励和掉落，并在草稿写入成功后复制到新 ID。
- 已保存草稿的怪物 ID 改为可编辑的目录选择器；只能切换到目录中已有的 ID，防止没有属性和掉落契约的裸 ID 进入客户端场景。
- 目录重建会读取场景战斗怪草稿；新 ID 会立即作为可编辑怪物进入“怪物管理”，并采用草稿的显示名称和首个场景标签。
- 保存或删除草稿后立即刷新怪物目录和与其平行的数据库属性缓存。
- 草稿新增的目录项带有 draft-only 标记。它可保存怪物属性和掉落，但不满足实时战斗怪的已知身份校验；只有部署后由真实 SCE2 kind-3 记录重新发现，才可被正常战斗入口使用。
- 场景战斗怪已有草稿卡片显示“怪物 ID <id>”，且可直接改为已有 ID。数据库继续只拒绝相同场景、相同 ID、相同坐标，因此同一 ID 可设定多个坐标点。

## 回归

admin-scene-battle-monster-layout-regression 直接构造一条草稿目录行，验证它可列入怪物管理数据、保留名称和场景标签，并验证该草稿不会被接受为已部署的实时战斗目标。它也验证从自定义 ID 起点分配新 ID 时会跳过已占用 ID，以及页面同时输出复用 ID、参考怪物和可编辑 ID 的表单契约。
