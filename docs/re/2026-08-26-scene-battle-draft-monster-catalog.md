# 场景战斗怪草稿与怪物目录

## 现象

在“场景战斗怪”保存草稿后，怪物 ID 可能尚未出现在“怪物管理”目录，因而无法在部署前配置属性或掉落；场景草稿卡片也没有直接显示对应的怪物 ID。

## 根因

怪物目录只从基础怪物表和已部署/已存在的 SCE2 kind-3 节点建立。server_scene_battle_monsters 是草稿数据源，保存和删除草稿均没有使目录缓存失效，也没有在目录重建时投影草稿 ID。

## 修复契约

- 目录重建会读取场景战斗怪草稿；新 ID 会立即作为可编辑怪物进入“怪物管理”，并采用草稿的显示名称和首个场景标签。
- 保存或删除草稿后立即刷新怪物目录和与其平行的数据库属性缓存。
- 草稿新增的目录项带有 draft-only 标记。它可保存怪物属性和掉落，但不满足实时战斗怪的已知身份校验；只有部署后由真实 SCE2 kind-3 记录重新发现，才可被正常战斗入口使用。
- 场景战斗怪已有草稿卡片显示“怪物 ID <id>”。

## 回归

admin-scene-battle-monster-layout-regression 直接构造一条草稿目录行，验证它可列入怪物管理数据、保留名称和场景标签，并验证该草稿不会被接受为已部署的实时战斗目标。
