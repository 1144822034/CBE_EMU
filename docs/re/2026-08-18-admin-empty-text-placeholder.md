# 后台可选文本空值显示为短横线

Date: 2026-08-18

## 现象

在 NPC 编辑器的“可同时提供的对话功能”中清空“选项名称”和“选项说明”后保存，
数据库关系行可以正确写入空字节串，但重新打开编辑器时输入框又显示单个 `-`。
继续保存会把这个展示占位符写成自定义对话文本。后台其他空名称、空场景等位置也使用
相同的短横线占位。

## 根因

共用转换函数 `vm_net_mock_gbk_label_to_utf8()` 同时承担编码转换和展示默认值职责。
当输入为 `NULL` 或空字符串时，它主动输出 `-`。NPC 编辑器将转换结果直接写入
`<input value>`，因此持久化空值在回填边界首次变成了非空短横线。

## 修复

- 编码转换函数对空输入保持空输出，不再生成展示占位符。
- NPC 服务表单把历史页面提交的单个 `-` 归一为空值。
- `server_npc_services` 加载和旧单服务兼容投影同样把单个 `-` 视为空，从而让已有
  遗留记录立即恢复默认服务文案，无需改写客户数据。
- 后台角色名称和场景等原先显式传入 `-` 的空值调用改为直接传入真实字段。

客户端对话仍按既有契约处理：选项名称或说明为空时，由
`vm_net_mock_npc_service_option_default()` 提供对应服务的默认文案。

## 回归

`scripts/admin-request-length-regression.c` 增加纯函数断言：

- 空 GBK 标签转换后仍为空；
- NPC 服务名称和说明提交为历史单个 `-` 时，解析结果为空；
- 其他后台请求长度和共享脚本断言继续通过。
