# 强化缩放表指针无静态写入点（2026-07-29）

## 结论

对本机 `江湖OL.CBE` + 全部 `mm*.cbm`：

**不存在**把非空指针写进 `*(business + 0x584)`（即文档里的
`global+0x580+4`）的代码；静态镜像里也**没有** 16 级
`(flat,pct)` 常量表（含本服 `M(L)` 的 10/45 表、或全 10% 表）。

因此本客户端构建里，`0x01028BCE` 的强化百分比累加在正常运行下会一直走
**`table == NULL` 分支**，主行 `%d` 只保留已加过的裸基值。这不是「还没找到
.dsh」，而是**出厂二进制就没有装表路径**。

## 对象与字段

| 项 | 证据 |
| --- | --- |
| 根对象 | `0x01028BCE`：`ldr` 字面量 → `add sb` → `ldr [slot]`；字面量静态值为 `0x54ace12c`，高 16 位 `0x54AC`，与宿主侧 `Global_R9+0x54AC`（business/scene 根）一致 |
| 表指针 | `addr = business + 0x580`；`table = *(addr + 4)` = `*(business + 0x584)` |
| 同结构旁路 | 强化 UI 用 `*(business + 0x580)` 作玄晶槽数组指针（`0x0101E3C0` 等）；与 `+0x584` 是**相邻字段**，不是同一指针 |

消费逻辑（已确认）：

```text
*dest += base
table = *(business + 0x584)
if table == NULL: 结束累加
else for i in [0, L):
  *dest += flat_i + pct_i * base / 100
```

调用方：穿戴汇总 `0x0101002E` / `0x01010056`；详情等另 4 处 `bl 0x01028BCE`。

## 静态穷尽（本轮）

1. **直接写 `*(obj+0x584)`**  
   在 CBE 与全部 `web/fs/JHOnlineData/mm*.cbm` 中，对
   `movs #0xb; lsls #7`（及 `0x16<<6` / `0x2c<<5` / `0x58<<4` / `mov #0x580`）
   后 `str …, [addr, #4]` 且中间未 `ldr [addr]` 的模式：**命中 0**。

2. **镜像内嵌表**  
   精确 `M(L)` 64 字节、以及 16×`(0,0,10)`：**均未出现**。

3. **资源名**  
   无 `enhance*.dsh` 等（见 `2026-07-29-enhance-table-dsh-not-viable.md`）。

4. **误报澄清**  
   同区大量 `0xb<<7` 属于强化 UI（读 `*(+0x580)` 再写槽内 `+0xe/+0x10`），
   不是装缩放表。

## 对「合法装表」的含义

| 方案 | 判定 |
| --- | --- |
| 新 `.dsh` / `18/7` 丢文件 | 无效（无人打开，且无写 `+0x584`） |
| 改 `equip.dsh` 加列 | 无效（加载路径不写该指针） |
| Host 写 `Global_R9` / business+0x584 | **禁止**（项目规范） |
| 等某 WT 字段触发客户端自装 | 当前二进制**无对应 writer**；除非换包体/补丁客户端，否则不会出现 |

权威属性与商店查看文案继续走服务端
`M(L) = 1 + (10*L + 35*floor(L/4))/100`（`vm_net_mock_equipment_bonus_scale`）。
原生详情主行在本客户端上**无法**靠协议单独变成已缩放总值。
