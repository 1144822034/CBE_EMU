# 商城直发道具（808、817--819）结算

## 触发与原始证据

在秘宝商城购买 `808 金元宝` 时，服务端已经扣除了角色酷宝并返回成功，但客户端
没有取得普通背包物品，也没有看到金钱变化。一次已保留的服务端记录为：

```text
mock_shop_buy14 type=2 item=808 count=1 unit=1 cost=1
wcoin=10000/9999 seq=15 result=1 known=1
```

这证明首个偏离不在请求识别、价格计算或 `14/3` 成功回执，而在购买成功后的道具
结算语义。

## 已确认的客户端链路

1. 商城购买请求是严格的 `WT 1/14/3 { id, num, type }`；本路径的商城购买类型为
   `type=2`。
2. `mmShopMstarWqvga.cbm:sub_9DE (0x9DE)` 先按 `seq`、`result` 读取 `1/14/3`。
   当 `result=1 && type=2` 时，它先在本地扣除 `coolmoney/ticket`，然后读取购买的
   item ID。
3. 同一函数对 `806` 直接扩充背包；对 `808` 以及 `817..819` 明确跳过
   `item_manager_add`。因此这四种值不是客户端通用背包管理器接收的“购买物品行”。
4. `sub_9DE` 还会解析 `1/1/14` 的完整 `actorinfo`，并立即交给共享
   actor-state parser。该对象必须位于同一商城响应的末尾；
   `docs/re/2026-06-26-local-role-db.md` 已确认其中 `gap09C0` 是角色钱币总额。
5. 商城后续的正常背包打开/列表请求由现有 `17/1 + 7/42` 或 `17/1` 路径处理。
   普通背包网格协议 `30/21`、`17/1` 不能包含 808/817--819 本体；808 的 DSH
   堆叠数为 0，作为普通行会展开为大量物理记录并可能耗尽客户端记录池。

## 资源事实

`JHOnlineData/item.dsh`（GBK）给出了这些直发商城项目的实际内容：

| 商城 ID | 名称 | 购买/结算内容 |
| --- | --- | --- |
| 808 | 金元宝 | `购买个数=100`；兑换 100 金，即 1,000,000 铜钱/份 |
| 817 | 普通礼包 | 黄金钥匙（815）×5 |
| 818 | 高级礼包 | 传送石（800）×5、小喇叭（807）×5、双倍经验卡（809）×10、修炼丹（827）×10 |
| 819 | 至尊礼包 | 黄金钥匙（815）×10、战斗心得（828）×5、四倍经验卡（810）×5 |

本服务端的钱币权威值 `role->money` 的显示换算为
`gold=money/10000, silver=(money/100)%100, copper=money%100`，所以 808 的
每份结算值是 `100 * 10000`。

## 首次违反的契约与根因

旧的 `vm_net_mock_build_shop_buy14_response` 对所有商城 ID 都调用普通
`vm_net_mock_role_add_backpack_item()`。这会把 808/817--819 持久化成通用背包
记录，然而 `sub_9DE` 对这些 ID 的成功分支明确不消费该记录。随后背包列表又为
避免 808 的零堆叠崩溃而隐藏该行，最终表现为：酷宝已扣、响应已成功、客户端却没有
任何可见或可用的结果。

已排除：价格来源错误（`item.dsh` 的秘宝酷宝列）、`14/3` 字段顺序错误、以及客户端
本地背包插入失败；前两者由实际日志和反编译字段读取证明，后一者正是客户端对这四种
直发项目的设计行为。

## 修复设计

- 将 808、817--819 限定在 `type=2` 商城路径按上表结算，而不是入库其本体。
- 礼包的内容物通过角色背包的内存 mutation 逐项加入，在扣酷宝后使用一次
  `role_db_save("shop-buy14-direct")` 持久化；任一物品因容量或序号分配失败时恢复
  整个角色快照，不扣酷宝。
- 金元宝在同一次成功回执中附加末尾 `1/1/14 actorinfo`，使客户端按已验证的商城
  actor-state parser 立即刷新钱币；回执本身仍保持 `14/3 {seq,result}` 的字段契约。
- 礼包不发送其本体的背包行；设置现有的购买后背包刷新标记，让客户端下一次正常
  `17/1`/`7/42` 路径显示其内容物。

## 验证目标

1. 购买一份金元宝：酷宝扣除一次，角色钱币增加 100 金，商城仍可继续操作。
2. 分别购买 817、818、819：礼包本体不出现在背包，打开背包后出现上表内容物和
   正确数量。
3. 背包没有足够空间时，礼包购买返回 `result=2`，角色钱币、酷宝及所有内容物均不变。
4. 重新登录后，钱币/礼包内容仍保持；`30/21`、`17/1` 中不出现 808、817--819。
