# 梦境空间地图刷怪取证（2026-07-30）

## 问题

用户反馈：原版 `29梦境空间` 地图上可以刷怪；当前 mock 进图后地图无怪。

## 资源交叉核验

全仓库（`web/fs`、`bin*`、`JianghuOL/.../assets`）中：

| 文件 | 大小 | MD5（前 12） | kind=3 战斗点 |
| --- | ---: | --- | ---: |
| `29梦境空间_01/02/03.sce` | 278 | `65a028cbf6aa`（三层相同） | **0** |
| `29梦境空间_03.map` | 871 | 共用 | — |
| `b_29梦境空间.sce/.map` | 167 / 434 | 出口壳 | 无战斗点 |
| `FB_lotus*` 等 | 装饰 | — | 非战斗 |

对比同包可踩怪场景（压缩 `.sce` 更大且含 kind=3）：

- `01桃花岛_01`、`25华山洞窟_01`、`27深渊沼泽_01`、`28地府门道_01` 均有多枚战斗 Actor。
- `automonster.dsh` 最后一行止于 `28地府门道_*`，**无任何 `29*`**。

结论：客户端资源包里的梦境 SCE **本身完整但无战斗点**，不是下载截断；仓库内**不存在**更大的「带怪版」梦境 SCE。

## 物品文案旁证（`item.dsh`）

- `#840` 梦境徽章：「梦境空间 **BOSS** 掉落物…」
- 另有梦境精魄等「梦境空间生物」描述  

支持「梦境有战斗/掉落」，**不证明**地图 kind=3 游走怪；与「副本 BOSS / 挑战开战」也兼容。

## 已证实的地图造怪契约

客户端进图后由本地 SCE → `ParseMinfoAndSpawnNPCs` 建 **kind-2 战斗节点**（见 `mock_server_social.c` 注释与 shop-return kind-2 文档）。

| 通道 | 能否在地图造可点怪 |
| --- | --- |
| SCE kind=3 | **能**（华山/地府等） |
| `automonster` / 后台场景刷怪 | **否**（只挂机选 ID；CBE 不引用 automonster） |
| `challenge_enemy_id` → `4/10` | **否**（非场景开战，无地图精灵） |
| `1/2/2` moveinfo | **否**（只灌已有 live-node 血蓝） |
| `27/11` npcinfo | **否**（type-21 NPC；空目录不重建战斗节点） |

## 对「原版能刷怪」的解释（按证据优先级）

1. **最吻合现有包数据**：原版梦境主战斗是 **副本向导「挑战守关怪」/ BOSS `4/10`**，玩家记忆中的「刷怪」可能是挑战/挂机，而非地图精灵。物品文案强调 BOSS。
2. **若确有地图游走怪**：权威不在当前客户端包内 SCE，只可能是  
   - 原服经 WT18/7 **下发过带 kind=3 的替换 SCE**（本仓库无该版本），或  
   - **尚未还原的服务端造节点协议**（本仓库无进梦境抓包、无 IDA 证据）。  
   在证据出现前，不得用伪 `27/11`/`1/2/2` 硬塞。

## unresolved

## 若目标是地图可点怪（对齐 25/27/28）

在 `29梦境空间_*.sce` **写入真实 kind=3**（可走区坐标 + 已有 `e_*.actor`），再经更新通道发布。这是现有客户端契约下唯一已证实路径。

挂机三槽 / `challenge_enemy_id` 仍不替代 SCE 造点。

## CBE 路径（江湖OL.CBE，既有 IDA 取证）

本会话未连 IDA；下列地址来自仓库已记录的反编译结论。

| 地址 | 函数 | 作用 |
| --- | --- | --- |
| `0x010396D6` | `scene_handle_enter_with_scene_pos` | 消费 `30/1` scene+posinfo |
| `0x01006204` | `LoadSceneDataFromStream` | 读**本地** SCE 流 |
| `0x010159DA` | `ParseMinfoAndSpawnNPCs` | 从 SCE 建 kind-2（门/战斗碰撞节点） |
| `0x01037998` | `scene_parse_npcinfo_and_spawn_npcs` | 消费 `27/11` → 节点类型 **21** |
| `0x0100EFC4` | `scene_node_find_or_create` | 通用造节点；类型由调用方写入 |

分流：

1. **地图可点怪**：`30/1` → LoadScene → ParseMinfo；SCE 记录 **kind=3** 变成运行时 **kind-2 战斗节点**。
2. **交互 NPC**：`27/11` → 类型 **21**，与 SCE kind=3 **不是同一条路径**。
3. **失败试验**：`2/5` / `2/10` 曾作 NPC 注入，文档记为破坏场景节点 / 空绘制回调；`1/2/2` 只刷新已有 live-node。

因此「服务端下发 kind=3」在 CBE 语义下只能是：**WT18/7 下发含 kind=3 的 `.sce`，再 `30/1` 触发 ParseMinfo**；没有已证实的「业务 WT 对象直接下发 kind=3」parser。
