# 怪物掉落概率小数精度

## 原有限制

怪物掉落概率原先从后台表单到内存和数据库都使用整数百分比，无法配置
`0.25%` 这类低概率掉落；战斗随机判定也只在 100 个整数百分比桶中取值。

## 新契约

后台的单条掉落和智能分配的品质 0/1/2 概率均支持 `0.01` 到 `100`，最多
两位小数。服务在内存中以基点保存：`25` 表示 `0.25%`，`10000` 表示
`100%`。数据库 `drop_rate_percent` 改为 `DECIMAL(5,2)`，原有整数数值保持
语义不变，例如 `5` 自动成为 `5.00`。

战斗掉落使用一次 0--9999 的随机判定，因此小数概率参与的是实际掉落，而非
仅后台显示。非掉落路径（例如逃跑）继续使用原有的整数百分比接口。

## 迁移与验证

服务启动会检测并将 `server_monsters` 和 `server_monster_drops` 的概率列升级为
`DECIMAL(5,2)`；停服手工升级可执行
`server/mysql/migrate_monster_drop_rate_decimal.sql`。

`scripts/monster-equipment-drop-assignment-regression.c` 断言 `0.25%` 表单解析、
格式化、超两位小数拒绝、智能分配小数概率保存值以及战斗的 0/100% 边界。
测试仅使用内存夹具，不连接 MySQL、不启动监听，也不写入持久化数据。
