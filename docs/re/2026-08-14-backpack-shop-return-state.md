# 背包打开商城后的返回状态

## 现象

从背包界面进入商城并返回时，客户端没有回到仍在栈中的背包，而是被带回场景。

## 客户端取证

IDA 实例先按 `binary_name=mmShopMstarWqvga.cbm` 动态选择。`sub_1038`
（商城模块初始化）只做以下工作：注册 `sub_9DE` 作为商城网络解析器，初始化商城页状态，
并发出 `1/14/14`、`1/14/4` 以及 `1/14/5..6` 请求。它没有调用场景进入、场景控制器或
screen-manager 的场景替换接口。

因此，商城关闭后恢复哪个界面是客户端既有 screen 栈的职责；商城初始化包本身不构成
“必须重入场景”的协议证据。`mmShop:sub_162C -> sub_11F0` 的 `1/1/14(actorId)` 仍须由
独立 builder 以“商城状态页 + 最后一个 ActorInfo”回应，但该请求本身不能证明来源是 NPC，
更不能授权场景重入。

## 2026-08-14 购买卡住与场景二次加载复核

### 运行时证据

本轮 `bin/server_out.txt` 的同一会话记录了：

1. 商城武器页的 `10001` 发出 `1/14/3 { type=2, id=10001, num=1 }`，服务端却记录
   `known=0 result=0`。`10001` 已由该商城页下发为有效目录项；错误来自
   `vm_net_mock_shop_calculate_cost()` 把 `type=2` 额外限制为“秘宝道具”。这是购买等待不
   结束的第一个协议偏离。
2. 普通商城打开先处理完整 `14/14+14/4+14/5+14/6`，随后收到
   `1/1/14 { actorId=10001 }`，其中 `10001` 等于当前角色 ID。旧的 actor-query builder
   仍据此写入 `shopSceneNpcReseedPending`，后续正常 scene follow-up 随即被转换为
   `1/30/1`；日志中的 `mock_shop_return_scene_enter ... contract=30/1...` 就是关闭商城后
   额外场景重载的直接来源。

### 客户端证据

- `mmShopMstarWqvga.cbm:sub_2F6C (0x2F6C)` 只序列化当前选择状态中的 `type`、`id`、
  `num` 为 `1/14/3`，不按物品 ID 范围或商城页类别拒绝武器。
- `mmShopMstarWqvga.cbm:sub_9DE (0x9DE)` 读取 `14/3` 的 `seq` 与 `result`，并只在
  `result=1` 时走购买完成分支；该函数没有以 `type=2` 排除装备目录项。
- `mmShopMstarWqvga.cbm:sub_11F0 (0x11F0)` 只把模块状态字段 `r9+10620`
  （反编译为 `v0[2655]`）写为 `actorId`。该单字段请求没有“由 NPC 对话进入”或“必须重建
  场景”的来源信息；`sub_1038 (0x1038)` 的商城初始化也没有场景进入调用。

## 根因

1. 服务端错误地将 `14/3.type==2` 解释为“只允许秘宝道具”，与客户端显示并可选择的武器
   商城行不一致，导致有效购买收到失败结果。
2. 服务端错误地将通用 `1/1/14(actorId)` 查询提升为“商城返回场景”事件。运行证据已经
   证明该请求可携带当前角色 ID，不能作为 NPC 或场景重入来源判据；它预置的会话标记使
   下一条普通 scene follow-up 被改造成 `30/1`，造成二次加载。

## 修正约束

1. 所有商城初始化/actor 查询响应只返回商城数据和必需的 ActorInfo，保留客户端现有
   screen 栈；不得预置场景重入。
2. `14/3` 的可买性以服务端已下发的启用目录项为准；`type` 保留给客户端余额/特殊物品
   分支，不得再用来排除装备页目录项。
3. 商城打开不得重置背包网格的登录期种子，因为不会重建 `mmGame` 的物品管理器；
成功购买所需的背包刷新仍由其自身的 `17/1` / `7/42` 请求处理。
4. 不修改客户端内存、screen 栈、寄存器或代码；不以延迟、屏蔽包或默认场景作为规避。

## 回归

1. 场景中打开背包，再由背包进入商城，返回后仍显示同一背包分类、选择项和滚动位置。
2. 商城购买普通物品后返回，背包仍显示且下一次刷新使用角色背包行而非商城 `17/1` 列表。
3. 商城武器页购买 `10001` 收到 `14/3 result=1` 并完成客户端物品插入。
4. 普通商城关闭后的 scene follow-up 不再产生 `mock_shop_return_scene_enter` 或任何
   `30/1`；NPC 对话中的购买入口同样不重建场景。

- `vm_net_mock_build_shop_actor_query14_response()` 仍按原顺序返回最后一个 ActorInfo，
  但不再重置背包网格种子或写入 scene-return 标记。

- 尚待真实客户端回归：这次修改没有启动、停止或替换用户当前运行的服务端。新版日志应
  显示武器购买 `known=1 result=1`，且商城关闭后不再出现
  `mock_shop_return_scene_enter`。
