# 服务端 EXE 体积与账号缓存生命周期

## 触发条件

Windows 服务端 `bin/jh-online-server.exe` 的体积达到 `136,169,820` 字节。该问题在
构建产物阶段即可稳定复现，与客户端请求、网络响应或 MySQL 内容无关。

## 取证

对旧产物执行 `objdump -h` 和 `nm -S --size-sort -r`：

- `.data` 为 `0x07ce93c0`（约 132 MB），而全部 DWARF 调试段约 2.7 MB；调试信息不是
  主因。
- `g_vm_mock_service_account_db` 单独为 `0x07a12020` 字节（约 128 MB）。
- 根因是账号缓存结构把 `1,000,000` 个、每条 128 字节的账号记录内嵌在静态数组中。
  在当前 MinGW PE 构建中，该静态对象进入已初始化 `.data`，被完整写入 EXE。
- 原有的旧账号快照导入还在函数栈上声明相同的大结构；即使常规运行已由 MySQL 权威
  持久化，这个遗留路径仍有约 128 MB 栈帧风险。

## 修正

`vm_mock_service_account_db_file` 改为小型头部加动态 `accounts` 指针：

1. MySQL 账号查询回调按需扩容，初始容量为 64 条，随后按 1.5 倍增长，最高仍严格限制为
   `1,000,000` 条。
2. 新账号写入会先保留一个记录槽，再写入 MySQL；分配失败不会修改数据库或内存目录。
3. 旧 `JHA1` 快照改为读取固定 12 字节头部后，动态读取其声明的实际记录数；不再把最大
   快照放进栈内存。旧文件格式保持兼容。
4. MySQL 仍是账号权威数据源；动态目录只是登录和后台查询缓存，没有改变注册、密码修改
   或事务写入契约。

未把其余固定大小的协议目录和服务会话表一并改写：它们合计只占数 MB，并且部分容量是
客户端/协议约束。先消除已证明占用 128 MB 的对象，避免以文件体积为由改变无关状态生命周期。

## 验证

修改后执行 `make -j2` 成功。新产物：

- `bin/jh-online-server.exe`：`8,173,047` 字节；
- `.data`：`0x002d73a0`（约 2.97 MB）；
- `nm` 中的 `g_vm_mock_service_account_db` 只剩 20 字节的缓存头；128 MB 的内嵌
  记录数组已不存在。
