# 怪物智能掉落分配规则核查

状态：已取证，尚未改变分配规则。

## 触发反馈

运营观察到两类现象：高等级首领疑似承接了明显偏低等级的装备；小龙女没有优先获得“龙女肚兜”。本次只读取 `equip.dsh`、SCE 怪物标签和当前配置库中的 `server_monsters` / `server_monster_drops`，不执行重新分配或写库。

## 当前规则

`vm_net_mock_monster_plan_equipment_drops()` 的承接顺序为：

1. 品质 0 仅普通怪、品质 1/2 仅首领；
2. 装备与怪物必须处于同一十级段；
3. 同品质同部位不能重复；
4. 在合格候选中，先比等级差，再比该品质已分配数，最后才以连续两个中文字符的名称关联作为打破平局的条件。

因此，名称关联并非优先规则，也不能跨过十级段门槛。这与“怪物名称应优先关联同名装备”的运营预期不一致。

## 资源与当前库证据

在部署的 `bin/JHOnlineData/equip.dsh` 中：

| 对象 | 数据 |
| --- | --- |
| 小龙女 | 怪物 ID `88`，SCE 标签“小龙女”；当前 MySQL 覆盖等级 `45`、首领 |
| 龙女肚兜 | 物品 ID `23504`、`30027`，需求等级 `38`、品质 `2`、装备槽位 `2` |
| 名称关系 | “小龙女”与“龙女肚兜”连续中文 token 匹配长度为 `2` |

等级 45 与 38 不在同一十级段，所以即使名称匹配成立，现有规划器也会拒绝小龙女。当前保存给小龙女的 16 件品质 1/2 装备均为 41–45 级，符合旧规则。

同一套当前 MySQL 配置中，等级 53 的首领（ID `19`）保存了一个任务材料及 16 件需求等级 51–55 的品质 1/2 装备，未发现需求等级 30 的装备。因此“53 级首领有大量 30 级装备”不是该配置库当前规划器输出；若游戏内仍显示该现象，应先比对客户端连接的服务实例和数据库名，并保留对应 `monster_equipment_drop_assign` 日志。

## 拟议规则（待确认后实施）

为同时保留成长段保护和名称关联，应将候选分为两层：

1. **强名称关联层**：连续至少两个中文字符相同，且装备与怪物等级差不超过 10；允许跨相邻十级段。小龙女 45 级与龙女肚兜 38 级符合这一层。
2. **常规层**：仍严格要求同十级段，以防 53 级首领承接 30 级装备。

强名称关联应在常规候选之前选择；同层内再按是否同段、等级差、品质已分配数和怪物 ID 排序。这样名称不会被“先比已分配数”的公平性规则压掉，也不会让低级装备无界上溢。

实施前需新增纯内存回归：45 级小龙女获得 38 级龙女肚兜；53 级首领不能获得 30 级装备；多首领同段时仍保持品质和部位分布均衡。
