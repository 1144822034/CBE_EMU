# 强化成功率：目标级玄晶 100% / 当前级 40%（2026-07-31）

## 约定

`+L → +(L+1)`：

- **目标级及以上**玄晶（等级 ≥ L+1）：单颗 **100%**
- **当前级**玄晶（等级 = L）：**40%**
- 再每低一级：贡献 ×40%（16%、6%…）
- 多颗累加，封顶 100%

## 样例

| 强化 | 材料 | rate |
| --- | --- | ---: |
| +4→+5 | 1×五级 | **100%** |
| +4→+5 | 1×四级 | **40%** |
| +4→+5 | 1×三级 | **16%** |
| +0→+1 | 1×一级 | **100%** |
| +15→+16 | 1×十六级 | **100%** |
| +15→+16 | 1×十五级 | **40%** |
| +15→+16 | 3×十五级 | **100%**（40×3） |

## 公式

```text
unit(tier) = 100                            // tier > L（含目标 L+1）
unit(tier) = 100 * (0.4)^(L - tier + 1)     // tier <= L
rate = min(100, Σ unit(tier_i) * count_i)
```

`29/1` data1/data2 用紧凑线性表（`power=tier×100`，`required(+0)=100`，
`required(+N)=N×250`）。**不要**再下发指数强度表：required(+13) 会到约 2e6，
客户端会把可用上限截成 12 并提示「强化等级达到上限」
（见 `2026-07-31-enhance-maxlevel-clamp-at-12.md`）。

真实预览/掷骰以 `29/2` `value` 为准。铜币与 compact `required` 同曲线。
