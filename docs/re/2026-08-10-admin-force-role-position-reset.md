# 后台强制重置在线角色位置（2026-08-10）

## 触发与首个偏离

后台“账号管理 → 重置到指定场景”原先在读取目标角色以前，用
`vm_mock_service_account_has_live_role_session(accountId)` 拒绝整个账号中任一在线
角色。管理员因此无法修复仍在线、但位置已经导致无法正常进入场景的角色；同账号的另一
角色在线也会错误阻断目标角色的修复。

旧实现虽然会在事务提交后断开目标会话，但离线转换与位置写入的先后关系不再符合管理操作的
统一契约。首个被违反的契约是“任何持久化位置修复都必须在旧会话完成离线转换后执行”，否则
在线快照仍可能在重置期间拥有旧位置。

## 正确生命周期边界

1. 仍要求管理端提交精确、服务端存在的 `.sce`，并从该 SCE 解析安全落点。
2. 管理端先以只读管理快照确认目标 `role_id`，随后关闭该快照。
3. 仅匹配 `(account_id, onlineRoleId)` 的会话执行既有
   `vm_mock_service_session_mark_offline()` 生命周期，然后清除该 session 的
   `accountId` 绑定。其他角色、其他账号均不受影响。
4. 管理端重新加载离线后的角色快照，在已有全局协议互斥锁下写入完整角色关系数据。
5. 清除绑定使下一次来自旧客户端的请求不能恢复或保存旧角色位置，客户端须按既有登录
   流程重新认证并读取新落点。

服务端请求处理为短连接：每一个请求持有并在响应后关闭自己的 transport socket，长期
session 中不保存可供后台关闭的 TCP socket。因此不伪造新的客户端下行“踢线”包，也不
尝试关闭无所有权的连接；复用账号封禁既有的“标准离线转换 + 清除绑定”才是这里真实的
服务端断开契约。

## 证据

- `src/server/mock_server_transport.c` 在普通客户端显式断开时，先在同一
  `g_vm_mock_service_protocol_mutex` 下保存脏位置，再走
  `vm_mock_service_session_mark_offline()`。
- `src/server/mock_server_equipment_npc.c` 的账号封禁已采用同一离线转换后清除
  `session->accountId` 的方式，避免无凭据标题请求复用旧账号绑定。
- 后台重置先关闭首次管理快照，再执行同一离线转换，并在第二次管理快照中写入安全落点；
  因而不会保留可在提交后覆盖新位置的在线角色快照。

## 验证边界

构建验证：`make -j2`。

人工回归应覆盖：

1. 目标角色在线时重置：后台成功提示已断开；该客户端下一次联网动作回到既有登录路径，
   重新进入后位于指定 SCE 的安全落点。
2. 同账号另一角色在线时重置离线目标角色：另一角色不被断开。
3. 离线目标角色重置：行为保持不变。
4. 在线目标角色重置后再让旧客户端发送一次请求：不得把旧场景/坐标写回数据库。
