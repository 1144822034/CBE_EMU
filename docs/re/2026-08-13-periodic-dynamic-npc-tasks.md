# 动态 NPC 任务的周期接取规则

## 目标

动态 NPC 的“可接取任务”除一次性与不限次数外，支持按自然日、自然周、自然月限制每个角色的接取次数。

## 配置与兼容

`server_dynamic_npc_tasks.repeatable` 复用为规则码：

- `0`：完成后不可再次接取；
- `1`：不限次数，完成后可立即再次接取；
- `2`：每日一次；
- `3`：每周一次；
- `4`：每月一次。

旧数据中的 `repeatable=1` 继续表示“不限次数”，不需要数据迁移。后台“任务重复接取规则”会显示这五种选项。

## 权威判定

客户端的 `6/11` 接取请求不携带 NPC 规则。服务端在该 NPC 对话实际下发任务选项时，把任务、NPC、场景和规则记录到当前会话；接取时消费该上下文并重新检查规则。

完成时 `account_role_tasks.task_state` 写为 `3`，其 `updated_at` 即为权威完成时间。规则按服务器本地自然周期比较：每日跨零点、每周跨周一零点、每月跨月初。任务进行中或待提交时不会重复接取。

任务候选列表、场景 NPC 的任务优先级/标识、NPC 对话选项和最终接取校验共用同一可用性判定。这样周期未刷新时不会出现“图标可接但接取失败”的状态。

如果重接取过程中的背包物品发放失败，服务端会恢复原完成时间，避免 MySQL 的自动更新时间意外延长周期。

## 验证

编译验证：`make -j2`。

手动验证：为一个动态 NPC 绑定任务并依次选择每日、每周、每月一次；完成提交后再次对话应不再给出接取选项，跨对应自然周期后才重新出现。选择不限次数时应保持旧行为。
