# 怪物管理：仅重置战斗四项属性（2026-08-10）

## 需求与原有边界

怪物管理原有“恢复服务端默认”动作会在一个事务中删除
`server_monsters` 与 `server_monster_drops` 的整条覆盖记录。这适合完全放弃编辑，
但不能用于“只重置 HP、MP、攻击、防御”：直接复用会错误丢失管理员已设置的等级、
怪物类型、经验、金钱和多项掉落。

## 正确契约

新增 `reset-monster-combat-stats` 管理动作，仅接受 `monster_id`。对于已有 MySQL
覆盖：

1. 使用该覆盖当前的 `level` 和 `family` 调用与普通怪物默认一致的基线计算；
2. 只替换 `hp`、`mp`、`attack`、`defense`；
3. 通过既有 `vm_net_mock_monster_admin_save()` 事务写回完整记录，保留经验、金钱和掉落。

若怪物没有 MySQL 覆盖，四项属性本来就来自同一基线公式，动作记录为 `noop`，不产生
冗余数据库记录。该功能只改变服务端权威怪物配置，不向客户端伪造响应或修改客户端状态；
之后正常战斗请求会读取新的属性。

## 可观察证据与验证

- 成功日志：`monster_combat_stats_reset ... preserve=reward-and-drops`；无覆盖时为
  `source=server-default action=noop`。
- 后台成功提示明确说明只改四项战斗属性。
- 构建验证：`make -j2`。

人工回归：编辑怪物的等级、奖励和多项掉落后将四项战斗属性改为任意值；点击新按钮应使
四项回到该等级/类型的公式值，而奖励、掉落、等级和类型保持原值。点击“恢复服务端默认”
仍应保留其原本的全量删除语义。
