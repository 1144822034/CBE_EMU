# 快速修理后进度条卡住 / 报价件数错乱

## phase

故障修复；状态：已实现（两阶段契约）。

## 触发

1. 个性/死亡菜单点「快速修理」后进度条不消失，或只靠旁路系统提示「修理完成」。
2. 确认框显示「您身上有25455件装备」（件数≈铜钱修理费）。

## 客户端契约

| 项 | 证据 |
|----|------|
| 报价请求 | `JianghuOL.CBE:0x0101CADC` → `1/7/29 {type}` |
| 报价/空闲 | `HandleRepairResponse(0x01028C9A)`：`repairnum>0` 确认框（件数+费用）；`type∈{1,2}` 且 `repairnum≤0` tip 无需修理 |
| 确认请求 | `JianghuOL.CBE:0x0101A8A0` → `1/7/13 …` |
| **完成** | `mmGameMstarWqvga.cbm:0x4986` 解析 **`1/7/13 {result}`** |
| result=1 | tip **修理完成**并清 wait |
| result=2 | 资金不足类对话框 |
| busy / 物品 | 同包 `7/7` 可经 `sub_11CE` 再置 `r9+21808`（NPC 购买同契约） |

## 根因

1. 完成态必须走 mmGame `7/13`，系统聊天 / `7/29 type=0` 不能清 wait。
2. 若在报价阶段把 `repair_cost` 的铜钱和写入 `repairnum`，客户端按「件数」显示 →「25455件」。
3. 正确链路是两阶段：`7/29` 报价（件数 + coolmoney=5）→ 用户确认 → `7/13` 扣费结算。

## 修改点

- 报价：`7/29` 只填 `repairnum=待修件数`、`coolmoney=5`，arm quote。
- 确认：`7/13` 扣 5 酷宝并修耐久，回 `result=1|2`；装备 `7/7` poll 延期。
- 无需修理：仍回 `7/29` 回显 type + `repairnum=0`。

## 验证

1. 有缺口：确认框件数 ≤ 装备槽位数，花费 5；确认后 tip「修理完成」、进度条消失、酷宝-5。
2. 酷宝不足：资金不足对话框、进度条消失。
3. 无需修理：原 tip；无 `7/13`。
4. `make -j2 server`。
