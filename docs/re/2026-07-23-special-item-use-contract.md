# 特殊道具使用：协议与权威状态契约

## 触发与首次偏离

在背包中选择特殊道具时，客户端不会把所有物品都提交为通用的
`WT 1/7/1`。当前服务端只实现了这个通用请求，因此经验卡、大力丸等
请求没有对应的 handler/响应；客户端的等待状态不会被结束，后续不能由
通用 `7/1`、`7/7` 或 `7/11` 伪造完成。

这就是本问题的首次偏离：服务端在请求分派层把专用物品协议遗漏为
“普通可消耗物品”。崩溃、等待条或背包显示不同步只是该偏离后的表现，
不是应当在客户端或 UI 层抑制的根因。

## 客户端证据

证据来自已按 `binary_name=江湖OL.CBE` 选择的 IDA 实例，以及
`tmp/ida_full_jh_actor_update/decompiled.c`：

| 道具 | 客户端请求 | 客户端成功响应契约 | 客户端扣除方式 |
| --- | --- | --- | --- |
| 809 双倍经验卡 | `1/7/30 {itemseq:u16,num:u8=1}` | `1/7/30 {result:u8=1,iteminfo:string}` | `HandleShopBuyItem(0x01025AE6)` 自行删除当前行并置 `expcard=1` |
| 810 四倍经验卡 | 同上 | 同上 | 同上 |
| 811 十倍经验卡 | 同上 | 同上 | 同上 |
| 829 大力丸 | `1/22/3 {seq:u16}` | `1/22/3 {result:u8=1,info:string,ruffianflag:u8}` | 同一专用响应分支自行删除当前行 |
| 830 神力丸 | 同上 | 同上 | 同上 |
| 827 修炼丹 | `1/7/16 {itemseq:u16}` | `1/7/16 {result,maxnum,iteminfo}` | 专用操作分支；不是 `7/1` |
| 828 战斗心得 | `1/25/6 {seq:u16}` | `1/25/6 {result,maxnum,iteminfo}` | `result=1` 时客户端请求背包刷新并关闭对话框 |
| 833 聚元丹 | `1/7/33 {itemseq:u16}` | `1/7/33 {result,maxnum,iteminfo}` | 专用操作分支；不是 `7/1` |
| 920 修炼天书 | `1/7/35 {seq:u16}` | `1/7/35 {result,bookdes}` | `result=0` 时客户端自行删除；实际书本内容为服务端数据 |
| 921 修炼天书实例 | 先 `1/7/38 {seq:u16}` 读描述，再 `1/7/40 {seq:u16}` 使用 | `7/38 {bookdes}`；`7/40` 的 result=0 还必须附带 `bookinfo,level,lastexp,curexp,persentexp` | 动态书本记录决定内容和经验，不能从 `item.dsh` 凭空推导 |

`HandleItemOperationResponse(0x01033544)` 只适用于通用 `7/1`；对上表任一
专用请求追加它会让客户端再次删除同一背包项或进入错误 UI 分支。

## 资源数据

`web/fs/JHOnlineData/item.dsh` 的字段顺序已经直接核验：

- 809/810/811 的说明分别给出 2、4、10 倍经验，时效均为 60 分钟。
- 828 的说明给出 60 分钟、战斗经验增加 20%。
- 829/830 的说明只给出“伤害和防御明显/巨幅提升”、时效 30 分钟；所有
  数值属性列均为零。因此该资源不能证明固定的攻防数值。
- 827 说明为离线修炼时间（每天最多 8 小时、累计最多 100 小时）；833 是
  活力恢复 100；这些依赖当前尚未建模的离线修炼/活力权威状态。
- 920/921 需要动态书本等级、经验内容和归属；静态 item 行没有这些值。

## 本次可实现范围

1. 为经验卡建立角色级、持久化且会过期的效果记录；只在怪物战斗奖励结算
   边界应用 2/4/10 倍，避免错误放大任务奖励或直接经验物品。
2. 登录、场景状态刷新和卡片状态查询均按同一持久化记录向客户端下发
   `expcard`，过期后明确下发 `7/32 {expcard=0}`。
3. 为战斗心得建立同样的角色级、60 分钟持久化记录；其 `multiplier=20`
   在该 effect kind 中明确表示“基础怪物经验的附加百分比”，不是经验卡倍数。
   奖励结算先应用经验卡，再额外加上 `基础经验 * 20%`。这是由资源文字
   “经验增加 20%”作出的可审计解释；不会放大任务奖励或战斗中直接使用的
   经验物品。
4. 大力丸/神力丸现在得到其真实 `22/3` 响应形状，但服务器返回明确的
   非成功 `result=4` 并保留道具。原因不是客户端兼容性：权威资源只有
   “明显/巨幅提升”文字，所有数值攻防列均为零；在没有真实数值前成功扣除
   而服务器战斗仍不增伤/减伤会构成假成功。
5. 修炼丹、聚元丹、920/921 修炼天书也不会再落到未处理断言：服务端分别
   回 `7/16`、`7/33`、`7/35`、`7/38`、`7/40` 的客户端已证实字段布局，
   但使用非成功/仅展示结果并保留背包项。这样能关闭客户端等待状态，同时
   不会把尚无离线修炼时间、活力、天书等级/经验记录的数据伪造成已生效。

827、833、920、921 不会由通用 `7/1` 偷偷扣除。它们各自缺少的权威
数据必须继续取证后再落地，避免“响应成功但实际无效果”的假成功。

## 验证要求

- 卡片请求只得到一个 `7/30` 专用响应，客户端自行删除一份；数据库内的
  背包扣除和时效记录必须在同一事务提交。
- 重新登录期间卡片未过期时客户端仍显示激活状态；过期后状态清除。
- 单次怪物战斗奖励按激活经验卡和战斗心得结算一次，不放大任务奖励或战斗中
  使用的直接经验物品。
- 大力丸/神力丸只得到 `22/3` 的专用响应，绝不追加通用背包删除包；权威数值
  缺失时必须保留道具。
- 覆盖无效序号、MySQL 失败回滚、重复登录和两个帐号的隔离。
