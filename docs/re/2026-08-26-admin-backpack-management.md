# 后台账号背包管理

账号管理的每个角色“操作”对话框新增“背包管理”页，用于查看该角色持久化的背包条目并删除指定条目。

## 身份与删除边界

- 页面逐项显示物品名称（目录可解析时）、物品 ID、背包序号、数量；装备实例还显示强化和耐久。背包条目区域独立滚动，外层角色操作内容区也允许收缩和滚动；窄屏导航按全部 7 个功能标签横向滚动，避免背包标签换行挤占列表高度。
- 删除请求携带账号、`role_id`、`item_id` 与 `item_seq`。服务端要求四项均有效，并以 `(role_id, item_id, item_seq)` 精确查找；不会按物品 ID 模糊删除，因此同 ID 的多个堆叠或装备实例互不影响。
- 一个确认后的删除会移除该背包序号对应的整组数量。请求在 `vm_mock_service_account_remove_role_backpack_item` 中打开该账号的角色数据库快照，清空目标条目、规范化背包，并以关系型全量快照事务保存。保存失败时会还原内存快照。
- 普通用户账号中心和后台共用这一删除服务，避免两条路径出现不同的背包持久化语义。

## 审计与验证

- 后台动作码为 `remove-role-backpack-item`，操作日志记录目标账号、角色、物品、删除数量及背包序号；日志写入失败会明确提示“物品已删除、日志未写入”。
- `scripts/admin-request-length-regression.c` 构造含普通物品和装备实例的角色，验证背包页、精确删除表单字段和操作日志标签均被渲染。
- 构建后运行该回归测试可验证后台 HTML 与操作登记；实际删除仍由 MySQL 关系型快照事务决定提交或回滚。
