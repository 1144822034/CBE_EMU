# 梦境空间 SCE 写入 kind=3 试验（2026-07-31）

## 目的

在 stub `29梦境空间_*` 写入 kind=3，使 `ParseMinfoAndSpawnNPCs` 造出地图战斗节点。

## 试验矩阵

| 版本 | 布局 | 结果 |
| --- | --- | --- |
| v1 | kind=3 **插入** FB 落点流与 `01 00 04 00` 命名传送之间 | **闪退**（落点流错位） |
| v2 | kind=3 **追加**在命名传送之后 | 不闪、**无怪**（尾部不被扫） |
| v3 | FB 落点完整保留 → `08 00` + kind=3 → 命名传送 | **出怪成功** |
| v3b | 同上，坐标改到入口西侧落点簇 | **待复测可达性** |

## 根因（v1 / v2）

梦境与 `b_29*` 同属 **FB 装饰场景族**（全库仅此）。载荷为：

1. `01 00 01 00 0d 00 01 00 00 00 06 00` + `FB_*.actor` 名表  
2. 连续 8 字节落点 `(x,y,0,actorIndex)`，`actorIndex < 名表数`  
3. 命名传送哨兵 `01 00 04 00 …`

对照可刷怪且带装饰的 `01桃花岛_01`：落点之后是 **`08 00 02 00` edge_portal**，再是 kind=3。  
地府战斗段则以 **`08 00 03 00`** 开头。

对 6 个 FB Actor 的梦境，裸 kind=3 头 `03 00 x y 05 00` 被落点循环看成 `index=5`（仍合法）→ 错位闪退。  
尾部追加则落点循环在命名传送处正常结束，**不再扫描**后面的 kind=3。

## v3 做法

脚本：`scripts/inject_dream_sce_kind3.py`

1. 从备份恢复 stub 前缀（落点 → 原命名传送偏移 245）  
2. 在命名传送前插入：`08 00` + 3×kind=3（#200 幽冥鬼火）  
3. 保留原命名传送字节  
4. 字面量 LZSS 写回 `bin/` + `web/fs/`，bump catalog  

落点 peek `[8, 3, 210, 292]` 的 index=292 ≥ 6 → 应结束落点循环。

坐标：

- v3（部分不可达）：(210,292) (355,276) (377,295) — 后两只在右侧装饰岛  
- v3b：(135,49) (65,84) (107,254) — 入口 `(50,50)` 西侧既有 FB 落点  

备份：`bin/JHOnlineData/_bak_dream_sce_before_kind3/`。

## 验证

1. 重启 mock；清客户端 `JHOnlineData/29梦境空间_*`  
2. 进 `29梦境空间_01`  
3. v3 已确认出怪；v3b 期望三只均可走到  
4. 若仍有不可达：按实际可达带微调解码落点，不必再改段结构
