# 装备强化玄晶数量不刷新

## 触发与现象（用户确认）

1. **放入玄晶时**：选择列表数量不减。
2. **返回强化后**：主背包玄晶数量也不更新。

## 业务链路

1. 开强化 `1/29/1` → 开玄晶背包 `0x0101C458` 填 `R9+0x900`，
   `0x0101C042` 用 `+4` 画选择列表。
2. 放入槽位 `0x0101E33E`：只改 `R9+0x580` 的 `+0x10/+0xe`，重画槽位；
   **不**改 `0x900+4`，**不**调用列表重绘。
3. 确认 `1/29/3` → `0x010293F0` → `0x0102147C(r2=0)` 按 `occult` 本地扣
   item-manager，**跳过** `0x900` 列表递减；随后 `0x0101C8F4` 关界面。
4. 旧 mock 只回 `29/3`（`result/tnum/equipseq/occult`），无背包权威同步对象。

| 场景 | 首次偏离 |

## 根因

- **选晶列表**：可见数量在 `0x900+4`；占用记账在 `0x580`。place 不把剩余写回列表。
  服务端无法在无请求时驱动该重绘。
- **返回后背包**：`r2=0` 本地 occult 扣减不可靠/不刷新网格；物品使用路径证明 stack
  变更需 `7/7 type=2`（iteminfo=remaining）+ `7/11.info`；铜币用 `1/10/26`。
