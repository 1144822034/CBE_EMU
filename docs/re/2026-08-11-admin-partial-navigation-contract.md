# 后台列表/详情局部导航约定

## 目标

后台的管理页选择一项数据时，只替换右侧详情编辑区；左侧目录的滚动位置、当前选择和浏览器
前进/后退历史必须保留。不能把一次简单的列表选择实现为整页重载。

## 通用契约

`/admin.js` 的 `setupPartialNavigation()` 使用以下声明式标记：

| 标记 | 所在元素 | 职责 |
| --- | --- | --- |
| `data-admin-list` | 可滚动的左侧目录 | 提供并恢复 `scrollTop` |
| `data-admin-select` | 指向同一 `tab` 的条目链接 | 拦截普通左键并请求目标详情 |
| `data-admin-detail` | 右侧详情容器 | 仅替换其内部 HTML |

响应仍是可直接访问的完整页面。局部请求会从返回文档取同名目录和详情片段，以响应中的
`aria-current="page"` 或 `.on` 同步当前选择，并以 `history.pushState()` 保留 URL；请求
失败或缺少片段时才回退到普通整页跳转，避免半页状态。

## Actor 资源管理接入

`?tab=actors` 已接入上述契约：Actor 条目和“新建 Actor 资源”使用
`data-admin-select`，Actor 列表使用 `data-admin-list`，右侧编辑卡片使用
`data-admin-detail`，并加载 `/admin.js`。因此切换 Actor 或进入新建模板时不再重载整页。

## 后续管理页要求

新建或改造具有“目录 + 详情”结构的后台页时，必须优先复用这三个标记和
`/admin.js`。只有详情替换后需要额外初始化控件时，才在通用脚本中增加幂等的
`setup...()` 初始化；不得重新实现整页跳转或依赖固定等待时间。

## 验证边界

构建验证执行 `make -j2`。浏览器回归应验证：切换任意两项时，文档不整页刷新、左侧滚动
位置不变、URL 和前进/后退能恢复相应详情；直接打开对应 URL 仍应渲染完整可用页面。
