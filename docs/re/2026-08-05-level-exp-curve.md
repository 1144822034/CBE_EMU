# 2026-08-05 等级经验曲线与 70 级封顶

## 触发条件

服务端原先以累计经验推导等级：升至 `N` 级的本级经验恒为
`100 * (N - 1)`，且没有上限。这与新的数值目标不相容：玩家在较高
等级仍能以非常小的线性经验升级，也可以进入 70 级以上。

## 现有协议契约

角色持久化字段 `account_roles.exp` 是**累计经验**。客户端的登录
`actorinfo`、战斗结算 `1/4/7` 和任务结算均接收：

```text
exp        当前累计经验
lastexp    当前等级起点的累计经验
curexp     下一等级起点的累计经验
persentexp 当前等级区间的百分比
level      由累计经验推导出的等级
```

因此不能把 `curexp` 改成单级需求，也不能只调整某一个结算包；所有
入口必须来自同一份累计阈值表。

## 数值设计

新曲线以“**升至该等级**所需的本级经验”作为锚点：

| 升至等级 | 本级经验 |
| --- | ---: |
| 2 | 67 |
| 10 | 386 |
| 20 | 3,460 |
| 30 | 31,010 |
| 40 | 277,899 |
| 49 | 2,000,000 |
| 60 | 22,317,680 |
| 69 | 160,617,144 |
| 70 | 200,000,000 |

相邻级别按指数比例增长，比例为 `100^(1/21)`；表中的整数值在构建时
已取整，并强制写死两个设计锚点。累计经验门槛为：

```text
48 -> 49: lastexp =   8,156,431, curexp =   10,156,431, 差额 2,000,000
69 -> 70: lastexp = 815,670,110, curexp = 1,015,670,110, 差额 200,000,000
70 级封顶: exp = 1,015,670,110, lastexp = curexp, persentexp = 100
```

`src/server/mock_server_role.c` 保存完整的累计阈值，避免服务端在不同
平台用浮点运算得到不同门槛。

## 旧角色迁移

旧数据格式为 6 或更低。升级为格式 7 时，服务端在角色标准化之前：

1. 保持旧的累计 `exp` 不变；
2. 仅当累计经验本身超过 70 级新曲线封顶门槛时，将其截到封顶门槛；
3. 以保留后的累计经验直接调用新曲线推导等级；
4. 在同一 MySQL 事务中写入规范化后的 `level`、必要时截断的 `exp` 与
   `account_role_state.format_version=7`。

旧等级只作为迁移审计信息，不能作为新等级依据。此前“保留旧等级再封顶”的做法会把
例如 162 级、1,315,134 累计经验的角色错误变为 70 级；按新曲线该累计经验落在 39 级。
事务失败时不会提交版本标记，下次加载会重新执行迁移。

## 覆盖范围

`vm_net_mock_role_level_start_exp`、`vm_net_mock_role_level_from_exp`、
`vm_net_mock_role_next_level_start_exp`、`vm_net_mock_role_exp_percent` 和
`vm_net_mock_role_add_exp` 是唯一的等级/经验入口。因此战斗奖励、任务
奖励、经验道具、死亡经验惩罚、登录 actorinfo 与结算包会共同使用新曲线。

70 级后奖励仍可正常完成其他结算，但不会增加超过上限的经验。
