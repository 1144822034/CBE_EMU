# 怪物四项属性的回合经济平衡（2026-08-14）

## 数据来源与比较口径

本次没有猜测客户端怪物公式。角色数据全部来自服务端当前的权威路径：

1. 无装备职业属性由 `vm_net_mock_role_build_base_player_stats()` 计算；
2. 同级品质 0 套装逐槽从真实 `JHOnlineData/equip.dsh` 选择：需求等级不高于角色等级、
   武器职业匹配、同级候选按物攻／护甲择优；
3. 怪物 HP、MP、攻击、防御由 `vm_net_mock_monster_base_stats_for_entry()` 下发；
4. 对攻回合使用战斗的同一软防御公式
   `damage = attack * 100 / (100 + defense)`，并向最近整数取整。

`automonster.dsh` 只有场景和怪物 ID 映射，不包含四项战斗属性；`server_monsters`
则是管理员的显式覆盖，不能当作未经解释的默认曲线来源。

## 实测样本

下表的无装备行取术士（职业 3，四项中最保守的常见基线）；品质 0 基准则是三职业中
每一项的最低值，用于使普通怪不会只对高输出职业成立。

| 等级 | 无装备 HP/MP/攻/防 | 品质 0 基准 HP/MP/攻/防 |
| ---: | --- | --- |
| 1 | 120 / 100 / 11 / 8 | 120 / 100 / 26 / 8 |
| 20 | 405 / 575 / 78 / 46 | 628 / 649 / 129 / 558 |
| 40 | 705 / 1075 / 148 / 86 | 1485 / 1372 / 286 / 1582 |
| 60 | 1005 / 1575 / 218 / 126 | 2234 / 1555 / 425 / 3588 |
| 70 | 1155 / 1825 / 253 / 146 | 3496 / 2253 / 791 / 5026 |

品质 0 装备的防御在中后期直接且完整地进入战斗属性，因此它是“同等级已正常装备角色”
的正确难度基线；裸装角色在高等级不应与完整套装处于同一战力层次。

旧普通怪 HP 按 `品质0攻击 × 5` 生成。装备攻击成长后，70 级最低职业要 **17** 次
普攻才能打败同级普通野兽；旧首领则需 **162** 次。首个偏离是把原始攻击直接当作生命池
倍率，忽略了战斗里防御对实际伤害的折减。

## 当前曲线（V4）

不再把完整品质 0 套装直接当成全部等级段的默认前提。每十级一个阶段，先把三职业的
**裸装保守值**与**同级品质 0 保守值**混合成预期战力；前 10 级完全按裸装，之后逐步提高
品质 0 装备的占比。HP、MP、攻击、防御分别混合，避免用某个职业的单一数值替代全部职业。

| 阶段 | 品质 0 占比 | 普通怪目标（击杀 / 承伤） | 首领目标（防御占比；击杀 / 承伤） |
| --- | ---: | --- | --- |
| 1–10 | 0% | 4 / 10 | 30%；12 / 5 |
| 11–20 | 20% | 5 / 11 | 34%；15 / 6 |
| 21–30 | 40% | 5 / 12 | 38%；20 / 7 |
| 31–40 | 60% | 6 / 13 | 42%；24 / 8 |
| 41–50 | 75% | 6 / 14 | 44%；28 / 8 |
| 51–60 | 90% | 7 / 15 | 45%；32 / 9 |
| 61–70 | 100% | 7 / 16 | 45%；36 / 9 |

普通怪仍使用战斗同一软防御公式：

```text
预期属性 = 裸装属性 × (1 - 品质0占比) + 品质0属性 × 品质0占比
普通防御 = 预期攻击 × 20%
普通HP   = SoftDamage(预期攻击, 普通防御) × 阶段击杀次数
普通攻击 = ceil(预期HP × (100 + 预期防御) / (阶段承伤次数 × 100))
```

首领以同一阶段预期属性计算，但使用表内首领防御占比、击杀次数和承伤次数。种类倍率依旧
最后应用：岩石、亡灵偏耐久，史莱姆、昆虫偏脆弱。

因此教程毒泥怪（3 级史莱姆）会从 V3 的 **197 / 29 / 15 / 6** 调整为
**58 / 29 / 15 / 3**。3 级裸装角色约 2～4 次普攻即可击杀，并可承受约 12～14 次攻击；
等级提升后，品质 0 装备逐步成为更轻松挑战同级怪的关键。

在保守品质 0 术士样本中，60 级普通怪约为 7 次击杀 / 18 次承伤、首领为 31 / 11；
70 级为普通怪 7 / 16、首领 36 / 10（整数伤害取整后比名义目标多一击）。

## 覆盖数据迁移

`server_monsters` 不是默认数据缓存，后台编辑过的怪物绝不能在曲线升级时被整体重置。
启动时的版本迁移（`monster-quality-zero-balance-v2`、`monster-quality-zero-balance-v3`、
`monster-quality-zero-balance-v4`）分别在一个 MySQL 事务中完成：

- 仅当某行的 **HP、MP、攻击、防御** 精确等于该等级、该类型的上一版本公式结果时，才把这四项
  更新为下一版本；经验、铜钱、掉落均不改动；
- 任一四项不同即视为管理员手调，完整保留；
- 迁移标记和全部更新同一事务提交，失败则回滚，下次启动重试。

因此新安装直接采用 V4；历史默认重置过的行会顺序升级；真实运营配置不会被静默覆盖。

后台的“重置属性与奖励”会按怪物当前等级和类型写入 HP、MP、攻击、防御、经验和铜钱；
物品掉落仍属于独立运营配置，不会因该按钮发生变化。“按场景等级重置”会额外改写怪物等级。

## 回归

`scripts/monster-balance-profile.c` 不启动服务、不连接 MySQL、不改动角色或数据库。它读取真实
`equip.dsh`，输出 1～70 级三职业的裸装／品质 0 对比及普通怪、首领回合数，并锁定 1、60、70
级的四项数值、3 级毒泥怪的新手契约，以及 60、70 级品质 0 职业的回合契约。
