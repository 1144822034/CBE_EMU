# 黄金宝箱获得数量提示虚高

## 触发与现象

开黄金宝箱时：

- 抽到装备等新行：提示「获得 1 个…」正常。
- 抽到可堆叠物（玄晶、材料等）且背包已有同 `itemId`：提示数量像是
  **原有堆叠 + 本次 1**；本地背包也可能短暂虚高。
- 重新登录后数量回到服务端真实值（仅 +1）。

## 业务链路

1. `1/7/15` 成功：服务端 `add_backpack_item` 真实只加 1，再组 `iteminfo`。
2. 客户端 `0x010261EC` → 自扣箱/钥 → 按 `total` 解析奖励行 →
   `0x01019228`：`*tipOut += wire_count`，并把 `wire_count` 叠加进本地行。
3. 成功提示 `0x01026376`：「获得%d个%s」使用上述累加值。

## 首次偏离

旧实现在入包后读 `rewardItem->count`（堆叠后绝对量）写入 `iteminfo` 的
`count`。可堆叠合并时该值 > 1，与「本次获得 1」契约偏离。

## 根因

`7/15` 奖励行 `count` 语义是**发放增量**，不是背包剩余/合并后总量。

## 修改

`vm_net_mock_build_chest_open_response`：`rewardCount` 固定为本次发放 `1`；
日志区分 `granted` 与 `bag_after`。
