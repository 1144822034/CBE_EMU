# player-3 鬼道鞋子智慧与单体伤害不变

状态：已取证；2026-08-26 已移除导致本问题的主属性 999 截断。

## 触发条件

`player-3` 的实际活动角色是 `10762`（鬼道、70 级），不是此前误查的角色
`10036`。在无情谷对怪物 `47` 使用鬼道单体技能 `201/operate=203` 时，用户先以
鞋子 `16402` 在装备栏的状态出手，随后脱下，再穿回；三次非暴击的 action 都显示
`694`。

服务端原始日志已经记录了完整顺序：

1. 鞋子在 slot `6`，以 `operate=203` 出手，伤害 `694`；
2. `7/8 type=4, seq=7` 成功脱下 `16402`，随后以同一技能出手，伤害仍为 `694`；
3. `7/8 type=3, seq=28` 成功穿回 `16402`，随后同一技能仍为 `694`。

三次目标的单体最大生命是 `1176`（三目标战斗的总生命为 `3528`），显著高于
`694`，因此不是目标剩余生命把伤害钳成相同数值。

## 装备与角色输入

客户端属性页显示正确：item `16402`（麻布靴）来自 `equip.dsh`，基础属性为
护甲 `65`、智慧 `21`、躲闪 `1`。当前实例耐久为 `67/70`、强化等级 `+2`；未达到
`+4`，所以没有已解锁的强化阶段词条。

角色的智慧来源如下：

| 来源 | 智慧 |
| --- | ---: |
| 鬼道 70 级基础成长 | 843 |
| 木制杖 `2001` | 26 |
| 梦境布盔 `40076` | 382 |
| 麻布靴 `16402` | 21 |
| 穿鞋合计 | 1272 |
| 脱鞋合计 | 1251 |

复现时（移除前），`vm_net_mock_role_build_player_stats_impl()` 对装备相加后的智慧执行
`min(value, 999)`。所以无论穿鞋还是脱鞋，技能结算实际读到的智慧都是 `999`：

```text
with boots: min(843 + 26 + 382 + 21, 999) = 999
without:    min(843 + 26 + 382,      999) = 999
```

这解释了“装备详情有 +21 智慧”与“伤害不变”同时成立，并不表示鞋子属性丢失。

## 技能结算核对

技能 `201`（客户端操作码 `203`）是敌方单体技能，基础伤害 `30`、智慧系数 `110`。
每次操作均即时重新汇总活动角色的已穿戴装备，并非进入战斗时缓存属性；但移除前的两次
汇总智慧都被截为 `999`。同样的智慧、武器攻击和怪物防御 `65` 得到相同的原始伤害和最终
伤害 `694`。

## 首个偏离与结论

首次错误判断是把 player-3 的角色错认为 `10036`、并据此读取了另一套鞋子
`40078`。更正为角色 `10762` 后，客户端显示和 `equip.dsh` 完全一致；真正决定伤害
不变的是数值上限，而不是装备同步、穿脱持久化、战斗快照或目标生命封顶。

## 主属性上限移除（2026-08-26）

用户已明确授权移除旧 mock 的主属性 `999` 截断。实现改为将基础属性与合法装备的
DSH 词条以 `u32` 饱和加法汇总：这只防止损坏资源导致无符号回绕，并不设玩法数值上限。
ActorInfo 的力量、敏捷、智慧基线和战斗内三种主属性增益也同步取消该截断，因此客户端
属性重建与服务端技能结算使用同一份完整数值。

初次修复仅移除了造成问题的主属性上限。用户随后明确要求**完全移除**派生战斗属性的
`9999` 保护边界；生命、法力、攻击、防御、命中、闪避、暴击和抗性现在均可保留超过
`9999` 的有效装备与战斗增益。属性汇总、强化词条累加、临时攻击/防御百分比增益、战斗内
直接增益及 ActorInfo 对应字段均使用完整 `u32` 值。

为避免损坏资源把正数回绕为更小的数值，所有相关加法和百分比计算改为 `u32` 饱和算术；
这不是新的玩法上限，而是协议字段本身可表示的最大值。目标当前生命的最终伤害限制、命中
和暴击概率规则、等级与强化等级规则均未改变。

新增离线回归 `battle-primary-stat-uncap-regression`，用同一套 70 级鬼道装备快照断言：
脱鞋智慧为 `1251`、穿鞋后为 `1272`，并且技能 `201/operate=203` 的原始伤害与高生命
目标的非暴击最终伤害都会提高。回归以本次怪物 `47` 已记录的防御 `65` 复算该最后一步，
不监听端口、不连接 MySQL，也不会接触 player-3 的存档。

本轮验证：`make -j2` 通过；随后执行 `make battle-primary-stat-uncap-regression` 与
`obj/server/battle-primary-stat-uncap-regression.exe`，输出为：

```text
primary-stat uncap regression passed wisdom=1251->1272 raw=1423->1446
damage=862->876 enemy_defense=65
```

另新增 `battle-derived-stat-uncap-regression`：用单件合法的合成装备提供每项 `10000`
加成，断言所有八项派生战斗属性、ActorInfo 的命中/防御/抗性字段和战斗内增益都不会在
`9999` 停止。该夹具同样不监听端口、不连接 MySQL，也不读取 player-3 的存档。

```text
derived-stat uncap regression passed hp=11155 mp=11825 atk=15253 def=10146
hit=30991 dodge=15249 crit=15643 resist=10000
```
