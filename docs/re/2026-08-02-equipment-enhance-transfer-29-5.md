# 装备强化转移 / 重铸（WT 29/5、29/6）

Date: 2026-08-02

Status: 已实现服务端转移规则；解包路径已验证

## 1. 触发与卡点

- 可见现象：强化转移确认后界面卡住；日志
  `unhandled wt=29/5 ... first=1/29/5:22`，随后通用
  `unimplemented-handler-notice`（`25/12+1/3/3`）不能清转移等待位。
- 根因：等待位在 `HandleItemUseAndEquip(0x010294AA)` 进入 `kind=29/subtype=5`
  分支时清零；必须回 `1/29/5`，不能只回聊天提示。

## 2. 请求契约

| 字段 | 含义 |
| --- | --- |
| `seqd` | 目标装备背包 seq（destination） |
| `seqs` | 当前/源装备背包 seq（source） |

- 发送器：`0x0101DB3A`，写入两个 tagged-u16；payload 22 字节。
- **`29/5`**：选中目标装备后的预览/打开确认（随后客户端展示扣金币界面）。
- **`29/6`**：确认转移（`0x0101E724` `movs r2,#6`）。
- 两类 subtype 共用同一 `seqd/seqs` 解析器。

## 3. 响应契约

### `29/5`（选装备 / 预览）

- 任意合法 `1/29/5` 对象先清等待（`0x010294CA..DA`）。
- `result=1`：再读 `flag`、`id`、`seq`、`name`、`money`(i16)、`level`(u8)，
  进入本地 UI（`0x010289E2`）——打开扣费确认。
  - `level == 1`：只显示「1.金钱：」（无材料/无目标装备）——不要发 1。
  - `level != 1`：材料 + 目标装备 +「2.金钱」。
  - **`level` 固定发 `0`**：走材料+目标装备 UI（`level==1` 会丢掉二者）。
  - `money`：**固定发 `7`**（产品）。「2.金钱」约 48金65银
    （标定：显示铜≈`27664+money×65536`；`7→48金65银`）。
    wire `money=7` 远小于角色铜钱，财力位可通过，确认走 `29/6`。
  - **`name`**：目标装备原名，**不**再追加 `(N金)`。
  - **不要**在 `29/5` 预览时另发 `1/3/3` tip。
  - **服务端此时不扣费、不改强化**。
- `result=2`：提示「装备不存在！」（仅真缺装备时使用）。
- 其它 result：等待已清，无本分支提示。

### `29/6`（确认）

- `result=1`：`seqs/curlevels` + `seqd/curleveld`，本地
  `0x010287C0` 写两侧强化，提示「转移成功」；服务端在此扣费并改库。
- `result=3/4/5`：没有对应玄晶 / 金钱不足 / 不可转移。

## 4. 服务端业务规则（产品确认）

1. 源、目标须为同类装备（`equip.dsh` slot 相同）。
2. 源、目标默认同品质（`equip.dsh` 品质相同）。跨品质须持有 **跨品重铸石(855)**，
   且仅在成功的 `29/6` 消耗 1 个；无石头仍 `result=5`（`quality-mismatch`）。
   详见 `docs/re/2026-09-25-cross-quality-recast-stone.md`。
3. 源强化等级 `L >= 1`，且目标当前强化 `< L`。
4. 成功后：源强化 → `0`；目标强化 → `L`（不降级）。
5. **仅在 `29/6` 确认成功时**固定扣 `48金65银`（`486500` 铜），与
   `29/5 money=7` 界面一致；与源强化等级无关。不足回 `result=4`。
   不得在 `29/5` 预览阶段做金钱检测（会堵死扣金币界面）。
6. 权威回写（仅确认成功）：源/目标各一份 `7/7 type=2` + `7/11`，金钱与
   `17/1(+7/42)` 只附一份；跨品质时顺带同步 855 余量；并 arm 背包列表 resync。
7. 幂等：`29/6` 若源已是 0 且目标已有强化，直接成功 ACK，不再改库、不扣费、不扣石。
