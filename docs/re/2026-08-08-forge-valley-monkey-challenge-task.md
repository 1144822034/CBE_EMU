# 铸剑谷“小猴子挑战”任务取证

## 目标

`00蓬莱仙岛_02.sce`（蓬莱-铸剑谷）中，角色从欧冶子领取“强化”后，挑战小猴子并获胜；获胜应推进任务，随后由任务定义的交付 NPC 提交。

## 固定现状

2026-08-08 对本地 `jh_online` 的只读检查得到：

- `server_tasks.task_id=100000` 的名称为“强化”，发布者/交付者均为欧冶子；目标文案为“挑战小猴子,获得玄晶碎片”。
- 但该任务的实际条件是 `requirement_type1=1`、`requirement_id1=900`、`requirement_count1=1`，即收集物品 900，而不是击败怪物。
- 此任务绑定在 `server_dynamic_npc_tasks` 的 `00蓬莱仙岛_02.sce / actor_id=20020`（欧冶子）。
- 小猴子为同场景 `actor_id=20021`、资源 `e_monkey.actor` 的服务端内置 NPC；当前覆盖行为是普通 NPC，未绑定挑战服务。

因此，任务文案与权威完成条件的第一次偏离发生在任务定义，而不是任务提交或战斗结算。

## 已验证的协议链

1. 任务的击杀条件必须使用 `requirement_type=2`，其目标 ID 是**战斗怪物 ID**。战斗胜利后 `vm_net_mock_task_progress_after_battle()` 仅以该 ID 推进已接取任务。
2. 小猴子的 `20021` 是场景 Actor ID，不是可直接填入任务击杀条件的战斗怪物 ID。
3. 动态 NPC 可同时拥有任务绑定和“副本传送与挑战”服务；后者的 `challenge_enemy_id` 必须是服务端怪物目录中的已知战斗怪物 ID。
4. 挑战确认使用 `26/1(action 13)` -> `26/0 + 30/9` -> `30/10` -> `4/10`。`mmBattleMstarWqvga.cbm:HandleBattleStartMsg(0x66CC)` 的 `4/10` 分支按怪物 ID 在客户端战斗模板表中查找外观。
5. `江湖OL.CBE:scene_parse_npcinfo_and_spawn_npcs(0x01037998)` 将 `npcinfo` 生成的场景 NPC 节点标为类型 `1`。`mmBattleMstarWqvga.cbm:HandleBattleStartMsg(0x66CC)` 的场景战斗 `4/5` 分支只匹配类型 `2` 的场景怪物节点。故不能将小猴子 NPC Actor `20021` 伪装为 `4/5` 场景怪物。

## 资源核查

- `e_monkey.actor` 及其 `houzi1.gif` 存在，能够作为场景 NPC 显示。
- 后台现有“怪物目录”有意只列举 `automonster.dsh ∪ task.dsh(type=2)` 中已经有
  原生战斗身份的怪物；`e_monkey.actor` 不在其中。因此“小猴子”不是被页面筛选漏掉，
  而是尚未成为可战斗实体。
- 对全部现有 `.sce` 的战斗生成记录扫描也未找到 `e_monkey.actor`。但该 Actor 自身有两组
  动画记录，和现有场景怪 `e_mucusP.actor` 的最小动画结构一致；这是“可作为场景怪模型”
  的正面线索，尚不是已经验证过攻击、受击和死亡生命周期的结论。
- `4/10` 只能按客户端已有的战斗模板 ID 取外观，不能携带任意 Actor 资源。把 `20021`
  加入服务端怪物目录，或把它填进 `challenge_enemy_id`，都不会让 `4/10` 取得小猴子模型，
  反而会走缺失模板路径。

## 正确的配置契约

在现有客户端资源下，功能正确的任务需要以下一致配置：

| 数据 | 必须值 |
| --- | --- |
| 任务 `100000` | 至少一个条件为 `类型=2（击败怪物）`、`数量=1`、`目标 ID=E` |
| 欧冶子 (`20020`) | 继续绑定任务 `100000`，用于接取和提交 |
| 小猴子 NPC (`20021`) | 保持对话/提示用途；它不是战斗目标 ID，也不承担战斗启动 |
| 小猴子场景怪 | SCE2 中新增独立的 kind=3 战斗生成点，使用一个未冲突的战斗怪 ID `E`、`e_monkey.actor` 和真实场景坐标；触碰此节点走正常 `4/1 → 4/5` |

其中 `E` 是新的**战斗怪物 ID**，不能复用 NPC Actor ID `20021`。`4/5` 不从下行包
读取小猴子外观：客户端会按 `scene_monster_index/x/y` 在当前场景的 type-2 节点中复制
怪物 ID、名称、生命值和精灵。因此只有真实 SCE2 战斗生成点，才能把任务目标、场景外观
和战斗结算统一到同一个实体。胜利会由正常战斗结算推进任务；未接取任务的玩家即使战胜它，
也不会获得任务进度。

## 尚未可配置的部分

要实现这个任务，下一步需要先在隔离客户端上验证一条最小的 SCE2 kind=3 小猴子生成点：
它必须能够创建 type-2 场景节点、由 `4/5` 正确带入战斗，并完整播放攻击、受击、死亡及
退场。验证通过后才可写入正式铸剑谷场景和后台的“场景战斗怪”管理项。

此外，现有 WT18/7 具名资源通道只会在客户端**缺少**资源时下载，不能证明可覆盖客户端
已缓存的核心 `.sce`。所以正式发布前还需要一个经过取证的核心场景版本/缓存更新协议；
在该协议恢复前，应把更新后的 `00蓬莱仙岛_02.sce` 随客户端资源包发放，不能假设服务器
替换同名文件会即时更新已有客户端。

在该资源契约完成前，不应把 `20021` 写入 `challenge_enemy_id` 或任务的击杀目标。
