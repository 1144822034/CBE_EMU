# 动态 NPC 副本传送：进入费用（铜钱）

## 目标

“游戏内容管理”中的动态 NPC 勾选“副本传送”后，可以配置每次进入的铜钱费用。
`0` 表示免费；正数以角色持久化 `money` 的最小单位“铜”为准。该金额不适用于守关怪挑战，
也不使用 W 币钱包。

## 已有客户端契约

动态副本向导的选项由既有的 NPC 对话请求解析。用户选择“进入副本”后，服务端在
`vm_net_mock_build_instance_enter_response()` 中返回已经验证的
`WT 1/30/1 { scene, posinfo }`。客户端按 `JianghuOL.CBE:0x01039B8A`
和 `0x010396D6` 的既有场景进入路径继续发出 `2/3`、资源请求和 `6/1`；不能为了刷新铜钱
在这个响应中拼接未请求的 actor-info 或宿主事件。

因此费用校验与扣款归入同一已确认的“进入副本”请求边界，而不是在显示对话、打开菜单、
进入场景后，或客户端本地计时器处执行。

## 数据与后台

`server_dynamic_npc_instances.entry_copper_cost INT UNSIGNED NOT NULL DEFAULT 0`
是副本传送的配置来源。启动时会自动为既有表增加该列；动态 NPC 的父场景键迁移、载入查询
及管理页保存事务都携带它。后台仅在服务 6“副本传送”启用时显示和接受
`instance_entry_copper_cost`；没有传送服务的 NPC 不能保存非零费用。

管理页面将字段显示为“进入费用（铜钱）”，范围为 `0` 至 `4294967295`。客户端菜单中，
非零费用会追加为“入场费用：N铜”，使玩家在确认前可见。

## 服务端行为

`vm_net_mock_instance_entry_copper_prepare_debit()` 先只读检查活动角色的 `money`：

- 费用为 `0`：保留原免费进入路径；
- 余额等于或大于费用：计算扣减后的余额，但尚不写入；
- 余额不足：不构造 `30/1`，不建立临时副本会话，不扣款；现有 NPC 对话路径返回“铜钱不足”；
- 付费进入还必须已有当前客户端的角色会话和可持久化的源场景锚点，避免无会话的测试构造器
  产生扣款。

场景进入对象成功构造后才会更新 `role->money` 并调用
`vm_net_mock_role_db_save("npc-instance-entry-copper")`。持久化失败时立即恢复内存余额、
不建立场景目标或副本会话、并沿原 NPC 对话路径返回失败文本。持久化成功后才登记普通的
`30/1` scene target 与临时副本会话。因此每一条成功的进入确认只扣一次；重开对话并再次确认
进入属于新的进入行为，会重新校验并扣除一次。

成功、余额不足、会话未绑定和持久化回滚都记录带 `actor`、`role`、费用与余额的服务端日志。
客户端主界面的余额不在 `30/1` 中被强行改写；后续正常角色信息刷新会读取同一个已持久化余额。

## 验证

`make -j2` 在 2026-09-01 通过。隔离回归
`fb-target-timer-field-regression` 不启动监听器、数据库或客户端，直接调用生产的费用准备函数，
验证：免费进入保留余额；余额刚好等于费用可通过且准备阶段不提前修改余额；余额少一铜时拒绝且
余额不变。原有副本计时与到期返回断言也在同一运行中继续通过。

仍需在本地服务重启后以 player-3 做人工体验验收：将某个动态 NPC 的副本传送费用设为一个
小额铜钱数，分别用余额充足和不足的角色选择进入，确认前者切图并扣款、后者停留在对话且不扣款；
重复成功进入时应按次数扣款。
