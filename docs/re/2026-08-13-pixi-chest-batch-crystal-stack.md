# Pixi 十连开箱：提示开到多颗玄晶但背包只有 1

日期：2026-08-13（同日补：tip / 世界祝贺数量对齐）

## 触发与现象

背包「批量开启」十连后，连开 tip / 世界祝贺出现 **2 次**「十四级玄晶」（或 tip 里两段「获得1个十四级玄晶」），打开背包同级玄晶数量仍为 **1**。

## 业务链路

1. Pixi `openChestBatch` 循环最多 10 次，每次独立发 `1/7/15`（服务端无十连协议）。
2. 服务端 `vm_net_mock_build_chest_open_response`：扣箱/钥 → `add_backpack` 按 `itemId` 堆叠 → 回 `7/15`，`iteminfo.count` 固定为本次发放增量 `1`（不得写合并后总量）。
3. CBE `0x010261EC` 成功后：`0x01023850` 自扣箱/钥；`0x01019228` 把 `iteminfo` 的 count **累加**进本地背包。成功包不得附带通用 `7/7`。
4. Pixi 旧逻辑：只解析 tip，不入包；十连结束后再 `openBag()`（`1/7/23`→`17/1`+`30/21`）拉权威。
5. 其它路径的 `7/7 type=1`（购买/取回/掉落）契约是 **增量**；Pixi `handleBodies` 旧实现按 seq **整行覆盖** count。
6. 稀有奖励世界祝贺：每次 `7/15` 成功各塞一条 `[世]`，十连同物会刷多条「获得十四级玄晶」，与 tip「获得2个」不一致。

## 首次偏离

1. **开箱成功未走 CBE 本地入包**：十连过程中本地背包不扣箱/钥、不加奖励；tip 已按每次 `获得1个…` 累计，背包行仍停留在开箱前（或仅被错误 peel 写成 1）。
2. **`7/7 type=1` 用绝对值覆盖**：若同 seq 可堆叠物先有 N，再来增量 1，客户端变成 1。
3. **tip 与世界祝贺口径分裂**：本地已汇总 N 个，世界仍按次广播 1 个×N。

## 根因

- Pixi 十连未实现 CBE 对 `iteminfo` 的 **ADD** 入包与自扣箱/钥。
- `parseBagItemUpdates` 把 type=1 wire count 当成剩余量 SET。
- 世界祝贺无短时合并，十连同稀有物产生多条 `[世]`。

## 修改

| 文件 | 内容 |
| --- | --- |
| `protocolExtras.ts` | `applyChestOpenToBag`；`mergeBagItemUpdateDeltas`（可堆叠 type=1 ADD） |
| `GameSession.ts` | 开箱本地入包；十连结束后 `openBag`，**tip 按背包增量**「获得N个」 |
| `mock_server_equipment_npc.c` | 稀有祝贺 500ms 合并同箱同物；文案「获得N个{物}」 |
| `mock_server_catalog.c` / `social.c` | 传入 `chestItemId`；poll 到期 flush |

## 验证

1. 十连两次 914：本地 tip「获得2个十四级玄晶」；背包 `X2`；世界祝贺 **一条**「获得2个十四级玄晶」。
2. 已有 914×1 再抽到 1：tip/背包增量 +1。
3. 单次开箱稀有：一条「获得1个…」（约 0.5s 后 poll）。
4. 可堆叠 peel 回归：原有+增量，勿 SET 覆盖。

## 补充取证（同日）：7 条都写「十二级玄晶」、背包只有 2

### 现象

十连后世界频道 **7 条**祝贺文案均含「十二级玄晶」；打开背包该物仅 **X2**。排除「7 次稀有里只有 2 次是十二级、其余是紫装/别级玄晶」假说。

### 契约对照

| 通道 | 线上 HEAD 行为 | 本次计数 |
| --- | --- | --- |
| 世界祝贺 | 每次 `7/15` 成功且 reward 达稀有门槛 → **立刻** `1/3/3` 一条（无合并） | 7 |
| 背包权威 | `add_backpack` 按 `itemId` 堆叠后的 `count`；Pixi 结束再 `openBag` | 2 |

世界祝贺在 `add_backpack` 成功且 `7/15` 编码成功之后触发；名称来自 shop 目录（912 → 十二级玄晶）。因此 **7 条同文案 ≈ 7 次「成功开出并广播十二级」事件**，与背包最终 2 **不是同一数量口径**。

### 首次偏离（相对「应发 7 个」）

1. **广播按开箱事件，不按十连结束后的背包增量**（线上仍按次；工作区 coalesce 未部署到 live 时仍会刷 7 条）。
2. **背包最终只有 2**：要么服务端 7 次入包后存量被压回 2（需 `mock_chest_open reward=912 bag_after=` 日志），要么客户端 `openBag`/展示未反映服务端存量。二者不能再用「播了别的稀有」解释。

### 仍需日志裁定

对同一次十连抓服务端：

`mock_chest_open ... reward=912 granted=1 bag_after=N`

- 若 `bag_after` 升到 7 而客户端仍 X2 → 客户端展示/解析。
- 若 `bag_after` 最终停在 2 → 服务端入包/会话覆盖/回滚。
