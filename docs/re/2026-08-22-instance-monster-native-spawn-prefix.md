# 副本场景战斗怪缺少原生生成区前导（2026-08-22）

## 触发与首个偏离

触发步骤是：在后台为 `测试地图.sce` 配置并部署场景战斗怪，客户端完整退出后重新进入
副本。WT18 已下载并安装场景与 Actor 资源，场景可以进入，但指定怪物没有出现在静态场景
节点中。

服务端日志曾显示 `scene_battle_monster_deploy ... nodes=0->1`，而已发布资源的解压 payload
在 NPC 数据后直接出现 kind-3 记录，尾部为 `00 00`。这能被服务端的逐字节 kind-3 扫描器
识别，却不等于客户端走过原生静态战斗怪区域的解析分支。

## 桃花岛对照证据

`bin/JHOnlineData/01桃花岛_01.sce` 是同客户端中可正常生成毒泥怪的权威样本：

- 怪物 ID `105`，主 Actor `e_mucusP.actor`；
- field18 效果 Actor `e_ghostfireR.actor`；
- 四个生成点为 `(295,57)`、`(179,120)`、`(146,349)`、`(292,484)`；
- 首个 kind-3 前的原生字节为
  `kind=8,x=70,y=38,scalar(field=1,value=38),00 00,kind=3`；
- 最后一个怪物的 field18 Actor 结束于 EOF，怪物记录后没有另一个零字终止项。

`测试地图.sce` 引用相同的 `01桃花岛_01.map`，但旧发布资源没有上述 kind-8/零字前导。
这是本轮确认的最早契约偏离。怪物 ID `1001` 与 Actor `e_batB.actor` 是否符合期望外观是
后续配置语义，不会解释客户端完全没有建立 kind-3 节点。

## 根因与修复

旧部署器只寻找场景尾部并追加 kind-3，把裸 `00 00` 当作怪物后的终止项；它没有证明
输出包含客户端原生的战斗怪区域前导。因此服务端自检与节点计数可以通过，而客户端不会
按桃花岛相同路径创建战斗怪节点。

`src/server/mock_server_scene_task.c` 现执行以下约束：

1. 已有 `kind=8,x,y,1,1,38,0` 尾部控制项时，将其作为战斗区前导移动到新增 kind-3 前；
2. 自定义场景没有 marker 时，按其 `.map` 名从不可变基础 SCE 中查找真实的
   `marker -> 00 00 -> kind-3` 样本并复制 marker；找不到时明确拒绝部署，不从怪物坐标
   猜测 marker；
3. 输出顺序固定为 `marker -> 00 00 -> kind-3... -> EOF`；
4. 发布后与“已部署”状态检查都要求启用怪物实际位于该原生前导之后。旧的裸 kind-3
   发布会显示为未部署，必须由管理员重新部署。

## 验证

- `make -j2`：通过；
- `scripts/scene-battle-monster-field18-regression.c`：通过；
- 回归覆盖完整 field18、kind-8/零字/kind-3 顺序、裸 kind-3 拒绝以及
  `01桃花岛_01.map` 的原生 `(70,38,field1=38)` marker 恢复；
- 回归只读取仓库资源，不连接 MySQL、不启动监听、不修改客户端内存。

尚未对用户正在使用的数据库和客户端执行部署写入。更新服务端后，需要在后台对目标场景
再次执行“部署场景战斗怪”，让 WT18 发布新 SCE；随后客户端完整退出并重新进入以安装该
内容版本。运行时成功证据应是新增 actor ID 的 scene entity callback/type-2 节点，而不只是
服务端离线扫描到 kind-3。
