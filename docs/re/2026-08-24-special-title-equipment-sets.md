# 圣诞骑士与武林传奇：全套装备称号

状态：已实现，待部署。

## 规则与证据

`equip.dsh` 是服务端装备目录的权威来源。只读解析的记录表明，两套装备都覆盖八个
已穿戴槽位：武器、头盔、铠甲、披风、腰带、护腿、靴子和戒指。

- 圣诞装：武器 `40020/40021/40022` 三选一，其他槽位依次为
  `40025,40023,40028,40027,40024,40026,40029`。
- 武林装：武器 `40150/40151/40152` 三选一，其他槽位依次为
  `40155,40153,40158,40157,40154,40156,40159`。

三种武器分别属于剑、匕首、魔杖职业槽位；因此任一种可用的同系列武器都满足武器槽。
其余七槽必须与该系列精确匹配。背包中拥有装备不算，错误槽位或角色等级不足导致的不可用
装备也不算；耐久归零的装备仍是已穿戴实例，故不额外要求耐久大于零。

## 服务端与后台契约

- 称号 ID 33「圣诞骑士」固定为 `condition_kind=3,value=1`。
- 称号 ID 34「武林传奇」固定为 `condition_kind=3,value=2`。
- 称号列表和选择确认沿用现有 `WT 23/1`、`23/3`、`23/2` 协议；只改变服务端是否将
  该称号列为已解锁，未伪造客户端状态或修改客户端内存。
- 后台称号管理显示固定的全套装备条件，只能调整启用状态。服务加载配置时会校正旧的
  等级占位条件，数据库迁移脚本提供部署前的显式更新。

## 验证边界

专用回归覆盖一套齐全、缺少一槽、混入另一套物品和背包持有但未穿戴的情况，并确认两个
称号的解锁判断互不串用。构建后仍需在隔离账号穿齐八槽、打开称号页，确认客户端通过既有
`23/1` 列表显示该称号；脱下一槽后再次打开页面应不再解锁。
