# 后台任务目标列表

## 目标

任务编辑页不再固定展示“条件一／条件二”。任务目标改为列表：未配置目标时只显示
空状态和“新增任务目标”按钮；新增后显示一条可配置、可移除的目标。

## 协议边界

任务定义协议仍只有两个目标槽位（`requirement_type/id/count/scene` 的 1、2 后缀），
因此列表最多添加两条。删除条目会把对应槽位的类型、目标 ID、数量、场景限制都清零，
而不是只在界面隐藏，保存请求保持原有字段名和数量。

每一条目标把可选 SCE 场景限制放在同一行：收集物品保留物品目录选择，击败怪物使用
怪物搜索选择器。目标类型切回“无”会等同移除该条目。

收集物品的 `requirement_id*` 仍作为隐藏提交值保留，但不再显示可手输的数值框；
操作界面只展示“从物品目录选择”入口。

## 验证

`scripts/admin-task-target-list-regression.c` 验证空槽位、怪物目标槽位、场景字段、
移除入口及前端列表控制器的契约。测试不启动 HTTP 服务，也不读取或修改数据库。
