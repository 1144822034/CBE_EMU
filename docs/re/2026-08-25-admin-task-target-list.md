# 后台任务目标列表

## 目标

任务编辑页不再固定展示“条件一／条件二”。任务目标改为列表：未配置目标时只显示
空状态和“新增任务目标”按钮；新增后显示一条可配置、可移除的目标。

## 协议边界

任务定义协议仍只有两个目标槽位（`requirement_type/id/count/scene` 的 1、2 后缀），
因此列表最多添加两条。删除条目会把对应槽位的类型、目标 ID、数量、场景限制都清零，
而不是只在界面隐藏，保存请求保持原有字段名和数量。

每一条目标把可选 SCE 场景限制放在同一行：收集物品保留物品目录选择，击败怪物使用
怪物搜索选择器。目标类型切回“无”会等同移除该条目。

收集物品的 `requirement_id*` 仍作为隐藏提交值保留，但不再显示可手输的数值框；
操作界面只展示“从物品目录选择”入口。

## 验证

`scripts/admin-task-target-list-regression.c` 验证空槽位、怪物目标槽位、场景字段、
移除入口、前端列表控制器，以及同一任务页局部切换后的重新绑定契约。测试不启动 HTTP
服务，也不读取或修改数据库。

## 2026-08-27：编辑任务的新增按钮未绑定

任务目录内切换任务时，`setupPartialNavigation()` 只替换编辑区 HTML，随后重新初始化了
物品、怪物和奖励控件，却漏掉 `setupTaskRequirementTargets()`。首次整页加载正常执行该
初始化，因此问题只出现在局部切换后：新的“新增任务目标”按钮没有点击监听器，点击看似
无反应。

修复在局部替换后、怪物选择器初始化完成后调用该列表初始化。初始化本身以
`data-task-requirement-list-bound` 防止对仍在页面中的旧控件重复绑定；新编辑区没有此标记，
所以会绑定新按钮。回归检查该调用位于局部导航的初始化序列中。
