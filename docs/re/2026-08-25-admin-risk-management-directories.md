# 后台风险管理目录：风险角色、风险 IP 与后台账号风险（2026-08-25）

## 目标

原“风险角色管理”只展示三秒内连续进入战斗的角色审计。登录来源 IP 的自动封锁已
持久化在 `server_login_ip_blocks`，但运营人员无法在同一风险入口核对已封锁地址。

本次将顶级入口改名为“风险管理”，并提供三个目录：

- `风险角色`：原有快速战斗审计、分页和账号封号操作。
- `风险 IP`：已封锁来源 IP、累计失败次数、封锁时间和最近更新时间，并可逐条清除封锁。
- `后台账号风险`：后台登录连续错误 5 次而封锁的来源 IP，以及触发封锁时提交的后台账号。

目录参数为 `risk_kind=roles`、`risk_kind=ips` 或 `risk_kind=admin-accounts`；旧的
`?tab=risk` 继续默认打开风险角色，保持已有链接兼容。

## 数据与安全边界

风险 IP 从权威表 `server_login_ip_blocks` 读取 `blocked=1` 的记录，并按封锁时间倒序
分页。页面先通过既有 `vm_mock_service_login_ip_schema_ensure()` 保证部署表存在。

清除操作仅接受严格校验的 IPv4 地址。服务端在登录封锁缓存互斥锁内再次确认该地址仍被
封锁，随后删除 `blocked=1` 的权威记录并移除当前进程的缓存项；因此封锁和失败次数会一
并清空，之后的凭据失败从第 1 次重新计数。页面已过期、该地址不再处于封锁状态或数据库
操作失败时，不会写入操作日志并会明确返回失败提示。

游戏和用户中心的连续 15 次凭据失败来源 IP 自动封锁契约保持不变。后台登录另有独立的
连续 5 次失败来源 IP 封锁，记录在 `server_admin_login_ip_blocks`，只拒绝后台登录而不影响
同一 IP 的游戏或用户中心路径。清除风险 IP 后同一服务进程立即允许该 IP 再次进入相应的
共享登录认证流程。
每次成功清除会以 `clear-risk-ip` 写入 `server_admin_operation_logs`，记录后台操作者、
来源 IP 和已重置失败计数。

风险角色目录保留原有账号封号操作。封号后的重定向明确返回
`risk_kind=roles`，不会跳到风险 IP 目录。

## 验证

`scripts/risk-admin-pagination-regression.c` 覆盖：

- 三个目录链接、选中状态及“风险管理”改名；
- 风险角色的既有分页、异常页码回退和封号表单页码；
- 风险 IP 的查询字段、分页 SQL、清除确认表单与页面渲染；
- 后台账号风险的查询字段、5 次阈值与页面渲染；
- 清除动作的缓存移除、非法 IP 拒绝与操作日志类型。
