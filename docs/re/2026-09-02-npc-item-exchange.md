# 可配置 NPC 物品兑换（2026-09-02）

## 目标和范围

新增 NPC 服务 `12：物品兑换`。管理员在原生 NPC 覆盖或动态 NPC 的“可同时提供的对话功能”勾选它时，编辑页立即显示“物品兑换配方”的配置提示；保存服务选择后，同一位置显示可新增、编辑、删除的多条规则。每条已保存规则以单行展示：物品 A 选择、消耗数量、物品 B 选择、获得数量、保存和删除。物品 A、B 复用后台统一的可搜索物品选择弹窗，不再要求手动输入 ID。每条规则为：消耗 `物品 A × 数量`，获得 `物品 B × 数量`。输入和输出物品必须是不同的已知物品，所有数量为 `1..1,000,000`。

配方按精确 `(scene, actor_id, recipe_id)` 保存在 `server_npc_item_exchange_recipes`；`recipe_id` 是服务端分配的稳定正整数，不是客户端可提交的物品 ID 或数量。旧的单条 `server_npc_item_exchange_configs` 在首次加载时仅迁移一次为 `recipe_id=1`，迁移记录保存在 `server_npc_item_exchange_migrations`，因此管理员之后删除或修改配方不会在下次启动时被旧数据覆盖。删除动态 NPC 或动态 NPC 的场景键迁移时，会同步删除或迁移全部配方，避免 Actor ID 复用或场景键规范化造成遗留规则。

单个 NPC 最多可保存 `128` 条规则。客户端每页显示 `8` 条并提供翻页，保证对话选项不超过客户端已验证的 `10` 条上限。

## 客户端协议与确认边界

客户端已验证的 `ParseNPCDialogData` / action=1 路径使用 `WT 26/1`、对象 `1/26/1`、字段 `{type=2,id=u32}`；既有运行记录将其定位到 `JianghuOL.CBE:0x010492B0` 与 `0x010380E8`。本实现使用 `0xfb000000 | page` 打开规则列表、`0xfc000000 | recipe_id` 选择一条已配置规则；两者仍由该已有 parser 消费。低 24 位只承载页号或服务端配方编号，绝不编码物品 ID 或数量。兑换列表、确认、成功和失败提示均使用客户端字符串槽所需的 GBK 中文文本；没有增加客户端字段、CBM/CBE 修改或宿主侧回调。

首次选择只构造“确认兑换／取消”对话，并将 `recipe_id`、输入物品、输入数量、输出物品、输出数量、角色、NPC、场景和该次实际展示的服务掩码写入一次性会话上下文。确认读取即清除上下文；跨角色、跨 NPC、跨场景、重复确认，或配置/配方编号在确认前被改变，都会拒绝且不改背包。取消回到规则列表。

确认时重新读取 `(scene, actor)` 配方并检查材料。服务端在同一角色快照中先扣除输入物品、再加入输出物品；任一步失败会恢复完整快照。持久化成功后响应严格为：

```text
1/26/1  完成确认对话
1/7/11  输入物品按序列更新（或数量 0 删除）
1/7/15  输出物品的获得增量
1/7/11  输出物品按序列的最终总数量
```

`7/11` 与 `7/15` 的顺序复用已有玄晶合成的真实客户端证据：`JianghuOL.CBE:0x01033544` 消费序列更新/删除，`HandleShopBuyItem(0x01025AE6)` 处理获得增量；末尾 `7/11` 使已存在的输出堆叠也立即刷新，而不是等待并不一定会出现的背包查询。

## 验证

- `make npc-item-exchange-regression`：通过。
- `obj/server/npc-item-exchange-regression.exe`：通过。隔离夹具不启动 listener、不连接数据库或客户端；断言确认上下文携带配方编号并一次性消费，`900×3 → 901×2` 成功后输入为 `6`、输出为 `2`，材料不足时角色完整快照不变。
- `make -j2`：通过，客户端与服务端均已重新链接。
- `make admin-route-prefix-regression` 和
  `obj/server/admin-route-prefix-regression.exe`：通过。隔离夹具同时断言
  `/action` 与已带前缀的 `/admin-418yz6/action` 都只会得到一个管理前缀，且
  新增、删除兑换配方都会分派至 NPC 配置处理器，不会落入账号操作处理器。

人工验收：勾选“物品兑换”并观察保存提示是否即时出现；保存后新增至少两条规则，确认后台都保留；客户端进入服务、选择不同配方、取消一次确认、再确认一次，并核对输入和输出两项背包数量立即变化。

后台内容页的表单源码使用 `/action`，由
`vm_mock_admin_prefix_page_routes` 统一改写为
`/admin-418yz6/action`。该改写现在具备幂等性：已带管理前缀的链接、表单
和资源地址会原样保留，不会再形成
`/admin-418yz6/admin-418yz6/action`。

`save-npc-item-exchange` 和 `delete-npc-item-exchange` 必须先在后台 action
分派层归入 NPC 配置处理器。账号操作也有独立白名单；不属于任何已处理类别的
action 会明确返回“不支持的管理操作”，不得再以缺少 `account` 参数为由落入账号
管理区。该分派和未知操作拒绝均由同一隔离回归覆盖。
