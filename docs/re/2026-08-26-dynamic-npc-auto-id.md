# SCE 管理新增动态 NPC 的自动 Actor ID

## 问题与边界

SCE 管理页原先把新增动态 NPC 的 `actor_id` 固定预填为 `30000`，管理员若未修改该值，保存会命中同场景已有动态 NPC 的主键并把它覆盖。

SCE 原生交互 NPC 的稳定派生 Actor ID 已明确使用 `20000..59999`；新增动态 NPC 因此从 `60000` 起分配。分配时同时取 `server_dynamic_npcs.actor_id` 与 `server_scene_battle_monsters.monster_id` 的已用最大值，避免动态 NPC 与已配置的场景战斗节点复用客户端场景身份。

## 保存契约

- “增加动态 NPC”表单不再提交可编辑的 `actor_id`，而是提交 `create_npc=1`。
- 服务端在所有表单与资源校验通过后分配下一未使用 ID，并在成功提示中显示该 ID。
- 新增使用普通 `INSERT`，不使用更新语句；两个并发新增若恰好竞争同一个 ID，后到请求会失败并提示重试，绝不覆盖已有 NPC。
- 已存在 NPC 的编辑、停用、删除和库存操作仍按其固定 Actor ID 工作，不改变原有资源、WT 27/11 NPC 投递或服务选项契约。

## 回归

`admin-dynamic-npc-id-regression` 在不连接业务数据库的前提下验证：

- 自动编号从 `60000` 开始并顺序递增；
- 编号上限拒绝分配；
- 新增表单只显示“保存后自动分配”，并提交创建标记。
