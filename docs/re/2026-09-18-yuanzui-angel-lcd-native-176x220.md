# 2026-09-18 原罪天使渲染花屏（176×220 帧未裁剪）

## 现象

启动器进入 `CBE/原罪天使(大型RPG)V100.CBE` 后：

- 窗口仍按江湖 OL 的 `240×400×2 = 480×832` 建窗
- 游戏内容挤在上半部；右侧约 1/4 为彩色雪花（花屏）
- 底栏「菜单 / 500 / 20 / 商店」与对话文字相对正常
- 日志：`is_big_endian 1`，`native_size=240x400 source=default`

## 证据

对用户截图（480×832）列密度：

| 区间（窗口 x） | 对应 guest 列（÷2） | 观察 |
|----------------|---------------------|------|
| 0..351 | 0..175 | 场景+UI 密度高 |
| 352..479 | 176..239 | 稀疏彩点/黑，即花屏带 |
| 内容底边 y≈469 | 高度≈438 ≈ 220×2 | 与 176×220 设计帧一致 |

与封神演义同一分辨率契约：只画 **176×220**，宿主却 present 整块 240×400。

## 根因

首次偏离在 **分辨率/present 契约**：BE 标题按经典 MTK `176×220` 出画，宿主默认 `240×400` 缓冲把未写入列当像素显示 → 右侧花屏 + 大块黑边。

## 修改

| 位置 | 改动 |
|------|------|
| `src/main.c` `vm_lcd_apply_native_size_for_cbe_path` | 路径匹配「原罪」+「天使」/ `SinAngel` → `native=176x220`、`scale=3` |

画面区期望 `528×660`（与封神相同），右侧花屏列不再进入 present。

## 验证

```text
cd bin
main.exe --cbe="CBE/原罪天使(大型RPG)V100.CBE" --no-launcher
```

期望日志：

```text
native_size=176x220 source=yuanzui-angel-176x220 scale=3
game_frame_blit ... native=176x220 ... surface=528x692 dst=(0,32 528x660)
```

## unresolved

若裁剪后左侧场景仍有明显横纹雪花，再查 guest 自绘 pitch（struct 宽 176）与宿主 `DrawImage` 强制 `LCD_WIDTH` pitch 240 是否混用。
