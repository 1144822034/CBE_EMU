# 场景挂机：奖励面板后自动续战（已废弃）

> **状态：已被 2026-08-09 的真实运行时证据推翻，不再作为实现依据。**
>
> 请参见[场景挂机：最后一只怪死亡后提前重入战斗](2026-08-09-scene-hangup-final-monster-reentry.md)。

本记录曾假设：在最后攻击动画播放边界后，服务端可直接下发
`2/2 + 4/5 + 4/11`，使奖励面板无需客户端 `25/5` 即进入下一场挂机战斗。

后续三怪挂机复现显示该假设错误：服务端记录
`mock_scene_hangup_auto_continue_deliver ... response=2/2+4/5+4/11-after-4/7`
时，旧战斗尚未发送 `25/5` 或完成 `BattleScene_ExitAndCleanup(0x60C8)`，客户端因此
将新 battleinfo 重入旧 BattleScreen，表现为重新刷怪后卡住。

有效契约是：`4/7` 奖励面板由客户端关闭，`BattleScene_ExitAndCleanup(0x60C8)` 再发送
空 `25/5`；服务端收到该确认后标记场景挂机续战，并在后续 scene poll 发送下一场
`2/2 + 4/5 + 4/11`。在没有新的客户端协议证据前，禁止在 `25/5` 之前发送新的 `4/5`。
