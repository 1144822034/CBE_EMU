# 怪物等级曲线与首领组队难度

## 触发与首次偏离

怪物默认属性此前只按怪物种类和等级作早期 mock 线性计算。例如 60 级首领为
`HP=800 / 攻击=194 / 防御=38`。同等级、无装备的最低战斗职业（术士）已具有
`HP=1005 / 攻击=218 / 防御=126`；因此首领的防御低于普通角色的裸装防御，HP 只够
数次普通攻击。

首次错误状态发生在服务端的默认怪物数值层：首领没有与角色成长对齐。客户端 `mmBattle`
只消费服务端给出的 HP、MP 与动作结果，不能自行建立首领难度；正确的服务端方案是提高
权威属性，使队伍协作成为胜利条件，而不是拒绝有效的单人挑战请求。

## 已确认契约

- 场景怪物触碰请求：`WT 1/4/1`，稳定字段为 `id/index/posx/posy`。
- 成功的场景战斗：`1/2/2` 为被触碰节点写入 HP/MP，随后 `1/4/5` 开始战斗。
- 同场景队伍战斗：队长的 `4/1` 被接受时，服务端冻结至少两名可见队员；每个客户端
  经其下一次 scene poll 接收观察者对应的 `1/4/5`。这一路径已有
  [2026-06-25-battle-server-flow.md](2026-06-25-battle-server-flow.md) 的运行时证据。
- 不能开战的已验证安全路径为 `1/2/10` 空对象加 `1/25/11` 信息提示；死亡角色拒绝
  已在该路径上由客户端正常清除交互等待层。

## 数值模型

这不是恢复出的原官服公式，而是明确标注的**服务端平衡设计**。它从现有、且部分由
客户端 `scene_apply_levelup_status_growth(0x01017F1C)` 证实的角色成长构造三个无装备
职业，取同等级的最低 HP、攻击和防御作为下限基准：

| 等级 | 最低 HP | 最低攻击 | 最低防御 |
| ---: | ---: | ---: | ---: |
| 1 | 120 | 11 | 8 |
| 10 | 255 | 43 | 26 |
| 20 | 405 | 78 | 46 |
| 40 | 705 | 148 | 86 |
| 60 | 1005 | 218 | 126 |
| 70 | 1155 | 253 | 146 |

普通怪的基础值为：

```text
HP      = 最低攻击 × 5
攻击    = ceil(最低HP × (100 + 最低防御) / 1600)
防御    = 最低攻击 × 30%
MP      = 8 + 等级 × 3
```

种类再使用固定倍率：飞行/昆虫偏敏捷，亡灵/岩石偏耐久，元素偏攻击，士兵偏防御。
这使同等级普通怪在无装备最低攻击角色面前约需数次攻击击杀；多怪战斗仍会因多个反击
而有风险。教程毒泥怪 `105` 同样使用史莱姆的等级曲线，不再保留旧 mock 属性例外。

所有除法向上取整，避免低等级怪因整数截断得到零属性。具体倍率如下（顺序为
`HP / MP / 攻击 / 防御`，基准为 `1000`）：

| 类型 | 倍率 |
| --- | --- |
| 史莱姆 | 850 / 1100 / 850 / 750 |
| 野兽 | 1000 / 1000 / 1000 / 1000 |
| 飞行、昆虫 | 850 / 1000 / 1100 / 750；800 / 1000 / 1050 / 700 |
| 爬行、亡灵 | 1000 / 1100 / 1050 / 1000；1200 / 850 / 1000 / 1200 |
| 灵体、元素 | 900 / 1300 / 1150 / 900；1100 / 1500 / 1200 / 1000 |
| 岩石、人形、士兵 | 1400 / 1000 / 900 / 1450；1000 / 1000 / 1100 / 1000；1150 / 850 / 1150 / 1200 |

首领固定为单体，属性使用：

```text
HP      = 最低攻击 × 28
攻击    = ceil(最低HP × (100 + 最低防御) / 750)
防御    = 最低攻击 × 60%
MP      = 24 + 等级 × 6
```

首领的经验与铜钱沿用既有结算模型；本次不根据新经验曲线臆造奖励倍率。

## 首领组队难度

首领**不设强制组队开战前置**。场景 `4/1`、副本挑战与挂机仍按各自原有战斗入口进入；
若发起者已在队伍中，场景触碰继续复用既有 `1/4/5` 队伍战斗冻结与 scene-poll 投递链路。

“需要组队”由属性而不是请求拒绝实现：同级无装备的最低职业对 60 级首领每次约造成
94 点伤害，而首领有 `6104 HP / 303 攻击 / 131 防御`；单人会在常规攻击耗尽首领血量
前先被击倒。多名成员的合并输出、治疗和装备提升才提供合理的完成窗口。首领固定为一只，
避免一个触碰请求随机生成多个同等首领。

## 修改与回归边界

- 默认属性统一位于 `vm_net_mock_monster_base_stats_for_enemy()`；MySQL
  `server_monsters` 的完整显式覆盖仍优先，后台将首领类型清楚标注为单体高强度战斗。
- 场景首领的怪物数量仍位于已处理 `WT 1/4/1` 的战斗 builder：有效类型为首领时固定为一只，
  但不改变开战资格或队伍判断。
- 定向回归应验证：普通怪等级单调、1 级史莱姆走通用曲线、首领属性高于同级普通怪、首领
  固定单体，以及两名同场景队员仍能进入既有同步组队战斗。
