# 场景战斗怪：多条草稿部署与 SCE 搜索

日期：2026-08-26

## 结论

同一个 SCE 可以保存和部署多条场景战斗怪草稿，并非只能有一条。每条草稿
都有独立的条目 ID、坐标、数量、Actor 与启用状态；怪物 ID 可以复用到不同
坐标。一次“验证并部署”会从
同一份捕获的基础 SCE 重建，并编译该场景所有启用草稿。

后台场景战斗怪页现在明确显示：草稿数量、每场景 96 条草稿上限、启用节点数
与还能继续新增的草稿数。新增表单名称改为“新增下一条场景战斗怪”，保存后
不会替换已有条目。左侧 SCE 列表增加本地搜索框，按场景名称即时筛选，不会
请求服务端或影响当前草稿。

## 多条部署契约

- 草稿表以 `entry_id` 为主键，按 `scene, entry_id` 查询；一个场景最多 96 条
  草稿。
- 唯一位置键是 `(scene, monster_id, pos_x, pos_y)`。同一怪物 ID 放在完全相同
  坐标是重复配置，保存时会得到明确提示；同一 ID 的不同坐标、或不同 ID 的
  任意坐标均可共存。
- 每条启用草稿的 `quantity` 会展开为最多五个独立 kind-3 节点。部署器遍历每
  条草稿及其展开节点，而不是只取第一条。
- 部署前会核算基础 SCE 静态节点、NPC 预留节点、所有启用怪物节点和 Actor 子
  节点。合计超过客户端 24 个非本地场景节点即拒绝，避免以截断列表的方式部署。
- 部署后的回读检查要求每一条启用草稿的所有展开节点都存在，且发布节点数与
  基础节点数加全部启用节点数相等。

因此，管理员新增多条后只需点击一次“验证并部署”；客户端完整退出并重启后，
重新进入场景即可获取同一次内容版本中发布的全部节点。

## 回归

- `obj/server/scene-battle-monster-field18-regression.exe`：在同一基础 SCE 中插入
  两条相同怪物 ID、不同坐标的草稿，验证两个 kind-3 记录都存在；再从基础
  重建一次，字节结果保持一致。
- `obj/server/admin-scene-battle-monster-layout-regression.exe`：验证场景搜索输入、
  可筛选的场景行、搜索初始化脚本和多条草稿提示均被页面输出。该回归在关闭的
  本地 MySQL 端口下运行，只验证静态页面，不读取或迁移 `jh_online`。
