# 幽冥鬼府普通死亡的最近主城复活

## 触发与第一处偏离

角色在 `21幽冥鬼府_01.sce`（`sMap.dsh` 行 140）普通死亡后，服务端此前记录：

```text
source_smap=140
target_scene=00蓬莱仙岛_02.sce
target_smap=38
target_world=1
route=wmap-nearest-town-center
hops=1
```

`WT 1/7/14(result=2)`、`1/20/1 + 1/30/1` 的响应契约和客户端场景 parser
均在该日志之后；第一次偏离是服务端构造 `30/1` 前把 `wMap.dsh` 的四方向
光标导航 ID 当作“最近城镇”的可通行连接。

## 原始资源证据

- 幽冥鬼府八个子场景均不含 `怪物等级=无` 的本地安全场景，所以应进入跨世界主城后备。
- `wMap.dsh` 中幽冥鬼府的“右”字段虽然为蓬莱，但该字段是地图界面的方向光标导航，
  不是旅行连接。
- `wMapLine.dsh` 的第 15、16、17 段组成从蜀山节点下侧到幽冥鬼府节点上侧的连续线；
  以 `wMap.dsh` 的节点 `(X,Y)` 和 16 x 16 图标边界切分后，得到唯一的直接边
  `幽冥鬼府 ↔ 蜀山`。没有任何线段接到蓬莱节点，因此蓬莱不是一跳目标。
- `wMap.dsh` 的 `怪物等级=无` 标记的是安全世界区域，而非“可作为主城的城镇”。它
  同时包含新手岛蓬莱。其权威 `下级地图` 基准场景是 `c00蓬莱仙岛...`；四个主城
  的基准场景才是非零 `cNN` 键：`c04临安府`、`c08雁门关`、`c14蜀山`、`c18大理`。
  因此 `c00` 不能作为普通死亡的全局主城后备。
- 目标场景通过既有 SCE 资源加载和出生点解析确认可用。蜀山中心行 105
  `c14蜀山_02.sce` 解析到安全落点 `(72,120)`，没有使用 `sMap.dsh` 的 UI 坐标作为
  角色坐标。

## 修复

`vm_net_mock_resolve_nearest_safe_respawn()` 现在按以下顺序选择：

1. 非主城来源优先在同一 `sMap` 连通图寻找最近的 `怪物等级=无` 安全场景；
2. 主城来源回到本城几何中心，或在没有本地安全场景时进入跨世界后备；
3. 后备只从可达的非零 `cNN` 主城候选中选择，排除 `c00` 蓬莱新手岛；
4. 严格按 `wMapLine` 与 `wMap` 节点坐标还原的实际连接做 BFS，以连线跳数选择最近主城，
   世界 ID 仅用于同跳数裁决；
5. 城内中心候选仍必须能由真实 SCE 解出出生点，随后经过既有传送触发框和 MAP 碰撞
   安全校正。

成功 trace 现在包含 `route=wmapline-nearest-city-link-distance` 与 `hops`；无可达主城或无可解析的主城 SCE 会记录明确的 unresolved 原因，
不会悄悄改回蓬莱。

## 验证

执行 `make -j2` 成功。随后运行资源隔离回归
`obj/server/zhongnan-taiyi-recovery-landing-regression.exe`：不启动监听器、不连接
MySQL、不写入角色数据。

回归通过并断言：

- 幽冥鬼府行 140 → 蜀山长亭行 105，沿世界地图实际连线 `hops=1`、安全落点 `(72,120)`；
- 太乙峰仍到临安府中心行 56；临安府内仍回同一城市中心；
- 蟠龙寨仍优先到本地止水堂行 153，不会跨世界回蓬莱；
- 原有太乙峰防卡位和设置页脱离的 MAP 安全落点保持通过。
