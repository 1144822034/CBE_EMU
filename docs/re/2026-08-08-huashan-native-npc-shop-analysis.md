# 华山－莲花峰原生 NPC 商店取证

状态：已实现服务端根因修复与配置层；待人工在后台验收具体库存。

## 触发与证据

在 `09华山_03.sce`（华山－莲花峰）与风清扬交谈时，服务端日志记录：

```text
mock_npc_dialog actor=58581 ... script=09华山风清扬.xse
scene=09华山_03.sce catalog_match=1 npc_kind=5
service_action=3875536897
mock_npc_service action=shop-category opcode=e7000001 ...
```

`0xe7000001` 是当前服务端私有的“药品商人”服务值，而不是客户端原生商店
协议 `26/3` 的商店编号。其后的服务菜单从完整商城目录中挑选 `item.dsh`
类别 `10` 的所有物品；它没有风清扬专属的商品表。

## 原始资源结论

服务端以只读方式解析实际服务资源 `09华山_03.sce`：风清扬记录为
`n_magemaster.actor`、`09华山风清扬.xse`、坐标 `(149,85)`，SCE 记录首字段
为 `5`。同一场景的小鱼儿首字段为 `4`。XSE 仅包含“十年”任务的对话、
红鬼火条件和 3000 经验奖励，没有商品 ID、价格或商店命令。

跨场景资源也证明 SCE 的 `4/5` 是原生场景实体记录类型，不能解释为服务端
`npc_kind`：例如大侠郭靖、白展堂、郭芙蓉、小鱼儿均出现 `4`，而大量任务
NPC（丘处机、王重阳、风清扬等）均出现 `5`。

## 首个错误状态（根因）

`vm_net_mock_parse_sce_interactive_npc_at()` 把 SCE 首字段写进
`vm_net_mock_scene_npcinfo_seed.kind`。同一个字段又被
`vm_net_mock_build_npc_dialog_response()` 当作动态 NPC 的
`VM_NET_MOCK_NPC_KIND_*` 服务类型分派：`4` 被解释为防具商人，`5` 被解释为
药品商人。因此静态场景 NPC 被意外附加了服务端伪造的商店入口。

这是类型语义复用，而不是风清扬 XSE、SCE 或客户端原生商店配置的商品价格错误。

## 当前价格来源及“便宜”的原因

商品候选来自全局 `item.dsh/equip.dsh` 目录：普通物品的原始价格是
`item.dsh` 第 9 列“价值”，之后由 `server_shop_items.price` 覆盖。当前实测：

| 物品 | DSH 价值 | 当前 MySQL 覆盖 | 实际服务价格 |
| --- | ---: | ---: | ---: |
| 小回春散（301） | 75 | 无 | 75 铜 |
| 中回春散（302） | 525 | 无 | 525 铜 |
| 神仙壶（802） | 0 | 10000 | 10000 铜 |
| 逍遥壶（803） | 0 | 10000 | 10000 铜 |
| 青铜/白银/黄金钥匙（813/814/815） | 0 | 1 | 1 铜 |

现有目录装载器把任何零价 DSH 行改为默认 `1` 铜；没有 MySQL 覆盖的零价
宝箱、经验卡、任务/特殊物品也因此会错误地以 1 铜进入这个伪造的药品列表。

## 已实现的服务端契约

1. `vm_net_mock_scene_npcinfo_seed` 现在将 `sceneEntityKind` 与 `kind` 分开。
   SCE 解析把首字段放入前者，并将后者固定为“普通/任务 NPC”；动态 NPC 和已有
   服务内置 NPC 继续只使用 `kind`。因此原生 `4/5` 不会自动映射为防具/药品商人。
2. 新表 `server_native_npc_overrides` 的主键为 `(scene, actor_id)`，其中 `scene`
   是精确的运行时场景键（不使用宽松别名比较），字段为 `service_kind`、`enabled`。
   它只在 SCE 原生 actor 解析完成、确定稳定 actor id 后应用；原始 SCE/XSE、模型、
   坐标和显示名保持只读。
3. 新表 `server_npc_shop_inventory` 的主键为 `(scene, actor_id, item_id)`，字段为
   `unit_price`、`enabled`。它可用于原生覆盖后的 NPC，也可用于现有动态/服务内置
   商人。商店候选必须同时满足：服务类型对应的分类、全局商品目录已启用、专属库存
   已启用且有正单价。
4. 进入嵌套商店菜单前，服务端在客户端会话记录 `role_id + scene + actor_id +
   service_kind`。后续 `26/1` 私有服务请求不携带 actor id，因此必须通过该上下文
   过滤商品与结算价；场景或角色变化会使该上下文失效，避免 NPC 之间串货。
5. 后台“游戏内容管理”新增“原生 NPC 覆盖”区：展示 SCE 实体类型、坐标、Actor、
   XSE，并可保存服务类型/启用状态、恢复默认。武器、防具和药品服务显示“NPC 专属
   库存”，复用已有的分类/关键字物品选择弹窗；库存行单独编辑单价与上/下架。动态
   NPC 与原有服务内置 NPC 也显示同一套专属库存，避免重新启用商人后回退到全局目录。

原生覆盖暂不接受“副本向导”类型：该服务需要额外的目标场景、坐标和守关怪契约，
属于动态 NPC 已有的配置域；不为原生 SCE actor 伪造这些字段。

## 验证边界

- `make -j2` 在实现后通过。
- 未启动或改动正在使用的服务端、账号或 `jh_online` 数据库。两张表由服务器首次
  装载原生 NPC 配置时以 `CREATE TABLE IF NOT EXISTS` 创建。
- 尚需人工验收：在华山－莲花峰将风清扬显式设为所需商人类型，添加至少一件对应分类
  的库存商品和正单价；重新进入场景后对话应只显示该服务与该库存，购买时扣除该库存
  单价，而不是 `item.dsh/equip.dsh` 的全局默认价。
