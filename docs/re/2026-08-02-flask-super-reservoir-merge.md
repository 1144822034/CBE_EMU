# 壶类单行超级储量合并

## 目标

802/803 在背包/仓库按 **itemId 单行** 合并储量；购买叠加单位容量；上限拒绝；
战斗每次成功使用固定扣单位容量的 1/3；背包在满血蓝时点用显示当前储量。

## 规则

| 项 | 值 |
| --- | --- |
| 单位容量（买一把） | 50000 |
| 单行硬上限 | 5000000 |
| 战斗单次回复上限 | `50000/3` = 16666 |
| 战斗手动用壶扣储量 | 只要有回复就固定扣 `50000/3`；余量不足则扣光（与实际回复量无关） |
| 战斗结算 auto-flask | 按实际回复量扣储（不用固定 `50000/3`）；组队须同步 `online*`/`battleMember*` |
| 场景点用 | 契约 `7/1+7/11`（见 vitality-flask-reserve）。满血蓝无扣储、不 mark dirty。储量用系统聊天 `1/3/3` 提示「当前储量：N/5000000」，不要用 `16/2`。 |
| 战斗结算 | 「背包 xx/64」客户端本地绘制，不能改。储量写入同面板 `4/7.fdata` 前缀（如 `N/M 战斗胜利`，仅数字）。 |
| 购买将超上限 | 不扣费；NPC 对话框文案 / 商城 `14/3 result=3` + `1/3/3`「储量已满，不可再购买。」 |

## 实现要点

- `vm_net_mock_role_grant_flask_reservoir_points`：合并同 ID 多行后按点加储；超上限整笔拒绝。
- 商城/NPC `add_backpack` 走上述授予；`g_vm_net_mock_backpack_add_fail_kind` 区分包满与壶满。
- 仓库存取同 ID 合并储量，超上限拒绝。
- `plan_reservoir_restore(..., perUseCap)`：战斗手动/结算 auto 均限制单次回复 ≤`FLASK_BATTLE_PER_USE_CAP`。
- 手动战内用壶：`battle_flask_charge` 固定扣费；结算 auto-flask：按回复量扣费，并 `sync_team_presence_after_settle`。

## 验证

1. 空包买壶 → 一行 `count=50000`。
2. 再买 → 仍一行，`count=100000`；不新开 seq。
3. 储量 ≥ 4950001 再买 → 提示已满，不扣费。
4. 满血蓝点壶 → 提示当前储量。
5. 战斗用壶（缺血 100）→ 回复 100，储量扣 16666。
6. 战斗用壶（余量 100）→ 回复 ≤100，储量扣光。
