# NPC 装备回收背包刷新与商店属性显示取证

日期：2026-08-14  
状态：已实现；最终链接待服务端进程释放输出文件

## 现象

1. 在装备回收 NPC 成功回收装备后，服务端已持久化删除装备，但客户端背包中的物品未立即正确刷新。
2. 装备商人的购买窗口中切换光标时，没有显示所选装备的属性。

本轮尚未收到上述两项操作的对应运行时日志；`bin/server_out.txt` 仅包含服务启动和后台操作记录，不能据此推断实际请求序列。

## 既有协议结论

- `26/1` 是 NPC 服务对话的回调上下文。装备回收成功只能在该上下文内确认成功；不能把 `7/7 type=2`、`7/11` 或完整 `17/1` 背包快照附加到这个回调中。
- 已有取证记录表明：`7/7 type=2` 是装备安装/同步语义，`7/11` 只能修改数量，均不能删除普通装备行。因此这两种“即时刷新”做法会造成协议错位，不能恢复。
- 回收后的背包变更必须由客户端随后发出的正常背包查询按角色持久化状态重建；本轮需核对该请求是否被遗留的 NPC/商店上下文截获。

## IDA 取证（按 binary_name 选择实例）

目标：`mmShopMstarWqvga.cbm`。

- `sub_2EB6 (0x2EB6)` 在切换商店光标时取已解析的 64 字节商品行，并调用 `sub_2E88 (0x2E88)` 写入当前选中商品状态。
- `sub_7BC (0x7BC)` 解析 `1/14/5..13` 的 `iteminfo` 行：商品 ID、名称、价格、库存、标志后，调用共享 `ParseEquipAttributes`，把属性数量及属性数组写入该商品行。
- `sub_9DE` 对各商店商品子类型均调用 `sub_7BC`。

该结论适用于 `mmShop` 的商城 `14/*` 页；它说明共享属性区是强化实例数据，不能把装备基础属性猜测性地塞入该区。

当前问题的实际路径是动态装备商人的 `26/1` 对话：服务端代码此前将每个装备选项的说明固定为 `名称 Lv.等级`。客户端在光标切换时显示的正是该选项说明，因此基础属性没有任何来源。正确修复是使用服务端已从 `equip.dsh` 加载的基础属性生成该说明，而不是改变商城的 `iteminfo` 尾部。

## 假设与计划

1. 已确认回收成功后缺少“下一次 `17/1` 必须返回角色背包”的状态标记。修复将清除遗留商城列表优先级、设置角色列表优先级，但不会在 `26/1` 中附加不属于该回调的删除包，也不会重置仍存活的背包网格种子。
2. 已确认动态装备商人使用 `26/1` 选项说明而非商城 `iteminfo`。修复以 `equip.dsh` 基础属性构造选项说明，保留商城共享属性块的现有强化语义。
3. 修改后仅执行 `make -j2`；运行时回归由用户在现有客户端完成。

## 本轮实现与验证

- 装备回收成功及 NPC 购买成功后，服务端清除遗留商城 `17/1` 优先级，并设置下一次背包请求为角色权威列表；不重置当前背包网格种子，也不在 `26/1` 中混入 `7/7`、`7/11` 或 `17/1`。
- NPC 装备选项的光标说明现在列出 `equip.dsh` 的基础属性：物攻、护甲、气血、法力、力量、敏捷、智慧、暴击、命中、躲闪、抗性（仅显示非零属性）。
- `make -j2` 已通过。未启动服务端；客户端实际回归需覆盖“回收后打开背包”和“装备商人切换不同武器光标”两条路径。

## 防具与药品光标说明扩展

### 当前卡点

- 防具商人与药品商人使用同一条 `WT 1/26/1 {type=2,id=...}` NPC 服务对话链路。
- 前一轮装备说明的分支已经按 `item->isEquip` 处理，因此防具和武器同样从 `equip.dsh` 基础属性获得说明；不需要另建防具协议。
- 药品仍落入旧的 `名称 Lv.等级` 回退分支，未将 `item.dsh` 效果显示到光标说明。

### IDA 证据

| binary | function/address | findings |
| --- | --- | --- |
| `江湖OL.CBE` | `ParseNPCDialogData (0x010380E8)` | 读取 `26/1` 的 `dialog` blob；每个选项依次读取类型、名称、动作、值和说明字符串。说明字符串被复制到选项状态的 `+40` 指针，分配容量为 `0xC8`（200 字节）。 |

因此服务端应通过既有 option description 字符串提供药品说明；不能额外附加对象，也无需修改客户端。

### 数据与最小实现计划

- `item.dsh` 已加载为 `vm_net_mock_item_effect_catalog_item`：等级（列 6）、使用方式（列 12）、时长分钟（列 13）、HP（列 15）、MP（列 16）、经验（列 17）。
- 药品商人仅允许 `category == 10` 的非装备商品进入该选择器，故可在现有 `effect != NULL` 分支中安全生成说明。
- 计划仅新增一个有长度上限的药品说明格式化函数，显示等级及非零的气血恢复、法力恢复、经验和时效；其他没有可确认效果数据的普通物品保留现有等级说明。

### 运行时证据与未知项

- 本轮没有新的客户端日志；这是已有 `26/1` 对话协议的显示字段扩展，不改变请求匹配、响应对象数量或回调时序。
- `consumeMode` 的各数值语义不在本轮作为文案分支依据；仅在非零时以“使用方式 N”保留原始资源值，避免猜测其中文名称。

### 实现结果与构建状态

- 防具沿用装备基础属性说明分支；药品新增使用 `item.dsh` 的气血、法力、经验和时效字段生成说明。零值字段不显示，未知的 `consumeMode` 数值未被猜测性翻译。
- `江湖OL.CBE:ParseNPCDialogData(0x010380E8)` 的 200 字节说明缓存是本轮说明字符串的长度上限依据；服务端仍只发送既有 `26/1` 对话对象。
- 本轮 `make -j2` 已完成 C 源编译，但链接 `bin/jh-online-server.exe` 时因该文件正被运行中的服务端占用而失败（Permission denied）。未终止用户进程；待输出文件释放后重跑完整构建。
