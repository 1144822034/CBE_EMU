# 后台怪物搜索选择器

## 范围

后台中原先要求手输怪物 ID 的三个业务入口改为统一的可搜索选择器：

- 场景战斗怪草稿的新建和编辑（`monster_id`）；
- NPC 副本传送的“进入后刷新怪物”（`instance_spawn_enemy_id`）；
- NPC 守关挑战的“守关怪”（`challenge_enemy_id`）。
- 任务目标的“击败怪物”条件（`requirement_id1`、`requirement_id2`）。

怪物管理页中的 `monster_id` 均为当前选中怪物或批量操作的隐藏上下文值，
并不是可编辑的怪物 ID 输入框，因此保持原状。

## 契约与实现

每个表单保留同名的隐藏 `select`，提交的字段名和值与改造前完全一致。页面仅
渲染一份怪物目录到 `#monster-picker-options`，弹窗按 ID、名称、等级、类型搜索，
选中时才把值写入发起表单的 `select`。这样场景页面包含多个 NPC 时不会重复输出
完整目录。

副本刷新字段额外提供“不额外刷新”，其提交值仍为 `0`。守关挑战和刷新怪物的
服务端场景部署校验没有放宽：选择器提供全目录用于检索，提交后仍必须分别满足
目标场景已部署/当前场景已启用的场景战斗怪约束。

任务目标按类型切换输入控件：收集物品保留物品目录选择，击败怪物时禁用同名的
数值输入并启用同名怪物选择字段。因此请求中始终只有一个 `requirement_id*`，
现有任务保存协议无需改变。

## 验证

`scripts/admin-monster-picker-regression.c` 验证各字段保留的提交名称、必填规则、
`0` 哨兵值，以及共享搜索弹窗的客户端绑定。该脚本不启动 HTTP 服务、不连接
数据库，也不修改账号或内容数据。
