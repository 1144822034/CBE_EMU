# 付费副本地图准入链路排查

## 目标

确定固件中“不能直接瞬移、需先付费”的地图名单、费用来源、确认与扣费时机；服务端只实现
客户端已验证的准入协议，不将普通传送石的消耗字段误作副本收费字段。

## 已确认事实

1. `江湖OL.CBE` 实例按 `binary_name` 选择后，`SendItemUseReq(0x0103573A)` 为世界地图点击
   发送 `WT 1/16/4`，字段只有 `curid` 与 `objid`。
2. `HandleItemUseDispatch(0x010357E0)` 仅把 `16/4` 响应交给
   `HandleItemUseConfirm(0x010190A8)`；后者将 `value` 传入确认回调。
3. `ConsumeInventoryItem(0x01018F66)` 在确认后固定从背包扣除物品 ID `800`，并发送 `16/2`
   和 `16/3`。因此 `16/4.value` 的语义是**传送石数量**，不能承载酷宝、W 币或副本门票价格。
4. 现有服务端的 `16/4`、`16/2`、`16/3` 实现对应上述普通地图传送链，付费副本必须寻找
   另一条入口而不是修改该链路。
5. `scene_runtime_init_and_sync(江湖OL.CBE:0x01012FB4)` 在具名入口初始化的状态 `2/3`
   发送 `WT 1/16/3 {exitID,type=0}`；普通场景进入则走 `1/2/3`。`exitID` 是 SCE
   入口编号，不是货币或传送石数量。
6. `mmGameMstarWqvga.cbm:sub_11CE(0x11CE)` 对该通道的契约为：
   - `1/16/2 {result=2}`：清理等待状态并显示原生“酷宝不足，请进入商城充值”提示；
   - `1/16/2 {result=4,hint}`：显示服务端拒绝原因并清理等待状态；
   - `1/16/3 {result=2,scene,posinfo,exitid}`：调用 `sub_BCC`，由客户端进入目标场景。
   因而不足余额不能答成 `16/3`，成功也不能答成普通 `30/1` 场景包。
7. SCE 具名入口字段为：`0x12` 背景/入口资源名、`0x15` 目标入口编号、`0x16`
   显示名称、`0x17` 目标场景。`wMap.dsh`、`sMap.dsh`、XSE 与具名入口记录均没有费用列或
   费用标量；价格不是客户端资源可恢复的数据，必须由服务端配置。
8. 原始资源中 `target_entry_id=2` 的收费入口组精确为：
   - `b_21幽冥鬼府.sce`：幽冥鬼府入口、万骨窟、百鬼墓、鬼王厅、将军冢、演武厅、血骨厅、炼血地狱；
   - `b_23蟠龙寨.sce`（客户端显示黑木崖）：入口、止水堂、玄武北堂、玄武殿、白虎东堂、白虎殿、
     朱雀南堂、火舞回廊、朱雀殿、麒麟正堂、云生回廊、麒麟殿；
   - `b_25华山洞窟.sce`：一层、二层、三层、南面、北面、四层。
   `b_29梦境空间.sce` 的 `target_entry_id=3` 为梦境三层返回临安的入口，排除在收费组之外。

## 根因

服务端的 `vm_net_mock_is_teleport_stone_transfer_request` 仅因 `16/3` 中含有 `exitID` 或
`type` 就将具名入口请求归入普通传送石路径。该路径以传送石确认目标或默认地图构造后续
`30/1`，既未校验玩家是否站在具名入口，也未读取账号 W 币，更不符合 `mmGame:0x11CE`
要求的 `16/2`/`16/3` 响应分支。

## 实施契约

新增处理器只接受单对象 `WT 16/3`、对象 `1/16/3`、`type=0` 且有 `exitID` 的具名入口
请求；它从当前角色所在场景和服务端权威坐标解析 SCE 具名入口矩形，并用目标场景的同编号
边缘入口解析真实落点。普通传送石 detector 显式排除 `type=0`。

收费规则存放于 `paid_instance_access_rules(background_scene,target_entry_id,wcoin_cost,enabled)`。
首次建表会为上述三组入口建立启用的、每次 `1` W 币的保守默认规则；这个数值不是从固件
猜出的，运营可在 MySQL 中修改。扣款走现有账户钱包 InnoDB 事务；余额不足仅返回原生
`16/2 result=2`，事务失败返回 `16/2 result=4`，成功后才保存场景目标并返回
`16/3 result=2`。

## 待验证

- 运行时分别验证三组入口的余额不足、扣费成功、重复进入和两账号并行状态隔离。
- 首次规则的 1 W 币默认值是否需要按运营方案调整；客户端资源未提供原始定价。

## 当前结论

普通地图传送的 `16/4.value` 保持为传送石数量。实现仅覆盖已证实的具名入口协议，不改变
世界地图、传送石、梦境返回入口或普通场景边缘传送。
