# 蓬莱铸剑谷 NPC 在场景别名和脱离后的显示（已废弃）

> **已废弃（2026-07-24）**：本文此前把 `c00蓬莱仙岛_02.sce` 视为
> `00蓬莱仙岛_02.sce` 的同一资源。用户已明确这类名称近似的 key 可以代表不同地图；
> 真实 `sMap.dsh` 也不支持该推导。请以
> [`2026-07-24-scene-key-identity-audit.md`](2026-07-24-scene-key-identity-audit.md)
> 的精确场景键契约为准，本文的别名修复结论不得再用于实现。

## 触发条件

角色场景保存为 `c00蓬莱仙岛_02.sce` 时，直接登录铸剑谷，或经“脱离卡死”后的
direct scene enter 进入该场景。客户端随后按已确认的场景运行时契约请求：

```text
1/16/3 { exitID: current-X, type: 0 }
1/27/11 {}
1/7/42 {}
```

画面没有欧冶子和小猴子；而场景以 `00蓬莱仙岛_02(.sce)` 形式进入时则正常。

## 客户端和服务端证据

- `江湖OL.CBE:scene_runtime_init_and_sync(0x01012FB4)` 在 direct enter 建立场景壳后
  请求 `27/11`；`scene_parse_npcinfo_and_spawn_npcs(0x01037998)` 只会从非空
  `npcnum/npcinfo` 创建 NPC 节点。
- `00蓬莱仙岛_02` 的 SCE 不含交互 NPC，欧冶子 `20020/n_blacksmith.actor` 和
  小猴子 `20021/e_monkey.actor` 是服务端目录行，坐标分别为 `(338,125)`、`(376,125)`。
- `vm_net_mock_scene_resource_exists()` 原先只会把 c 前缀的键转换成旧式
  `00_蓬莱仙岛02.sce`。但铸剑谷的实际资源名是 `00蓬莱仙岛_02.sce`；所以
  `c00蓬莱仙岛_02.sce` 被错误判为不存在，`vm_net_mock_role_normalize()` 随即把
  已保存的角色场景替换为初始场景 `c00蓬莱仙岛_01.sce`。这发生在脱离目标和
  NPC 目录构建之前，是本故障的首次偏离。
- 资源名校验修正后，`vm_net_mock_current_scene_name()` 仍会为运行时目录保留
  extensionless `c00蓬莱仙岛_02`。旧的 `vm_net_mock_scene_is_penglai02()` 只匹配
  非 c 前缀形式，因此目录收集仍会得到零行；它是同一场景别名链上的第二个、独立
  契约缺口。

已排除：坐标、模型资源、`27/11` 字段顺序、以及把 direct runtime `16/3` 当传送石的
问题。后者有独立的精确 handler；本次错误发生在它已经正确进入目录 builder 之后。

## 修复

资源校验会先尝试移除 c 前缀而保持其余文件名不变，即
`c00蓬莱仙岛_02.sce -> 00蓬莱仙岛_02.sce`；只有此资源不存在时，才尝试原有的
旧式标点别名。随后将 `c00蓬莱仙岛_02` 及其 `.sce` 形式加入铸剑谷的同一已验证
NPC 目录身份。

这不改写传送名、持久化字段、坐标或客户端逻辑；它只让已有的正确场景键通过资源
校验，并让该缺少静态 NPC 的场景取得它本来就必须拥有的服务端 `27/11` 目录。

## 回归

`scripts/forge-valley-npc-lifecycle-regression.php` 使用独立测试账号，并故意将其场景
保存为 `c00蓬莱仙岛_02.sce`。它断言：

1. `0/12/3` 的 `16/3.scene` 仍是这个 c 前缀的铸剑谷场景；
2. `16/2` direct enter 后的真实形状 `16/3 + 27/11 + 7/42` 返回至少两行，且
   包含 actor id `20020/20021`（动态 NPC 可以额外增加行）；
3. 该过程不依赖重复投递、轮询兜底或客户端内存修改。

2026-07-24 使用独立服务端口 `19095` 实测通过：`12/3` 返回并保持
`c00蓬莱仙岛_02.sce`，随后 `16/2` 与 direct-runtime 流中 `27/11` 的目录为
`npcnum=2`，包含上述两个 actor；服务日志同时确认目录键为
`c00蓬莱仙岛_02`。`make -j2` 已通过。
