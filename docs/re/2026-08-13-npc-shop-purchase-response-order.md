# NPC 商人购买响应顺序（2026-08-13）

## 触发与现象

动态 NPC 武器商人的购买选项通过 `task_hall_activate_selected_entry`
（`JianghuOL.CBE:0x010492B0`）发起私有 `26/1` 请求。运行日志确认服务端
`mock_npc_service action=shop-buy` 会正确扣除铜钱、写入背包，并返回一个含
三个对象的 450 字节响应，但客户端持续显示“获取数据”。

## 客户端证据

- `0x010492B0` 的 action 1 调用 `SendEvent26_1(2, value)`；
- `0x01039C28` 对 `1/26/1` 调用 `ParseNPCDialogData`，随后清除该事件的
  网络等待状态；
- `mmGameMstarWqvga.cbm:0x11CE` 遍历 event 7 的对象，`1/7/7` 交给
  `0x0D04` 更新物品管理器；
- `JianghuOL.CBE:0x010114FC` 的 `1/10/26` 分支仅用 `name` 与 `money`
  刷新角色货币信息。

因此，对话请求的 `26/1` 回包与背包/货币刷新虽可被各自解析，却不应在同一
请求回调中混合下发；物品管理器更新必须在该对话回调完成后，走下一次普通场景
同步事件。

## 修复合同

1. NPC 购买的直接响应只返回 `1/26/1` 对话数据；
2. 成功购买在当前客户端会话记录一次性 `seq/item/count`；
3. 下一次场景同步轮询（至少下一调度 tick）单独返回 `1/10/26 + 1/7/7`；
4. 同一会话在前一次背包同步未发送前拒绝第二次购买，防止覆盖增量；
5. 会话、角色、序号或物品状态不一致时丢弃待发同步并记录明确错误日志，绝不
   向其他角色下发。

该方案同时覆盖武器、防具与药品商人，因为三者共用 `shop-buy` 服务分支。
商人服务授权按商品分类与对应服务位独立判断，因此同一 NPC 同时具备武器、防具、
药品服务时，各分类的后续购买请求也都保持有效。
