# 梦境一层踩怪不掉 841：掉落配在 203，开战 real 是 204

日期：2026-08-11

## 触发

角色已接收集任务 `100006`（需 841），在梦境踩怪多场后背包仍无 841。
后台在怪 **203** 上配置了 `841@100%`。

## 权威数据

| 来源 | 内容 |
|------|------|
| `server_monster_drops` | **203** slot1=`841@100`；**204** 仅 1% 装备，**无 841** |
| `server_scene_combat_spawns` `29梦境空间_01` | wire=`200` → **real=`204`**（两槽） |
| `server_scene_monsters` `_01` | 挂机槽 `204,204,0` |
| `_04` | wire→**203**；挂机槽 `203` |
| `account_role_tasks` role=456 | `100006 state=1 progress1=0`（已接） |
| `account_role_backpack` | 全服无 `item_id=841` |
| debug-0b451a | role=456 在梦境内大量 `4/1` 踩怪（非挑战对话） |

挑战 NPC `32901.challenge_enemy_id=203` 与一层刷怪点无关。

## 预期 / 实际 / 首次偏离

- 预期：打「配了 841@100% 的怪」且已接 `100006` → 必掉 841。
- 实际：一层踩怪结算按 **enemy=204** 查掉落表 → 表中无 841 → 不发。
- 首次偏离：开战 remap `200→204` 后，`grant_reward_once` 使用
  `g_vm_net_mock_battle_enemy_id_current=204`，从未读取 203 的掉落行。

任务材料门闩**不是**本例根因：456 已有 `100006 state=1 remaining=10`；
即便门闩放行，204 也没有 841 可掷。

## 根因

掉落配置挂在 **203**，一层地图开战身份是 **204**。配置对象与开战
`battleEnemyId` 不一致。

## 修正方向（择一，勿混）

1. **运营数据**：把 `841@100%` 配到实际开战怪 **204**（及需要掉材料的其他层 real）。
2. **玩法路径**：只打挑战/ `_04` 等 remap 到 **203** 的怪，才能吃到现有 203 表。
3. **不要**再改「100% 绕过材料门闩」——本例与门闩无关。

## 验证

1. 确认一层踩怪日志：`mock_scene_combat_spawn_remap … wire=200 real=204`，
   `mock_battle_drop_gate enemy=204`（不是 203）。
2. 在 204 增加 `841@100` 并重启服务后：接 `100006` 踩一层怪 →
   `item=841 rate=100 … grant=1`，背包有 841。
3. 挑战 `32901` 打 203：仍走 203 表（若保留 203 的 841 行）。
