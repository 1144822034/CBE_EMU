# 全服奖励后台附件控件在单页导航下失效

## 触发条件与首次偏离

1. 在后台任意标签页打开侧边栏的“全服奖励管理”。
2. 侧边栏单页导航取得该页 HTML，并将主体片段写入 #admin-spa-content。
3. 点击“添加附件”。

页面会显示该按钮和 12 个预先渲染的附件槽位，但第二个槽位保持隐藏，计数也不变。首次偏离发生在前端初始化：全服奖励页面把事件绑定写在自身末尾的内联脚本中，而单页导航以 innerHTML 插入该脚本，浏览器不会执行它；共享 admin.js 的 setupAdminContent() 当时也没有对应初始化器。

这不是发奖表单、MySQL 写入或游戏客户端邮件协议的问题：点击未使 DOM 状态发生变化，因而尚未形成提交请求。

## 修复与契约

- 为全服奖励表单、添加按钮和计数器添加稳定的 data-global-reward-* 标识。
- 将附件行显示、计数、物品选择后的默认数量、移除时的行压缩和物品选择器标签同步，迁入共享 setupGlobalRewards()。
- setupAdminContent() 在每次单页内容替换后调用该初始化器；表单数据标记防止重复绑定。
- 移除页面片段中的内联脚本，避免直接载入页面时双重绑定。

该修复只恢复管理端 DOM 与表单字段契约，不修改任何奖励数据、服务端发放事务或 CBE 客户端状态。

## 回归边界

scripts/admin-request-length-regression.c 断言共享脚本同时包含全服奖励初始化器、稳定选择器、显示隐藏行的操作和 setupAdminContent() 调用。构建后的定向回归应证明：从侧边栏进入页面后，“添加附件”会显示下一个槽位、更新计数并聚焦该槽位的物品选择按钮；移除附件仍会压缩行并保持至少一个槽位可见。
