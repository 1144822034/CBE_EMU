# 锁妖塔一层地图名空格

Date: 2026-07-25

Status: fixed (emulator UCS-2 path detection)

## 问题

1. `16锁妖塔_01.sce` 内嵌地图名为 GBK/UCS-2 `16锁妖塔_01 .map`（`_01` 与
   `.map` 之间有空格）。同塔 `_02`…`_09` 无此空格。
2. 进图后客户端对同一文件反复 `WT18/7`（`resp=1035`，payload=926），伴随
   `stream_data_result ... res=0 result=0`。

## 错误尝试（已回滚）

曾改 SCE：同占位把带空格名改成无空格并补 `00`。对照 `_02.sce`，名后应是
4 个 `00`，补丁变成 5 个 → SCE2 流错位 → 闪退。已恢复原始 SCE。

## 根因

`vm_path_looks_like_ucs2_le()` 允许的 ASCII 子集原先不含空格（U+0020）。
带空格的 UCS-2 资源名检测失败后，`vm_read_path_string()` 按 GBK C 字符串回退，
在第一个 `0x00` 高字节处截断（例如变成 `"1"`）。  
结果：网络侧仍按完整 GBK 名请求并收到 chunk，本地安装/打开路径被截断，文件
永远对不上，客户端不停重下。

## 修改

`src/vmFunc.c`：UCS-2 路径 ASCII 白名单增加 `' '`。不改 SCE、不做资源名别名。

## 验证

- 复测进 `16锁妖塔_01.sce`：应只下一次 `16锁妖塔_01 .map`（若本地已有则不下），
  不再出现同文件 `resp=1035` 死循环。
- `make -j2`
