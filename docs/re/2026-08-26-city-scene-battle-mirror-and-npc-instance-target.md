# 城市场景战斗镜像与 NPC 副本挑战目标

日期：2026-08-26

## 结论

后台“场景战斗怪”部署现在同时覆盖普通野外场景和 `c` 开头的城市
场景。城市的原场景仍按原生城镇屏幕加载；只要该城市有启用的场景战斗怪，
部署会在同一次内容更新中额外发布一个普通碰撞场景镜像以及该镜像所需的
专属背景资源。

NPC 副本传送的挑战怪物 ID 采用 `instance_spawn_enemy_id`：它表示**目标
场景中已部署的 SCE2 kind-3 战斗怪**。目标是城市时，服务端仍保存管理员选择
的 `c...sce`，但在正常 `30/1` 入场响应中发送已发布的非 `c` 镜像；玩家触碰
火团后仍由客户端发起正常的 `WT4/1`。

`challenge_enemy_id` 则被明确收敛为“没有副本目的地的旧式当前场景守关怪”。
它不能与副本传送服务组合，以免再次进入已经被否定的 action-13 直开战路径。

## 根因与契约

- `JianghuOL.CBE:0x0100EEBC` 按资源名首字节将 `c...sce` 归类为城镇/特殊
  屏幕。该屏幕不会调用 `TriggerAutoBattle`，即使 SCE 中存在 kind-3 火团。
- 用 `w04临安府_01.sce` 进入同一份 kind-3 数据会走野外碰撞分支；这是已由
  手工验证的客户端行为，不涉及修改客户端状态、寄存器或战斗回调。
- 野外碰撞场景还要求具备 `b_*.sce` 背景描述和相应地图。缺失 field18 背景
  会在后续地图控制器/战斗背景分配中崩溃；借用丹霞山背景虽能进入战斗，但
  会显示错误场景。

## 部署设计

对 `c04临安府_01.sce`，且至少有一个启用战斗怪时，后台部署生成并发布：

| 配置/资源 | 作用 |
| --- | --- |
| `c04临安府_01.sce` | 管理员选择的原城市场景；保留城镇交互。 |
| `w04临安府_01.sce` | 带相同 kind-3 战斗怪的非 `c` 碰撞镜像。 |
| `b_04临安府_01.sce` | 以已验证的空战斗背景壳为结构、使用临安府尺寸和地图名的背景描述。 |
| `b_04临安府_01.map` | 原城市地图的精确副本，作为该背景的地图。 |

镜像只在服务器生成阶段做资源键安全校验；发布后，NPC 入场会用
`vm_net_mock_select_sce_combat_spawn` 同时验证镜像文件实际存在且包含目标
kind-3 ID。任何背景模板、空 field18 槽、地图、编码或回读验证失败都会拒绝
部署。写入或内容更新发布失败时，部署会恢复本次涉及的精确 overlay 文件。

内容更新清单包含原 SCE、Actor/GIF 闭包以及三项城市镜像资源，因此客户端在
完整退出并重启后会在首次创建场景前获得整组资源。

## NPC 管理规则

1. 勾选“副本传送”（服务 6），选择目标场景与落点。
2. 在“传送后挑战怪物”选择该目标场景中启用并部署的场景战斗怪 ID；不需要
   战斗时可选择“不设置挑战怪物”。
3. 不要同时勾选“守关怪挑战”（服务 10）。保存会拒绝这个组合，并提示改用
   “传送后挑战怪物”。
4. 遗留的“有目标场景 + 服务 10”配置不会再在 NPC 菜单中暴露直开战入口；保存
   后应按以上规则整理。

进入日志会同时记录 `configured_scene`（后台保存的城市）和 `scene`（真正发送
给客户端的镜像），以便核对路由。

## 回归证据

以下均为不启动监听服务、不连接 MySQL、不写入账号或后台草稿的本地测试：

- `make -B -j2`：客户端和服务端完整构建通过。
- `obj/server/city-scene-battle-mirror-regression.exe`：用
  `c04临安府_01.sce` 插入 kind-3 记录后，验证 `w...sce`、`b_...sce`、
  `b_...map`、field18 引用和 LZSS 回读，已通过。
- `obj/server/instance-guide-direct-entry-regression.exe`：验证目标副本不再使用
  action-13，而无目标旧守关怪仍保留该兼容入口，已通过。
- `obj/server/scene-battle-monster-field18-regression.exe`：196 个已发货 SCE2
  实体列表与 field18 战斗怪插入回归通过。
- `obj/server/admin-scene-battle-monster-layout-regression.exe`：后台编辑页面布局和
  城市镜像提示通过。

## 人工验收

1. 在后台为城市场景保存并部署至少一个启用的场景战斗怪。
2. 为 NPC 仅配置“副本传送”，把该城市选作目标，并在“传送后挑战怪物”选择
   刚部署的怪物 ID。
3. 重启客户端后通过 NPC 进入。服务端日志应显示
   `configured_scene=c...` 和 `scene=w...`。
4. 触碰火团。客户端应自动发送 `WT4/1` 并进入战斗，背景应为目标城市自身；
   不应需要鼠标左键，也不应显示丹霞山背景。

限制：城市原场景直接游走时仍保持城镇交互，火团不在该城镇屏幕直接开战；
这是客户端分类契约，战斗入口只由 NPC 副本传送使用的镜像承担。
