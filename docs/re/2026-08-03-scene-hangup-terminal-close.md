# 场景挂机奖励结算与结束边界（2026-08-03）

## 触发与证据

场景挂机的最后一击会在同一响应中下发最终 `4/6` 与奖励结算 `4/7`。此前为让下一场
自动开始，服务端又在动作播放完成后的 scene poll 人为追加：

```text
4/8 { result=1, autorevive=1, info=<12 bytes> }
```

用户随后确认正常胜利不再显示奖励结算，而是出现空白信息弹窗。对应真实服务端记录为：

```text
mock_battle_settle ... reward_claimed=1 exp_gain=10 ... fdata_len=0
scene_hangup_terminal_close ... response=4/8(result=1,autorevive=1)
```

`fdata_len=0` 在没有物品掉落时是正确状态；经验和金钱由 `4/7` 的数值字段结算。首个
错误状态发生在 `4/7` 已成功解析之后：服务端把复活消息 `4/8` 伪作胜利关闭消息。

## 客户端契约

`mmBattleMstarWqvga.cbm` 的 `HandleBattleSettleMsg(0x743C)` 读取 `4/7` 的
`exp`、`gold`、`itemnum/iteminfo`、`autorevive`，并在尾部从 `0x7B08` 读取
`fdata`。结果面板在 `DrawBattleAnimEffect(0x4462)` 使用这个已复制的字符串渲染额外的
文本行；经验、金钱仍来自上述数值字段。普通物品不能安全使用 `iteminfo` 填充，因此仅在
有掉落时用 `fdata` 显示物品名称和数量。

`HandleServerBattleCmd(0x7BD0)` 的 subtype `4/8` 则读取 `autorevive` 和 `info`：
它属于复活后的状态收尾分支。该对象只有复活石完成流程拥有已验证的 `info` 语义；用固定
零字节 `info` 伪造普通胜利会进入错误的提示/复活分支。

对有奖励的战斗，客户端正确的生命周期是：

```text
最终 4/6 + 4/7 { fdata=掉落摘要（若有） }
  -> 奖励结算面板
  -> 玩家确认面板
  -> 客户端原生 25/5
  -> 服务端标记 sceneHangupRestartPending
  -> 后续 scene poll 发送下一场 4/5
```

`BattleScene_HandleInput(0x6258)` 已证明结算 phase 的确认输入会走
`BattleScene_ExitAndCleanup()`；`25/5` 是服务端安全安排下一场挂机的唯一已确认边界。
`4/4` 是逃跑结果，`4/8` 是复活结果，均不能替代该确认路径。

## 修改

- `4/7` 的经验、金钱仅通过原生数值字段结算；`fdata` 仅在有掉落时写入 GBK 物品名称与
  数量。角色背包仍由既有 `7/7 type=1` 增量路径更新。
- 普通胜利的场景挂机终局不再下发 `4/8`，`4/8` 仅保留给已验证的复活石完成流程。
- 对已有 `4/7` 的场景挂机，服务端等待客户端因奖励面板确认而发出的原生 `25/5`，不再
  伪造关闭或重放结算。八秒奖励冷却导致的无奖励路径仍沿用原有无结算面板关闭契约。
- 最终动作的延后调度标记在奖励面板到达后只释放自身，不再抢占后续 scene poll；下一场
  仍只能由确认面板后设置的 `sceneHangupRestartPending` 启动。
- 普通战斗、队伍战斗、切磋与复活流程没有被改为场景挂机的等待规则。

## 先前试验的更正

`hangup-auto-terminal-v1-20260803T101334002Z-35412` 曾仅以“收到 `25/5` 并进入下一轮”
判定 `4/8` 成功；它没有验证奖励面板的文本和语义。用户观察到的空白弹窗推翻了这一完成
条件，该工件不能再作为胜利关闭协议的正面证据。

对应的只读回归观察仅检查普通胜利到达 `4/7`，并在奖励面板到达时停止；有无 `fdata` 由
本场是否掉落物品决定。它不会代替玩家确认该面板或伪造后续 `25/5`。

## 验证

- 静态链路：`4/7.fdata` parser（`0x7B08`）和 `4/8.autorevive/info` parser
  （`0x7E06..0x7E94`）已分别核对。
- 回归观察：`hangup-auto-terminal-v1` 仅接受普通胜利的 `4/7`，不再把 `4/8` 当作
  普通胜利关闭条件；本次不由代理执行客户端自动化。
- 构建：修改后执行 `make -j2`。
- 仍需用户手动复测：完成一场有奖励的挂机战斗；应显示原生经验、金钱结算，文字区域仅在
  掉落时显示物品名称与数量，而不是空白信息框。确认面板后，日志应出现
  `scene_hangup_round_complete ... evidence=4/7-panel->25/5->poll`，再进入下一场。
