# 后台列表选择：保留滚动位置的局部更新

## 触发与首次偏离

账号、场景、任务和怪物管理页原本都使用普通 `<a>` 导航。选中一个很靠后的
条目时，浏览器销毁整页，再从新文档的顶部重建列表；即使服务端正确选择了目标
详情，列表自身的滚动节点和账号渐进加载的已追加行也已经丢失。

这不是列表数据或 MySQL 游标的问题，首次被破坏的状态是浏览器的列表 DOM 节点，
发生在完整文档导航时。

## 修复契约

- 四类可选择条目统一标记为 `data-admin-select`，左侧滚动容器标记为
  `data-admin-list`，右侧详情容器标记为 `data-admin-detail`。
- 同一管理页内选择条目时，`admin.js` 以已认证、禁缓存的同源 `fetch()` 获取目标
  页面，只将解析出的目标详情内容挂载到现有 `data-admin-detail` 节点。
- 原有列表节点不会替换：其 `scrollTop`、账号页已经加载的续页条目、怪物页本地
  筛选状态及既有事件处理器都会保留。选中样式和浏览器历史 URL 仍会更新；前进、
  后退会以相同方式重新加载详情。
- 写操作、标签页切换、退出登录及请求失败不伪装为成功。失败时回退到原始完整导航，
  仍可得到服务端页面或登录跳转。

## 覆盖范围与验证

覆盖账号管理、游戏内容场景、任务管理和怪物管理的列表选择（包括“新增任务”）。
任务页的“新增任务”和“任务目录”标题位于独立固定头部，只有任务行容器滚动。
商品管理的筛选/分页、更新发布和服务器配置是表单或页级操作，不属于“选择左侧
条目并刷新右侧详情”的交互，保持其原有提交语义。

验证步骤：分别滚动四个列表到非首屏条目，选择该条目后确认 URL 与右侧详情改变、
列表仍停留在原滚动位置；账号页还应先加载至少一页续项再选择其中账号，确认已加载
条目不丢失。再用浏览器后退/前进确认详情与高亮同步。
