# 商城 14/3：酷宝充足却提示不足（2026-07-26）

## 触发与首次偏离

背包已满（日志 `capacity=20/20`）时购买秘宝（例 `item=802`，`cost=20`，
`wcoin=9586`），客户端弹出「酷宝和礼券不足，是否进入充值？」；服务端
`insufficient=0`、`result=2`。

## 根因

`mmShopMstarWqvga.cbm:sub_9DE` 对 `14/3`：

| result | 客户端效果 |
| --- | --- |
| 1 | 成功入库 / 扩容 |
| 2 + type=2 | shop 状态 `+0xf=2` →「酷宝和礼券不足，是否进入充值？」 |
| 3 | 状态 `+0xf=3`、flag=0 →「背包已满，请扩容或整理背包后再购买。」；若当前商品为 806 则改为扩容上限文案 |
| 4 | 状态 `+0xf=3`、flag=1 →「背包余空不足，无法购买礼包。」 |

旧逻辑把**一切失败**（含背包满、扩容失败）都映射成
`vm_net_mock_shop_buy14_failure_result` → `result=2`，与「酷宝不足」撞车。

## 修复

- 仅 `wcoin < cost` 返回 `result=2`
- 背包 `add` 失败、扩容达上限、扩容一次买多个 → `result=3`
- 不扣费、不改背包

- [ ] 酷宝够、背包满：提示背包已满/请扩容，**不是**酷宝不足；日志 `result=3 insufficient=0`
- [ ] 酷宝不够：仍提示酷宝和礼券不足；日志 `result=2 insufficient=1`
- [ ] 背包有空位：购买成功，`result=1`，酷宝减少
