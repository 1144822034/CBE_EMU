# 后台账号列表：搜索与渐进加载

## 目标

账号管理页原先在服务器端遍历全部账号，并把每一行都拼入一次 HTML
响应。账号数量增长后，首次打开后台会造成不必要的响应体、DOM 和浏览器
布局开销，也没有快速定位账号的入口。

## 契约

- 管理页首屏最多输出 40 个账号行。
- 已认证的 `GET /admin-418yz6/accounts?q=<search>&cursor=<index>` 返回下一段
  HTML 账号行和只读分页状态；该端点同样受 `cbe_admin` 会话保护，并带
  `Cache-Control: no-store`。
- `q` 是账号 ID 的大小写不敏感子串匹配。账号 ID 仍作为 HTML 文本和 URL
  参数分别转义，不能由搜索结果注入页面。
- `cursor` 是服务进程中已加载账号目录的下一索引，不是 SQL `OFFSET`：
  每次续页只继续扫描尚未发送的目录区间，避免页码越大查询越慢。
- 前端在账号栏接近底部时请求续页；输入搜索词后以 220ms 防抖重置列表。
  请求结果必须含有 `data-account-page-state`，缺失或游标无效会保留当前
  结果并显示加载失败，而不会把页面替换成不完整数据。

## 验证边界

账号搜索和滚动续页通过浏览器同源 `fetch()` 请求该片段端点。初版页面的响应
头设为 `default-src 'none'`，却漏掉了 `connect-src`；依照 CSP 回退规则，
这会拦截该 `fetch()`，即使 `script-src 'self'` 已允许加载 `admin.js`，前端也
只能显示“账号列表加载失败”。

响应头现明确声明 `connect-src 'self'`，仅允许后台页面连接回同一来源；它不放宽
外部网络连接、脚本来源或表单提交目标。

构建后应在后台页验证：首屏 40 行、账号搜索、滚动续页和结果账号的详情跳转。
