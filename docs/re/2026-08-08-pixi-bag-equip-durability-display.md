# 背包装备耐久与 CBE/穿戴侧一致

日期：2026-08-08

## 触发与现象

穿戴栏已显示服务端当前耐久后，背包内同件装备详情仍固定满耐久；脱装后打开背包也看不到脱装前的损耗。

## 根因

契约拆分（`2026-07-29-enhance-attr-gray-and-unequip.md`）：

| 路径 | count 语义 |
| --- | --- |
| `30/21` / 背包 `7/7` | 装备实例 **1**（堆叠/入包循环；CBE 对装备 id 写入 `item+0x110`） |
| 穿戴 `7/7 type=2` | **当前耐久** → `item+0x110` |

因此登录/新入包背包装备的当前耐久与 wire 一致为 **1**（显示 `1/max`），不是 `equip.dsh` 满值。

CBE：脱装/替换是搬动物件，**保留** `item+0x110`；再开背包的 `30/21` 只写堆叠（`+0xf2`），不重置耐久。

Pixi 首次偏离：把背包装备耐久写死满值，且 `openBag` 重建时丢掉已有/脱装带来的当前值。

## 修改

- `enrichBagRow`：背包装备 `durability = wire count`（登录/授予为 1），`count = 1`。
- `GameSession`：按 seq 保留背包耐久；`7/8 type=4` / `7/9` 把穿戴当前耐久 stash 到入包 seq；无先验时回落为 1。
- `openBag`：解析前暂存旧行供 merge。

## 验证

1. 新获 / 登录背包装备：`[耐久]` = `1/max`。
2. 战后穿戴耐久下降 → 卸下 → 背包详情为卸下时的当前值/上限。
3. 再打开背包不因 `30/21` 被刷成满值；无 stash 的新行仍为 `1/max`。
4. 替换占用槽：卸下到背包的那件带原穿戴耐久。
