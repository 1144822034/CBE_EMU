# 异常断线后的副本重连恢复

## 现象与首个偏离

角色通过 NPC 进入临时副本后，`vm_mock_service_client_session` 保存副本场景、坐标、返回锚点和计时起点。异常关闭客户端后，心跳超时（或新客户端登录导致账号接管）会进入 `vm_mock_service_session_mark_offline()`；原实现无条件清空这些字段。随后选角的 `1/1/6` ActorInfo 只能读取角色表中的世界场景，后续 `1/27/4` 的 `min` 也只能读取已经清空的会话，因此为零。

这不是客户端倒计时绘制或宿主网络投递问题：客户端仍走正常的标题选角、场景资源加载以及 `27/4` 请求链，最早偏离是服务端在离线边界丢失了临时副本的权威状态。

恢复场景后的第一次人工复测确认了第二个独立缺口：标题登录后的副本走 `WT12/1` 场景运行时初始化，不会重放 NPC 进入时的 `30/1 -> WT6/1`。原 `WT12/1` 回复只重建场景/NPC，缺少正常副本完成中初始化倒计时 HUD 的 `27/12 -> 27/11 -> 27/4(min)` 组合，因此场景正确但右上角没有计时器。

随后复测的首次偏离不是 `min` 编码：`mock_fb_target_result4` 已以四字节大端 `u32` 写入 `min`。问题是该标题登录子集原本已有八个回复对象；直接追加三对象 FB 尾部得到 11 个对象，而 `ParseDMenuResponse` 只有 10 个对象槽。审计记录为 `object-limit`，最后的 `27/4` 虽然在线上包内，但客户端无法到达它，因而同时出现解包错误和没有计时器。

## 修复契约

服务端为异常断线增加了进程内、一次性的重连记录：

- `explicit-disconnect`、`heartbeat-timeout`、`account-login-takeover` 和同账号的 `title-login-rebind` 会保存。player-3 的“强行关闭”实际到达服务端时也是 `explicit-disconnect`，并非等待心跳超时；不保存它会在真正复现中提前丢失副本状态。封禁、管理重置、账号改绑等边界仍会丢弃记录。
- 键为 `(accountId, roleId)`。不同角色即使属于同一账号也不能消费该记录。
- 记录保存副本场景/坐标、原世界返回锚点、计时总分钟数和**原始** `timerStartedMs`。重连不会把“剩余分钟数”重新作为起点，因此服务器运行期间的实际经过时间仍会从剩余时间中扣除。
- 相同账号和角色在现有 `1/1/6` 选角成功后恢复该会话状态；没有新包、没有宿主侧回调重排，也不向客户端伪造 `30/1`。
- ActorInfo 继续由既有 `parse_actorinfo_response` 路径消费。场景键和出生坐标在临时副本激活时从恢复后的会话读取，CBE 因而按通常的标题登录资源流程加载副本。
- 恢复后的首次、客户端请求的 `WT12/1` 会保留技能、背包、角色和任务回复；不在这一次批量回复中发送非状态性的 `25/5` 信息横幅，从而为 `27/12 -> 27/11 -> 27/4(min)` 保留三个对象槽。总数严格为 10；该顺序与正常 NPC 副本进入的已验证 FB 对象顺序一致，并且不重发 `30/1`。客户端后续普通轮询仍可取得 `25/5` 横幅。
- 后续客户端本来就会发送 `1/27/4`；既有 FB 构造器以恢复后会话中的原始计时起点编码 `min`（u32）。

计时在选角前已经到期时，重连记录会被丢弃，角色照常进入持久化的世界锚点；不会恢复一个过期副本。副本正常离开或到期退出时，同样会清理任何同键记录。

该记录故意不写入角色表，也不跨**服务端进程重启**保存。该范围解决“客户端异常退出、服务端仍在运行”的重连；服务重启后的副本恢复需要另行确定可持久化时钟和数据库迁移契约。

## 证据与回归

关联的既有客户端链路：标题选角 `1/1/6` 的 ActorInfo 被 `parse_actorinfo_response` 读取并交给场景资源加载；梦境目标倒计时由 `JianghuOL.CBE:0x01033CF2` 读取 `1/27/4` 的四字节 `min` 字段。

新增隔离回归：

```powershell
make transient-instance-reconnect-regression
.\obj\server\transient-instance-reconnect-regression.exe
```

它不启动监听器、数据库或客户端，验证：

1. 同账号同角色的快照恢复副本场景、坐标和原始计时起点；
2. ActorInfo 的场景/坐标来源切换到恢复后的副本；
3. 重登录场景回调包含严格的 `27/12 -> 27/11 -> 27/4` 顺序、总对象数不超过 10，且 `min` 仍为原计时起点扣除一分钟后的值；
4. 其他角色不能消费记录，且选角前已到期的记录不能恢复。

人工复测时可查看服务端日志：

```text
transient_instance_reconnect_snapshot ... reason=heartbeat-timeout
transient_instance_reconnect_resume ... remaining_minutes=...
mock_backpack_grid_reseed ... instance_resume=1
mock_instance_reconnect_fb_completion ... response=WT12/1
mock_fb_target_result4 min_minutes=...
```

建议流程：配置一个非零副本计时，进入副本后异常关闭客户端并等待服务端检测离线（或以同账号新客户端登录触发接管），再选回同一角色。应仍加载副本场景，右上角显示比进入时更小的剩余时间；不同角色或已经到期的副本应回到持久化世界位置。
