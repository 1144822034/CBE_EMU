# 登录背包强化等级显示为 0

## 触发与现象

角色刚登录后打开背包，此前已强化（`enhance_level≥1`）的装备仍显示无
`(+N)`，或看起来像强化 0。MySQL / 内存 `enhanceLevel` 往往已是正确值。

## 业务链路

1. 登录播种 `1/30/21`：`itemId + seq + count + common-extra`。
2. common-extra：`tagged-i16` ×2 + `u8 attr_count` + 可选词条。
3. 客户端把第一份 i16 低字节写入物品 `+0xe`，第二份低字节写入 `+0xf`
   （与 `29/1` 成功路径 `0x010287C0`：curlevel→`+0xe`、maxlevel→`+0xf` 一致）。
4. 背包名称绘制用 `item+0xe` 拼 `(+N)`。

## 首次偏离

旧编码对装备写 `(first=0, second=enhanceLevel)`：

- `+0xe` = 0 → 名称无强化等级；
- `+0xf` = enhance → 错把当前等级当成上限字段。

仓库取回 bug（`(1,0)`→`(+1)`）已证明**第一**份 i16 才是强化显示来源；
把真实等级放在第二份无法修复登录显示。

## 根因

装备 common-extra 字段语义弄反：第一份应为**当前强化等级**，第二份应为
**最大强化等级**（低字节；L≥4 时高字节仍为词条槽上限 4）。

## 修改

`vm_net_mock_seq_put_item_common_extra`：

| 类型 | first i16 | second i16 |
|------|-----------|------------|
| 装备 | `enhanceLevel` | `maxlevel`（16），L≥4 时 `maxlevel \| (4<<8)` |
| 非装备 | `stackRuntime` | `0` |

覆盖登录 `30/21`、穿戴 `7/7 type=2`、强化后 sync、仓库取回等所有经该入口的路径。

## 验证

- [ ] 强化 ≥1 的装备存档后重登，开背包显示 `(+N)`。
- [ ] 未强化装备仍无 `(+1)`（不得再出现仓库假 +1）。
- [ ] 穿戴登录 `7/7 type=2` 身上装备强化显示正确。
- [ ] `make -j2` 通过。
