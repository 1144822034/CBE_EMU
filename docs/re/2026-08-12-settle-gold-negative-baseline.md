# 结算面板经验/金钱：非直接掉落字段 + 胜利负数金钱

## 机制（不是「直接显示怪物掉落」）

| 层级 | 含义 |
|------|------|
| 怪物表 `reward_exp` / `reward_money` | 本场胜利奖励（可×敌人数等） |
| 角色 `exp` / `money` | 入账后的**绝对总量** |
| `4/7.exp` / `4/7.gold` | 同上，战后绝对总量（CBE `HandleBattleSettleMsg`） |
| 面板「获得经验/金钱」 | 客户端 `总量 − 战前基线` |

物品掉落在 `fdata` / 背包同步里另走，不是金钱行本身。

## 胜利却显示金钱为负

### 根因

1. Pixi 用 `session.gold` 作战前基线；若高于真实战前铜币（消费未同步等），则 `goldTotal − session.gold < 0`。
2. 旧逻辑把「任意负增量」当成惩罚（切磋失败），胜利也会原样显示负数。
3. 服务端虽在 `4/7` 前塞 `1/1/14` 基线，但 **live actorinfo 不下发 money**，CBE 靠内存金钱，Pixi 吃不到基线。

### 修改

1. 结算基线 `1/1/14` 改发 **fresh actorinfo**（含 money/exp）。
2. Pixi 识别 fresh 布局后写入 `session.exp/gold`，再算 `4/7` 增量。
3. 仅 `挑战失败` / `比武失败` / fdata 含 `金钱-`·`经验-` 时保留负增量；普通胜利夹到 ≥0，并以线总量回写基线。

## 验证

1. 登录后多场胜利：金钱行应为 `+N`（与 `mock_battle_settle … gold_gain=` 同量级），不为负。
2. 先花铜币再开战：增量仍接近本场 `gold_gain`，不是「总量 − 过期基线」。
3. 切磋/比武失败：仍可显示负经验/金钱（若 fdata 带惩罚文案）。
4. `make -j2`
