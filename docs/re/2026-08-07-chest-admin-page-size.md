# 宝箱管理页面超过大小限制

## 触发与首次偏离

宝箱奖池允许每个宝箱配置最多 120 行。页面原本把青铜、白银、黄金三个宝箱的
完整表单同时生成，并用 HTML `hidden` 属性隐藏非选中项。每行还包含物品选择控件，
页面末尾还会嵌入一次 1700+ 项的共享物品目录。

在奖励行增加“世界播报”控件后，原本固定为 512 KiB 的后台响应工作区被耗尽。
`vm_mock_admin_text` 正确标记 `truncated`，随后页面渲染器将其替换为：

```text
宝箱管理页面超过大小限制。
```

这不是宝箱数据库、配置内容或 HTTP 解包错误；首个违反点是服务端错误地序列化了两个
不可操作的隐藏编辑器。

## 修复

侧栏每个宝箱改为正常链接 `?tab=chests&chest=<id>`。服务端只生成当前选择宝箱的一份
120 行表单，未选择的宝箱不再出现在 HTML 响应中。共享物品选择器保持一份，客户端的
“添加奖励/移除奖励/概率预览”逻辑不变。

这同时符合左右布局“左边宝箱列表、右边对应配置”的数据边界。后台响应工作区已调整为
2 MiB，它是由既有、有限的宝箱行数和目录项数决定的分配容量，不再将 512 KiB 当作页面
功能限制。

## 回归

`scripts/chest-admin-page-size-regression.c` 在三个宝箱均填满 120 项的最坏数据量下，
渲染黄金宝箱页面并断言：

1. 没有出现大小限制替代页面；
2. 响应仅含黄金宝箱编辑器；
3. 包含恰好 120 条奖励行；
4. 输出严格小于当前响应分配容量；
5. 宝箱专用物品窗口仍带有装备品质、需求等级的联合筛选字段，并保留目录中的
   `data-quality`、`data-level` 元数据。

该测试只构造进程内配置数据，不连接 MySQL、不启动 HTTP 服务，也不修改账号或宝箱。
