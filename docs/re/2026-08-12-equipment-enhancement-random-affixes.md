# 强化阶段词条：实例随机与持久化

## 客户端协议事实

- `ParseEquipAttributes`（`JianghuOL.CBE:0x010185C2`）按“当前强化、最大强化、属性数、重复的阶段/类型/mode/i16 数值”读取装备扩展属性。
- `mmGameMstarWqvga.cbm` 的装备详情使用阶段阈值显示 `+4/+8/+12/+16` 条目；`mode=0` 是已确认的固定数值分支。
- 阶段条目是已经生成的装备属性，而不是客户端要求服务端预告的目录模板。因此未到达阶段不能下发灰色预览行。

## 服务端规则

1. 装备到达 `+4/+8/+12/+16` 时，为该阶段生成一条词条。
2. 词条从该装备部位的四个候选属性中等概率抽取；同一件装备的四个阶段不重复。
3. 数值以装备等级对应的阶段基准值为中心，在约 ±10% 的小范围内随机（小整数属性至少有 ±1 的离散变化）。
4. 结果保存在具体装备实例中：背包、穿戴、交易报价与交易落库均携带相同的四阶段状态。
5. 对历史已强化实例，首次角色加载时补抽一次并在同一 MySQL 角色事务中写回；之后绝不因打开背包、刷新装备页或重新登录重掷。

## MySQL 表达

- `account_role_equipment` 和 `account_role_backpack` 各增加：
  - `enhance_affix_types`：四个 `u8` 词条类型打包为一个无符号整数。
  - `enhance_affix_values`：四个 `u16` 词条数值打包为一个无符号 64 位整数。
- 零值代表尚未达到阶段或待首次历史迁移。
- 迁移脚本：`server/mysql/migrate_random_equipment_affixes.sql`；服务启动也会逐列自动补齐。
