# 普通死亡复活到最近安全区域

## 需求与第一处偏离

普通死亡此前按“最近含 n_telestone 的场景”复活。这个规则会优先选择当前世界中的传送石
场景；例如太乙峰本身含传送石，旧路径距离为 0，因此死亡后仍会留在终南山区域。

最初改动只在 `wMap.dsh` 中寻找最近的城镇中心。这会遗漏同一世界内部已经由
`sMap.dsh` 标注为安全的子场景：例如蟠龙寨的第 154 行“玄武北堂”距第 153 行
“止水堂”只有两跳，但旧代码把 `wMap` 的方向光标 ID 误当一跳到蓬莱的连接，于是错误复活到蓬莱。

现行规则先返回地图局部拓扑中最近的安全子场景；主城来源则回到本城中心。仅在非主城的
局部连通图没有安全点时，才跨世界地图的实际连线到最近主城中心。复活请求与客户端响应契约不变：客户端的
WT 1/7/14(result=2) 仍由服务端返回既有的 1/20/1 + 1/30/1 场景重生数据，服务端只
更换 30/1 中的权威场景和安全坐标。

## 原始资源定义

- sMap.dsh 的第 0、1、3、4、11、12 列分别提供子场景 ID、精确场景键、世界地图 UI
  位置、所属世界地图和怪物等级；第 12 列为“无”的子场景是本地安全点。
- wMap.dsh 的第 0、4、5、8 至 12、16 列提供世界地图 ID、节点画布坐标、四方向
  光标导航 ID、下级地图基准行和怪物等级。四方向 ID 只用于世界地图上的方向选择，不能
  视为可通行连接。
- wMapLine.dsh 的第 1 至 4 列给出每段实际世界地图连线的画布端点。以 wMap 节点
  `(X,Y)` 的 16 x 16 图标矩形切分这些线段；同一节点两侧的线段必须经该节点才能继续，
  因而可还原不带世界 ID 的真实旅行图。
- wMap 怪物等级字段为“无”标记五个安全世界：蓬莱、临安府、雁门关、蜀山和大理。
  它不等同于主城资格：以 `wMap` 的“下级地图”基准行在 `sMap.dsh` 中的非零 `cNN`
  场景键识别四个主城（临安府、雁门关、蜀山、大理），排除 `c00` 蓬莱新手岛。
- 城镇内部不把 sMap 的 UI 位置当作角色坐标；它仅用于从该城镇全部子场景中选最接近
  几何中心的一个。之后仍从选中 SCE 解出真实出生点，并执行传送触发框和 MAP 碰撞
  安全修正。

太乙峰的 sMap 行为 90，所属世界地图为终南山（wMap 11）。终南山与临安府（wMap 4）
由实际世界地图连线直接相连，距离为 1。临安府十个子场景的 UI 几何中心对应行 56：
c04临安府_10.sce，别名“临安-宣阳广场”。因此太乙峰普通死亡稳定复活到该城镇中心。

## 实现

vm_net_mock_resolve_nearest_safe_respawn() 先以当前精确 SCE 查 sMap 源行。非主城来源会在
局部 sMap 四方向图上 BFS 到第一个“无怪物等级”的安全子场景；主城来源则转入本城中心选择。
没有本地目标时，加载 wMap 节点坐标和 wMapLine 线段，将穿过节点的线段在 16 x 16
节点矩形处分割，再在得到的真实旅行图上 BFS。选择连线跳数最少的可达主城；跳数相同才
按世界地图 ID 稳定取值。

选定城镇后，函数在该世界的 sMap 子场景中按 UI 几何中心选择中心行，并使用：

1. SCE 边缘入口或场景尺寸推导实际场景坐标；
2. 既有传送触发框安全间距；
3. MAP 高半字节碰撞和 3 x 3 占用邻域校验。

本地安全路径只依赖 sMap 与 SCE；跨世界后备路径另需 wMap 和 wMapLine。所需资源缺失都会明确返回
unresolved；角色保留当前有效场景的安全落点，不会偷偷回退到蓬莱或伪造坐标。

设置页“脱离”不使用该规则，仍在当前场景寻找防卡位落点。

## 运行时取证（2026-08-23）

`bin/server_out.txt` 中的普通死亡链已确认请求和客户端响应契约正确，但暴露了第一个
错误的目标选择：`23蟠龙寨_03.sce`（sMap 154）被城镇后备直接解析为
`00蓬莱仙岛_02.sce`（sMap 38，world 1，hops 1）。同一份 `sMap.dsh` 表中，154 经
154 → 155 → 153 两跳即可到达怪物等级为“无”的 `23蟠龙寨_02.sce`（止水堂）。

因此错误发生在服务端构造 `30/1` 前的复活目标解析，而不是 `WT 1/7/14(result=2)`
detector、`20/1 + 30/1` 响应结构或客户端场景 parser。修复后的 trace source 为
`mock_death_respawn_nearest_safe`，并显式记录 `route=smap-nearest-safe-scene`、源/目标
sMap 行和落点；跨世界主城后备记录 `route=wmapline-nearest-city-link-distance` 与 `hops`。
幽冥鬼府的后续取证见
[`2026-08-26-ghost-palace-nearest-city-respawn.md`](2026-08-26-ghost-palace-nearest-city-respawn.md)。
