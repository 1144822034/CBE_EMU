# 普通死亡复活到最近城镇中心

## 需求与第一处偏离

普通死亡此前按“最近含 n_telestone 的场景”复活。这个规则会优先选择当前世界中的传送石
场景；例如太乙峰本身含传送石，旧路径距离为 0，因此死亡后仍会留在终南山区域。

新的规则要求返回地图拓扑中最近的城镇中心。复活请求与客户端响应契约不变：客户端的
WT 1/7/14(result=2) 仍由服务端返回既有的 1/20/1 + 1/30/1 场景重生数据，服务端只
更换 30/1 中的权威场景和安全坐标。

## 原始资源定义

- sMap.dsh 的第 0、1、3、4、11 列分别提供子场景 ID、精确场景键、世界地图 UI
  位置、所属世界地图。
- wMap.dsh 的第 0、8 至 11、16 列提供世界地图 ID、四方向连接和怪物等级。
- wMap 怪物等级字段为“无”的五个原始安全城镇是：蓬莱、临安府、雁门关、蜀山和
  大理。该字段来自资源，不依赖场景名称关键字。
- 城镇内部不把 sMap 的 UI 位置当作角色坐标；它仅用于从该城镇全部子场景中选最接近
  几何中心的一个。之后仍从选中 SCE 解出真实出生点，并执行传送触发框和 MAP 碰撞
  安全修正。

太乙峰的 sMap 行为 90，所属世界地图为终南山（wMap 11）。终南山的右侧邻接临安府
（wMap 4），距离为 1。临安府十个子场景的 UI 几何中心对应行 56：
c04临安府_10.sce，别名“临安-宣阳广场”。因此太乙峰普通死亡稳定复活到该城镇中心。

## 实现

vm_net_mock_resolve_nearest_town_center_respawn() 以当前精确 SCE 查 sMap 源行，再在
wMap 四方向图上 BFS 计算到每个安全城镇的最短距离。距离相同按世界地图 ID 稳定取值。

选定城镇后，函数在该世界的 sMap 子场景中按 UI 几何中心选择中心行，并使用：

1. SCE 边缘入口或场景尺寸推导实际场景坐标；
2. 既有传送触发框安全间距；
3. MAP 高半字节碰撞和 3 x 3 占用邻域校验。

任何 sMap、wMap 或 SCE 资源缺失都会明确返回 unresolved；角色保留当前有效场景的安全
落点，不会偷偷回退到蓬莱或伪造坐标。

设置页“脱离”不使用该规则，仍在当前场景寻找防卡位落点。

## 验证

已执行 make -j2，服务端完整编译、链接通过。

更新 scripts/zhongnan-taiyi-recovery-landing-regression.c；它不启动监听器、不连接
MySQL、不写入角色数据。测试成功（退出码 0），验证：

- 太乙峰入口的旧防重触发偏移仍会复现并被 MAP 碰撞恢复器移出柱子；
- 太乙峰普通死亡的源行是 90，最短城镇距离是 1，目标行是 56，精确目标为
  c04临安府_10.sce；
- 临安府内的源行 47 到同一城镇中心的距离为 0，仍稳定选择行 56；
- 该复活落点通过实际 MAP 的 3 x 3 碰撞安全检查；
- 设置页脱离仍留在太乙峰并使用既有的 (408,280) 防卡位落点。

客户端仍建议用测试账号从太乙峰及另一个跨世界地图各死亡一次，验收复活场景、加载流程
和城镇内移动体验。
