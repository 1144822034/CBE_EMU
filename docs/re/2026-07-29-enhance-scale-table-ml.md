# 客户端强化缩放表（flat/pct）与 M(L) 对齐

## 客户端怎么用

`JianghuOL.CBE:0x01028BCE`：

```text
*dest += base
table = *(global_obj + 0x580 + 4)
if table == NULL: 不再加 → 主行仍是裸基值
else for i in [0, L):
  *dest += table[i].flat + table[i].pct * base / 100
```

表项 4 字节：`u8 flat`，1 字节填充，`i16 pct`（小端）。

详情物攻/护甲与穿戴汇总都会走到这套逻辑（详情经 `global+0x980+0xc`
函数指针；穿戴直接 `bl 0x01028BCE`）。

## 与服务端 M(L) 对齐

```text
M(L) = 1 + (10*L + 35*floor(L/4)) / 100
```

等价于对 `i = 0 .. L-1`（对应升到强化等级 `i+1`）：

| 升到等级 | pct | flat |
| --- | --- | --- |
| 非 4 倍数 | 10 | 0 |
| +4/+8/+12/+16 | 45 | 0 |

校验：`L=16` → `12×10 + 4×45 = 300` → 合计 `base×4`。

## 16 级表字节（小端）

每级 4 字节，共 64 字节：

```text
# i=0..15；pct=45 iff (i+1)%4==0 else 10
00 00 0A 00   # +1  pct=10
00 00 0A 00   # +2
00 00 0A 00   # +3
00 00 2D 00   # +4  pct=45
00 00 0A 00   # +5
00 00 0A 00   # +6
00 00 0A 00   # +7
00 00 2D 00   # +8
00 00 0A 00   # +9
00 00 0A 00   # +10
00 00 0A 00   # +11
00 00 2D 00   # +12
00 00 0A 00   # +13
00 00 0A 00   # +14
00 00 0A 00   # +15
00 00 2D 00   # +16
```

## 为何现在还装不进去

1. 本构建 CBE + 全部 mm*.cbm：**没有任何**把指针写入 `*(business+0x584)` 的代码，
   也无嵌入的 16 级 `(flat,pct)` 常量表（详见
   `2026-07-29-enhance-scale-table-no-writer.md`）。本地主行累加会一直
   `table==NULL`。
2. **不能**靠往 `JHOnlineData` 丢新 `.dsh` 解决：客户端只打开硬编码文件名，
   且表格式不是 DataSheet（详见 `2026-07-29-enhance-table-dsh-not-viable.md`）。
3. 项目规范禁止用 `Global_R9` / 客户端内存写入强行塞表。

因此：**算法表已定好，但本客户端没有合法装载点可接。**

穿戴战斗属性与商店查看文案仍由服务端 `M(L)` 保证正确；缺的只是原生详情
主行 `%d` 的本地加算（本构建下属预期局限，不是服务端漏发字段）。
