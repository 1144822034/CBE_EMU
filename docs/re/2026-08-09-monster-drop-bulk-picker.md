# 怪物掉落批量管理与装备目录元数据（2026-08-09）

## 原有行为与问题边界

怪物管理把最多 64 条 `server_monster_drops` 逐项渲染，每项只能打开一次单选
物品窗口。掉落配置本身没有错：每行都代表一次独立概率投掷，保存时由
`vm_net_mock_monster_admin_save()` 在一个 MySQL 事务中删除旧列表并写入完整的新列表。

不足在后台编辑层：管理员无法按分类多选再批量填充空掉落槽位；物品选择器与
NPC 专属库存相比缺少装备的资源品质和需求等级信息。不能把掉落改成 NPC 库存的
“商品集合 + 同一单价”模型，否则会丢失每条掉落独立概率的服务器语义。

## 正确契约

- 物品目录仍来自 `item.dsh/equip.dsh`，不是角色背包实例。
- 装备类别与品质取自商品目录中的 `equip.dsh` 行；需求等级取自装备目录同一物品 ID
  的 `levelRequired`。强化等级属于角色的装备实例，不能显示为目录品质或需求等级。
- 多选窗口只暂存物品 ID；点击“加入掉落”时，按选择顺序填入空槽位，并为每项写入管理员
  指定的默认概率（1–100）。随后仍能逐项修改概率。
- 提交仍仅走 `save-monster`，由既有最大 64 项、物品存在、概率范围和禁止重复 ID 校验，
  再在一个事务中保存完整掉落列表。批量选择不直接绕过或分裂该持久化边界。

## 修改

1. `src/web_admin_server.c` 抽取了目录物品的统一展示：所有共享单选窗口均为装备显示
   “品质 N · 需求等级 N”；NPC 专属库存的批量窗口与现有库存行也显示同样元数据。
2. 怪物管理新增独立的批量掉落选择窗口，复用共享物品目录而不复制完整目录 HTML。
   支持分类、装备品质、名称/ID 搜索、当前筛选全选与移除暂存选择。
3. 怪物编辑器新增“批量添加掉落”和“管理已有掉落”工具区：已存在掉落可按分类/品质
   筛选、全选并批量移除；加入时严格受剩余 64 个槽位约束。单项物品和概率编辑仍保留。
4. 共享物品单选器在变更隐藏值时触发普通 `change` 事件，使怪物行能即时同步其类别、品质、
   等级筛选元数据；这不会改变任何服务端请求或业务状态。
