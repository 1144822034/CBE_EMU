# 装备回收 NPC：一键回收品质 0 装备

日期：2026-08-29
状态：已实现；待客户端手工体验验收

## 需求与最早改动点

装备回收 NPC 原先只提供按背包序号逐件回收的选项；没有“按品质批量筛选”的服务端动作。
客户端已有普通 NPC 对话和二次确认的完整解析链，因此不新增客户端回调、宿主行为或输入自动化。
最早改动点是服务端现有 `WT 1/26/1 {type=2,id=value}` 装备回收菜单：在其首页增加一个受
NPC 会话上下文约束的私有动作值。

## 协议与数据契约

- 首次点击值为 `0xfa000001`，仍由 `task_hall_activate_selected_entry`
  （`江湖OL.CBE:0x010492B0`）发送为普通 `26/1` action=1 请求；
  `ParseNPCDialogData`（`0x010380E8`）继续按既有对话格式处理响应。
- 新值仅在 `VM_NET_MOCK_NPC_KIND_EQUIPMENT_BUYER` 已登记的会话上下文中可达，并且必须取得
  既有的 `0xf0` 确认上下文。确认或取消都会消费上下文；直接伪造确认、跨 NPC/场景/角色重放均被拒绝。
- 候选必须是背包中的独立装备实例，且其 `equip.dsh` 权威目录记录 `quality == 0`、该实例的
  `enhanceLevel == 0`。不通过物品 ID 区间猜测品质。已装备物品、强化过的品质 0 装备，以及品质
  1 及以上装备都不会被选中；菜单与确认页明确标示“未强化品质 0 装备”。

## 结算与失败边界

首次点击只保存候选件数、总报价、角色/NPC/场景/服务掩码和列表页，不修改角色。确认时重新计算
未强化品质 0 候选与总价；任一数值变化即拒绝，并保持角色状态不变。通过复核后，先在内存投影中收集
所有背包序号，再删除每个实例并增加铜钱，最后仅调用一次既有角色保存事务。保存失败会完整恢复内存角色。

定价继续复用既有规则：每件获得 `ceil(基础价 × 10 / 100)`；不读取 NPC 专属售卖价，也不引入
强化附加价。

## 客户端回包与解包错误（2026-08-29 修正）

player-1 在确认“一键回收品质 0 装备”后显示“解包错误”。服务端的结算和持久化已在这之前
完成，因此首次偏离不是候选筛选、报价或事务，而是确认回复的对象流。8 月 27 日的实现把下列对象
放进同一个 `action=1` 的响应：

```text
26/1（成功对话及返回装备列表动作）
-> 7/11 {seq, count=0}（每件已回收装备）
-> 10/26（提交后的铜钱）
```

其中每个对象自身可按各自 parser 解码，但它们不属于同一个回调契约：

- `task_hall_activate_selected_entry`（`0x010492B0`）发出 `26/1 action=1`；
  `DispatchItemEvent`（`0x01039C28`）必须由同一回调中的 `26/1` 完成并清除等待。
- `7/11` 是 `HandleItemOperationResponse`（`0x01033544`）的物品管理器数量通道；
  `10/26` 由场景 HUD 消费。把它们追加到 NPC 对话完成包中会让真实客户端在业务分派前后的
  对象流失配，最终显示通用解包错误。

服务端现在严格只回复一个 `1/26/1` 成功对话对象，其中保留“返回装备列表”动作，避免空选项列表
覆盖成功文案。角色快照仍在同一原子事务中删除所有品质 0 背包装备并增加铜钱；事务成功后只标记
下一次客户端原生背包查询使用该权威快照。返回装备列表是用户的下一次正常 `26/1` 输入，不由宿主
伪造或重排网络回调。

## 宿主边界

本改动没有修改客户端宿主的网络、定时器、回调或 screen 生命周期。宿主仍只将不透明响应字节按
CBE 已登记的 callback/context 投递；筛选、确认、背包变更和后续 UI 均由已有固件 parser 与
服务端协议完成。

## 验证

```text
make -j2
```

该隔离回归不启动监听器、不连接 MySQL、不运行客户端，也不读写账号或角色数据。它构造一件已装备
品质 0 装备、一件背包品质 0 装备（强化 +5）、一件未强化的背包品质 0 装备和一件背包品质 1 装备，
断言：白名单接受该对话操作、首次点击不修改角色、确认上下文只能消费一次、报价改变会在变更前被拒绝，
以及成功结算只删除未强化的品质 0 背包装备、保留 +5 装备并增加正确铜钱；还断言成功包严格只含带
返回动作的一个 `26/1`，没有 `7/11`、`10/26` 或其他后续对象。
