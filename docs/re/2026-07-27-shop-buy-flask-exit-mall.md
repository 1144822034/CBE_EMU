# 商城买壶进不了背包（修订 5：DSH consumeMode 导致叠行）

## 用户观察

- 逍遥壶/神仙壶商城购买后背包仍只有原来的壶。
- **修炼丹、经验卡（同属类别 10）可以买。**
- 曾怀疑：背包里已经有壶就不能再买。

## 结论

**不是唯一限制。** 登录契约允许同一角色多把 802/803（不同 `seq`）。

经验卡/修炼丹：`堆叠数` 大，`14/3` 本地合并数量即可。  
壶：必须新开 `seq` 行，并走 `30/21(count=1) + 7/11(储量)`。

## 根因（可检验）

`bin/JHOnlineData/item.dsh` 中 802/803：

| 字段 | 值 |
|---|---|
| category | 10 |
| stack | 1 |
| **consumeMode** | **0**（不是 2） |
| hp/mp | 50000 / 0 或 0 / 50000 |

旧逻辑：`item_effect_is_reservoir` 要求 `consumeMode==2`，因此
`reservoir_capacity(802/803)==0`。`add_backpack` 落到按 `itemId` **堆叠合并**：
已有壶的 `count` += 1（例如 50000→50001），`seqOut` 仍是旧序号。  
扣费成功、日志 `result=1`，但背包永远只有一行 →「只有原来的壶」。

此前误判的补包问题（`7/7 count=1` 当储量、`14/3` 跨 mmShop→mmGame）仍真实，
但是**第二次偏离更早**：服务端根本没有新开行。

## 修复

1. `item_effect_is_reservoir`：对硬编码 802/803（且 hp/mp≠0）视为储量壶，
   不依赖 DSH `consumeMode==2`。
2. `add_backpack`：若仍算不出容量，对 802/803 默认 `50000`，禁止叠行。
3. 保留 mmGame 就绪后的 `30/21+7/11` 投递/跳过（跨场景重建仍需要）。

日志：`resp=14/3+pending-30/21+7/11`，随后
`shop_flask_backpack_deliver ... 30/21+7/11` 或
`shop_flask_backpack_skip ... already-seeded`；`seq` 应为**新序号**。

## 验证

1. 已有一把神仙壶再买：退出商城后应看到两把；服务端两行独立 `seq`。
2. 空包买第一把：同样进包。
3. 经验卡/修炼丹无回归。
4. 若曾误买叠过：旧壶 `count` 可能略大于 50000，不影响新行创建。
