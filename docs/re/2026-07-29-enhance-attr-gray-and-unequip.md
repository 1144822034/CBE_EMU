# 强化附加四档灰显 + 背包装备 count 误当耐久导致脱装失败（2026-07-29）

## 1. 强化附加显示

### 预期

强化到 `+4`：属性 1 生效（亮色）；属性 2/3/4 可见但灰色未生效。
`+8/+12/+16` 依次点亮。

### 根因

`JianghuOL.CBE:0x01032118` 遍历 **全部** `attr_count` 槽，用

```text
unlock > current_enhance  → 颜色 5（灰）
否则                      → 颜色 4（亮）
```

旧 wire：`attr_count = L/4`，`+4` 只下发 1 槽，后三档根本不进包，无法灰显。

### 修复

`L>=4` 时 `attr_count` 固定为部位模板的 **4** 槽（unlock 仍为 4/8/12/16），
由客户端按当前强化等级着色。

## 2. 耐久有消耗后脱装失败

### 关联根因（同日耐久改动回退）

曾把背包 `7/7` / 购买 / 掉落 / 开箱 follow-up 的装备 `count` 写成
`equip.dsh` 耐久上限。增量入包路径会按 `count` **复制格子**（同
`2026-07-25-trade-equipment-duplicate-bag.md`），客户端背包被撑满后，
`7/8 type=4` 脱装入包失败（表现为「打过折耐久的装备卸不下来」——常与
战后耐久下降同一时段复现）。

契约拆分：

| 路径 | count 语义 |
| --- | --- |
| `30/21` / 背包 `7/7` / 掉落授予 | 装备实例 **1** |
| 穿戴位登录 `7/7 type=2` equipment blob | **当前耐久** → `item+0x110` |

### 附加修复：seq 脱装

穿戴行 `seq = slot+1`。多件已穿且请求只带 seq 时，旧逻辑走「仅一件可消歧」
会 `ambiguous-seq`。现优先按 `seq ∈ [1,8]` 映射槽位。
