# 账号 21642502 登录场景时背包初始化闪退

## 触发与原始证据

账号 `21642502` 选择角色并进入场景时，首个角色组响应完成后客户端崩溃：

```text
queue_data connect=2 event=7 resp=36
PC=0x01031EF4 LR=0x01033041 r0=0
```

角色 `10036` 的持久化背包中有 `808 金元宝`（序号 `20`）共 `51` 个，
同时角色的持久化背包容量为 `100`。用独立 CBMS 会话回放该账号的登录、选角、
`5/10 + 7/7(type=1)` 请求，服务端稳定生成 1408 字节的 WT 复合响应；因此这不是
WT 帧长度、场景资源或网络投递问题。

## 已确认的客户端链路

1. `7/7(type=1)` 的服务端登录组响应附带 `1/30/21` 背包网格；
   `江湖OL.CBE:0x01039952` 逐行解析
   `itemId + seq + count + common-extra`，并调用 `0x0101918E`。
2. 该调用最终进入 `TimerControl_ProcessItem` (`0x01032EB8`)。场景初始化仅以
   `InitTimerControl(64, 74)` 创建 64 个逻辑槽和 74 个物理记录。
3. `item.dsh` 中 808 的堆叠上限为 0，而
   `BuildTimerItemData` (`0x01033044`) 会把 0 修正为 1。因而服务端把
   `808,count=51` 写进一个普通 `30/21` 行时，客户端会递归申请 51 个物理记录，
   而不是一个 51 堆的记录。
4. 本账号在该行前后还有普通背包行；申请总数超过 74 后，
   `TimerControl_ProcessItem` 找不到空记录，仍把空指针传给
   `UpdateActorHpMpDisplay` (`0x01031EEA`)。后者的第一条读取正是
   `0x01031EF4`，与现场 `r0=0`、`LR=0x01033041` 一致。

## 首次违反的契约与根因

服务端把 808 当作普通背包物品写入 `30/21` 和 `17/1`。但
`mmShopMstarWqvga.cbm:sub_9DE` 在商店成功路径明确跳过 808 以及 817--819 的
通用背包管理器插入；它们不是该客户端通用背包网格的项目。

此外，服务端把持久化容量 100 直接写入 actorinfo 和 `17/1 maxnum`，超过客户端
初始化出的 64 个逻辑槽。这没有造成当前空指针的第一处偏离，但会让后续背包增长
再次违反同一容量契约。

已排除：`7/11` 不是首个错误点；`0x01033544` 仅更新已经由 `30/21` 建立的序号。
场景/NPC 数据也不在上述崩溃调用链中。

## 修复计划

- 为客户端可表示的普通背包行建立单一判定：808、817--819 不进入 `30/21` 或
  `17/1`；保留持久化数据，不把未知的金元宝语义擅自转换成 W 币或普通物品。
- 将 actorinfo 与 `17/1` 对客户端公布的容量限制为客户端已经初始化的 64。
  持久化存储上限仍维持独立的服务器上限，避免本次修复静默删除旧角色数据。
- 用真实 mock-service 的账号登录回放校验：808 不再出现在首包网格或背包全表，
  802/803 的 `7/11` 储量语义不变，重复组请求不重放初始化对象。

## 尚存边界

本次仅修复客户端已经证明为“非通用网格”的 808/817--819 及其容量公布边界。
若某个旧角色拥有超过 64 个客户端可表示的普通记录，需要单独设计数据迁移或仓储
分页协议；不能在本路径静默截断或删除其物品。

## 修复与验证结果

- `vm_net_mock_backpack_item_is_client_grid_item()` 统一用于登录 `30/21` 与背包
  `17/1` 序列化；808/817--819 不再进入客户端通用道具管理器，但数据库中的原始行
  保持不变。
- actorinfo 的 `backpackCapacity` 和 `17/1 maxnum` 都经过 64 格客户端上限转换；
  `806` 扩容也不再把客户端可用容量推进到该上限之外。
- 已通过真实运行服务上的账号回放：

  ```text
  backpack login reseed regression passed user=21642502 role=10036
  first=1381 duplicate=234 open=564 relogin=1381 forbidden=808 capacity=64
  ```

  首次 `30/21` 为 29 行（持久化原始行 30），6 个 802/803 仍有后续 `7/11` 储量
  种子；重复 group 请求不重放初始化对象，重新选角后会重新播种。
- `php -l tmp/backpack-login-reseed-regression.php` 通过；服务进程短暂重启后
  `make -j2` 通过并重新链接正式 `bin/jh-online-server.exe`。
